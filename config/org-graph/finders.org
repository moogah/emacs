#+title: org-graph Finders
#+author: Jeff Farr
#+property: header-args:emacs-lisp :tangle finders.el
#+auto_tangle: y

Schema-aware per-type finder commands (RE-3).  Each finder selects and
visits a note of a given note type, driving its =vulpea-find= =:filter-fn=
from the *same* =vulpea-schema= predicate that
=openspec/.../schemas.org= uses to validate that type.  This keeps a
single definition of "what a topic note is" instead of the original
hand-rolled filetag predicate, which could drift from the taxonomy.

Two boundaries matter here:

- The per-type finders route through the note-type schemas.  =agent-draft=
  is *not* a note type — it is a cross-cutting filetag the write tool
  stamps on any note — so =org-graph/find-agent-drafts= filters that
  filetag *directly* and never touches the type schemas.
- Finders are thin: selection + visit only.  =vulpea-find= already
  handles candidate sourcing, the =vulpea-note= completion category (so
  marginalia/embark/consult annotations work for free), and visiting.

* Type predicate

A thin helper delegating to the note-type schema's =:predicate= — the
single source of truth for type membership.  It maps the note-type
symbol to its schema name (=topic= ⇄ =org-graph-topic=) and asks
=vulpea-schema-applies-p=.  Returns nil when no schema is registered for
TYPE, mirroring =org-graph/validate-note-type='s guard.

#+begin_src emacs-lisp
(defun org-graph/note-of-type-p (note type)
  "Return non-nil when NOTE is of note-type TYPE.
TYPE is a symbol from `org-graph-note-types'.  Delegates to the
note-type schema's predicate (the single source of truth for \"what a
note of type X is\") via `vulpea-schema-applies-p', rather than
re-implementing filetag matching.  Returns nil when no schema is
registered for TYPE."
  (let ((name (org-graph-schemas--schema-name type)))
    (and (vulpea-schema-get name)
         (vulpea-schema-applies-p note name))))
#+end_src

* Per-type finders

Each finder hands =vulpea-find= a =:filter-fn= built from
=org-graph/note-of-type-p=.  =:require-match t= keeps finders to
selection+visit of existing notes — these navigate the taxonomy, they
do not create.

#+begin_src emacs-lisp
(defun org-graph-finders--type-filter (type)
  "Return a `vulpea-find' :filter-fn admitting notes of note-type TYPE.
The returned predicate takes a `vulpea-note' and delegates to
`org-graph/note-of-type-p'."
  (lambda (note) (org-graph/note-of-type-p note type)))

(defun org-graph/find-topic ()
  "Find and visit a topic note."
  (interactive)
  (vulpea-find :filter-fn (org-graph-finders--type-filter 'topic)
               :require-match t))

(defun org-graph/find-debug ()

* Catch-all finder

=org-graph/find-any= imposes no type filter, so =vulpea-find= falls back
to =vulpea-find-default-filter= and offers every indexed note.

#+begin_src emacs-lisp
(defun org-graph/find-any ()
  "Find and visit any indexed note, regardless of note type."
  (interactive)
  (vulpea-find :require-match t))
#+end_src

* Agent-draft review finder

=agent-draft= is a cross-cutting filetag, not a note type, so this finder
filters the filetag directly rather than routing through a type schema.
It supports reviewing agent-authored drafts.

#+begin_src emacs-lisp
(defun org-graph-finders--agent-draft-p (note)
  "Return non-nil when NOTE carries the cross-cutting agent-draft filetag."
  (and (member "agent-draft" (vulpea-note-tags note)) t))

(defun org-graph/find-agent-drafts ()
  "Find and visit a note stamped with the agent-draft filetag.
agent-draft is NOT a note type; it is a cross-cutting filetag the write
tool stamps on agent-authored drafts.  This finder filters the filetag
directly and deliberately does not route through the note-type schemas."
  (interactive)
  (vulpea-find :filter-fn #'org-graph-finders--agent-draft-p
               :require-match t))
#+end_src
