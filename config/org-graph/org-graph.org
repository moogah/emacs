#+title: Org Graph
#+author: Jeff Farr
#+property: header-args:emacs-lisp :tangle org-graph.el
#+auto_tangle: y

A layered knowledge-graph spike over [[https://github.com/d12frosted/vulpea][vulpea]] (v2.4+), plugged into the
=workspaces= substrate. org-graph indexes the durable concept vault
(=~/org/roam/=) plus each active workspace =:home=, extracts typed
semantic edges from a dedicated edge drawer of description-list items,
exposes schema-backed note-type finders, and registers an agent-facing
query/write surface into gptel and the =workspace-assistant= preset.

This file is the top-level loader for the =org-graph= module. Behavior
is implemented incrementally in submodules under =config/org-graph/=;
they are loaded from the [[#submodules][Submodules]] section as they land.

org-roam runs unchanged alongside this module for the duration of the
spike — see =openspec/specs/org-graph/spec.md= (Coexistence with
org-roam) and =openspec/changes/org-graph-spike/design.md=.

* Defcustoms

** Concept-vault / typed-edge root

=~/org/roam/= is both the durable concept vault and the *only* scope in
which typed-edge extraction runs (RE-4 / D2). Operational notes
(workspace homes, sessions) are indexed for discovery but do not
participate in the typed-edge index.

#+begin_src emacs-lisp
(defcustom org-graph-roam-root "~/org/roam/"
  "Durable concept vault and typed-edge extraction scope.
This directory is always indexed by vulpea, and it is the only root on
which the typed-edge extractor runs.  Workspace homes are indexed for
discovery/navigation but excluded from typed-edge extraction."
  :type 'directory
  :group 'org-graph)
#+end_src

** Relation types

Relation symbols are an *open* vocabulary (design OV-1/LD-2): any
author-coined edge-drawer item tag, normalized, is a valid relation the
moment it appears in a note.  This list gates nothing — it survives
only as a non-authoritative completion seed for authoring surfaces.

#+begin_src emacs-lisp
(defcustom org-graph-relation-types
  '(implements contradicts supersedes relates-to)
  "Completion seed of typed-edge relation symbols.
The relation vocabulary is OPEN: the extractor accepts any relation an
author coins as an edge-drawer item tag (see `org-graph-edge-drawer'),
and this list gates NOTHING.  It only seeds completion on authoring
surfaces; author-coined relations are first-class the moment they
appear in a note."
  :type '(repeat symbol)
  :group 'org-graph)
#+end_src

** Edge drawer

The dedicated drawer holding typed-edge description-list items (design
LD-1).  The drawer *name* is the one and only edge discriminator
(LD-3): content is a typed edge iff it is a description-list item
inside this drawer, matched case-insensitively.  Org constrains drawer
names to word characters, =-= and =_=; the setter warns on a value org
cannot parse as a drawer name.  Settle the name before real notes
accumulate (LD-Q1).

#+begin_src emacs-lisp
(defcustom org-graph-edge-drawer "EDGES"
  "Name of the drawer holding typed-edge description-list items.
Each item `- <type> :: [[id:...]]' inside this drawer declares one
typed edge per `id:' link; the item tag (normalized) is the relation.
The drawer name is matched case-insensitively and is the ONLY edge
discriminator: ordinary PROPERTIES entries and body links are never
edges.

Export: unlike properties, custom drawers export by default.  The
loader therefore adds this drawer to `org-export-with-drawers''
exclusion list -- but only while that variable still has its default
value ((not \"LOGBOOK\")).  If you have customized
`org-export-with-drawers' yourself, the loader leaves it alone and you
own excluding this drawer from export.

Org can only parse drawer names made of word characters, `-' and `_';
setting a value outside that alphabet triggers a warning, and no drawer
will ever match it."
  :type 'string
  :group 'org-graph
  :set (lambda (symbol value)
         (when (and (stringp value)
                    (not (string-match-p "\\`[[:word:]_-]+\\'" value)))
           (display-warning
            'org-graph
            (format "`org-graph-edge-drawer' value %S is not a valid org drawer name (word characters, `-' and `_' only); no drawer will match it"
                    value)
            :warning))
         (set-default symbol value)))
#+end_src

** Edge-drawer export exclusion

Custom drawers export by default (=org-export-with-drawers= excludes
only =LOGBOOK=), but the edge drawer is graph data, not document
content (design LD-6).  While the user has not customized
=org-export-with-drawers=, extend its exclusion list with the
configured edge drawer; a user who *has* customized it owns the
outcome (documented in the defcustom docstring above).

#+begin_src emacs-lisp
(with-eval-after-load 'ox
  (when (equal org-export-with-drawers '(not "LOGBOOK"))
    (setq org-export-with-drawers
          (list 'not "LOGBOOK" org-graph-edge-drawer))))
#+end_src

* Packages
:PROPERTIES:
:CUSTOM_ID: packages
:END:

vulpea is the single index/discovery engine for the spike (RE-2:
org-node is *not* adopted — vulpea already keeps =org-id-locations=
populated via =org-id-add-location=, so a second index would be
redundant double-work).

The recipe is pinned to a specific commit rather than =master=. Pinning
is ordinary hygiene here, not a spike-survival mechanism: vulpea 2.4's
parser-epoch cache invalidation, schema-version auto-rebuild, and
async-default sync retired the original "API still evolving" risk
(RE-6).

Pin = release tag =v2.4.0= (commit
=0f55c96b6649872155d5486acb749710b3726e4a=). straight.el does *not*
honour a recipe-level =:commit= keyword — version pinning is otherwise
done through a profile *versions lockfile*, which this config does not
maintain. straight *does* pass =:branch= to =git clone --branch=, and
git accepts a tag name there, so =:branch "v2.4.0"= checks out the
release tag (detached HEAD at the commit above). That is the
working, declarative pin and it satisfies the task's "v2.4.x release
tag/commit" requirement. A profile lockfile entry is the production-grade
follow-up if the spike survives.

Change detection prefers =fswatch= on macOS; if it is not installed,
vulpea falls back to fd/find polling, so the spike does not require it.

=:config= pins =vulpea-db-location= to the isolated runtime path (D8 /
=register/invariant/vulpea-db-isolation=) and otherwise stays minimal —
directory sync and autosync wiring belong to the =registry-discovery=
task, not here.

D8 requires the org-graph index DB to live under the worktree runtime
=state/= dir (=runtime/state/vulpea/notes.db=), distinct from org-roam
and from vulpea's default (=runtime/vulpea.db=). Isolation is the
spike's clean-rollback property: wiping/rebuilding the org-graph DB then
never touches org-roam's DB or the =org-id-locations= cache.

The path is set here in the *loader's* vulpea =:config=, not in
=discovery/configure-sync=, because it MUST be fixed before the first
DB open. Module load itself is DB-free (both DB-touching ops — the
=org-id-locations= seed and the extractor registration — are deferred
to =emacs-startup-hook=; see [[#deferred-registrations][Deferred
DB-touching registrations]]), so the first open happens at a deferred
op or an interactive command. The loader's vulpea =:config= runs
eagerly when this block evaluates — before submodules load and long
before the startup hook fires — so the path is fixed first in every
case. =user-emacs-directory= resolves to this worktree's =runtime/=
dir (see =early-init.el=), so the path is worktree-isolated. The
directory is created if vulpea has not already done so.

#+begin_src emacs-lisp
(use-package vulpea
  :straight (vulpea :type git :host github :repo "d12frosted/vulpea"
                    :branch "v2.4.0")
  :config
  (setq vulpea-db-location
        (expand-file-name "state/vulpea/notes.db" user-emacs-directory))
  (make-directory (file-name-directory vulpea-db-location) t))
#+end_src

* Workspace integration
:PROPERTIES:
:CUSTOM_ID: workspace-integration
:END:

Registration with the =workspaces= integration registry (=:on-create=

=workspace-assistant= preset's =:tools= slot.  Implemented in the

load-wired from the consolidated [[#submodules][Submodules]] sequence
(not here), as the LAST submodule.

* Submodules
:PROPERTIES:
:CUSTOM_ID: submodules
:END:

All org-graph submodules are load-wired here, in ONE dependency-correct
sequence (=register/invariant/org-graph-loader-ordered-sequence=).  Each
submodule's basename differs from the feature it =provide='s
(=schemas.el= → =org-graph-schemas=, =finders.el= → =org-graph-finders=,
=tools.el= → =org-graph-tools=, =workspace-integration.el= →
=org-graph-workspace-integration=, …), so =require= cannot auto-resolve
load order: order is *load-bearing* and is made explicit by loading each
file BY PATH via =jf/load-module=.

Canonical order: =schemas → extractor → coordinator → query → finders →
edge-type → tools → discovery=, with =workspace-integration= last (AFTER =tools=,
because its =:tools= population needs =org-graph/agent-tools= from
=tools.el=).  Dependencies the order satisfies: =finders= requires
=org-graph-schemas=; =tools= layers on =query= and =coordinator=;
=workspace-integration= consumes =org-graph/agent-tools=.

Module load stays *DB-free*.  The two registrations that open the vulpea
DB — the discovery =org-id-locations= seed (=vulpea-db-query=) and the
typed-edge extractor (=vulpea-db-register-extractor= applies the
=typed_edges= schema) — are NOT run at load: the loader defers both to
=emacs-startup-hook= in the [[#deferred-registrations][Deferred
DB-touching registrations]] section below.  The DB-free registrations
(schemas register in memory at load; gptel tools register at load when
gptel is present; =workspace-integration= attaches via
=with-eval-after-load=) all fire as their files load.

(jf/load-module (expand-file-name "config/org-graph/schemas.el" jf/emacs-dir))

(jf/load-module (expand-file-name "config/org-graph/coordinator.el" jf/emacs-dir))
(jf/load-module (expand-file-name "config/org-graph/query.el" jf/emacs-dir))
(jf/load-module (expand-file-name "config/org-graph/finders.el" jf/emacs-dir))
(jf/load-module (expand-file-name "config/org-graph/edge-type.el" jf/emacs-dir))

** Deferred DB-touching registrations
:PROPERTIES:
:CUSTOM_ID: deferred-registrations
:END:

The loader owns BOTH post-init deferrals, through one shared idiom.  The
two DB-touching ops — the discovery =org-id-locations= seed
(=org-graph/seed-org-id-locations= calls =vulpea-db-query=) and the
typed-edge extractor registration (=org-graph-extractor-register=
applies the =typed_edges= schema via =vulpea-db-register-extractor= →
=vulpea-db--apply-plugin-schema=) — would each break the DB-free-load
contract (and the cold-load guard) if run at module-load time
(USER-RESOLVED decision =ask-cycle-1782570180-1=: defer to post-init).
Both are deferred to =emacs-startup-hook= — the post-init seam that,
unlike =after-init-hook=, runs AFTER this config's =-q --load init.el=
command-line actions (see =bin/emacs-isolated.sh=; matches
=config/look-and-feel/themes.el=).  In =-batch= no startup hook runs, so
a bare =(require 'org-graph)= opens no DB — the cold-load guard
(=config/org-graph/test/module-load-spec.el=) verifies the wiring and
drives the wired functions directly with the DB boundary stubbed.

Each deferral stays a *named* function on the hook (not a closure): the
guard asserts membership by name, =add-hook= stays idempotent across
module reloads, and =remove-hook= works interactively.  The shared
resilience body lives in =org-graph--run-deferred-op=: a missing/unbuilt
DB at startup is logged via =display-warning= — visible, but never
aborting startup.  A silent no-op would be worse than a warning here
(e.g. =id:= links quietly failing to resolve is exactly the gap the seed
exists to close).

#+begin_src emacs-lisp
(defun org-graph--run-deferred-op (fn what)
  "Run FN, a deferred DB-touching org-graph op, resiliently.
Shared body for the org-graph `emacs-startup-hook' deferrals: FN opens
the vulpea DB and so runs post-init rather than at module-load time
(module load stays DB-free).  WHAT is a short description used in the
warning when FN fails.  A failure (e.g. a missing/unbuilt DB) is logged
via `display-warning' rather than aborting startup."
  (condition-case err
      (funcall fn)
    (error
     (display-warning 'org-graph
                      (format "%s skipped: %S" what err)
                      :warning))))
#+end_src

The seed's behaviour is unit-tested against
=org-graph/seed-org-id-locations= directly (=discovery-spec.el=); this
wrapper's only job is post-init resilience.

#+begin_src emacs-lisp
(defun org-graph--seed-org-id-locations-deferred ()
  "Run the `org-id-locations' seed once, resiliently, for `emacs-startup-hook'.
`org-graph/seed-org-id-locations' calls `vulpea-db-query', which opens
the vulpea DB, so it is deferred out of module-load time (load stays
DB-free).  A missing/unbuilt DB is logged via `display-warning' rather
than aborting startup."
  (org-graph--run-deferred-op #'org-graph/seed-org-id-locations
                              "org-id-locations seed"))

(add-hook 'emacs-startup-hook #'org-graph--seed-org-id-locations-deferred)
#+end_src

#+begin_src emacs-lisp
(defun org-graph--register-extractor ()

schema and so opens the vulpea DB) for `emacs-startup-hook'.  A
missing/unbuilt DB is logged via `display-warning' rather than aborting
startup."

(add-hook 'emacs-startup-hook #'org-graph--register-extractor)
