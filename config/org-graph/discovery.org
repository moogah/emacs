#+title: Org Graph — Vault Discovery
#+author: Jeff Farr
#+property: header-args:emacs-lisp :tangle discovery.el
#+auto_tangle: y

vulpea discovery for org-graph.  vulpea is the single index; this
module feeds it *exactly one* root — the expanded =org-graph-vault-root=
(default =~/org/=, the whole durable note vault including its =roam/=
and =sessions/= subdirectories) — and seeds =org-id-locations= from the
vulpea DB at startup so =id:= links resolve immediately on a fresh
session.

No other package is consulted to discover roots, no directory outside
the vault is ever added to the sync set, and no wider tree (e.g.
=~/work=) is ever walked.  ID-bearing notes anywhere under the vault
root are indexed; hidden directories under the vault (any path segment
beginning with =.=) are excluded by vulpea's own rule
(=vulpea-db-sync--org-file-p= rejects paths containing =/.=), so
org-graph adds no file predicate of its own
(=register/invariant/bounded-discovery-roots=).

The earlier registry-driven form — a second contribution of workspace
home directories, gated by a loader toggle — is gone: indexing a home
recursively swept up thousands of third-party org files under a
checked-out worktree's =runtime/= and evaluated their file-local
variables from the sync timer, and notes no longer live in homes.
Anything that binds graph behaviour to another package belongs to the
integration layer (=config/integrations/=), never here
(=register/invariant/packages-independent-no-cross-naming=).

* Default notes directory

Where =vulpea-create= (and therefore the create-on-miss paths of
=vulpea-find= / =vulpea-insert=) puts new notes.  Without this, vulpea
falls back to the *first* entry of =vulpea-db-sync-directories= — which
is empty until =org-graph/configure-sync= has run in the session, so new
notes would silently land in =org-directory=.  Pinning it makes note
creation boot-order-independent.

The directory derives from =org-graph-vault-root= (boundp-guarded, same
pattern as the index-roots seed) so placement and the index root stay
aligned: default-placed new notes live inside the re-scan boundary and
survive a full DB rebuild.

The filename template pins the *dash* separator between timestamp and
slug (=20260813104944-some_note.org=), matching the existing corpus
convention; vulpea's own default uses an underscore
(=${timestamp}_${slug}.org=).  See
=register/invariant/note-filename-template-dash= — the agent path
(=tools.el= =org-graph-tools/write-node=) carries the same dash
convention independently in its own format string.

Set with plain =setq= (not defcustoms of our own): both variables are
vulpea's own defcustoms, and =defcustom= does not clobber an existing
binding, so this is safe regardless of whether vulpea loads before or
after this module.

#+begin_src emacs-lisp
(setq vulpea-default-notes-directory
      (file-name-as-directory
       (expand-file-name (if (boundp 'org-graph-vault-root)
                             org-graph-vault-root
                           "~/org"))))

(setq vulpea-create-default-template
      '(:file-name "${timestamp}-${slug}.org"))
#+end_src

* Index roots

The whole discovery contract: a single-element list holding the
canonicalised vault root.  The =boundp= guard keeps this module loadable
standalone (the defcustom lives in the loader, =org-graph.org=) — with
=org-graph-vault-root= unbound the root falls back to =~/org/=, the same
directory as the defcustom's default.  There is no second contribution
and no fallback that walks a wider tree.

#+begin_src emacs-lisp
(defun org-graph/index-roots ()
  "Return the explicit list of directories vulpea SHALL index.
Exactly one entry: `org-graph-vault-root' (canonicalised: expanded,
trailing slash), falling back to ~/org/ when the loader defcustom is
unbound.  No other package is consulted and no wider tree is ever
walked to discover notes; hidden subdirectories of the vault are
excluded by vulpea itself
\(`register/invariant/bounded-discovery-roots')."
  (list (file-name-as-directory
         (expand-file-name
          (if (boundp 'org-graph-vault-root)
              org-graph-vault-root
            "~/org/")))))
#+end_src

* Configure sync

Point vulpea at the vault root, enable autosync, and trigger an initial
async scan.  Interactive and idempotent so it can be re-run on demand
(e.g. from the menu's Maintain → re-index entry, or after changing
=org-graph-vault-root= mid-session).

#+begin_src emacs-lisp
(defun org-graph/configure-sync ()
  "Point vulpea at the vault root and enable autosync.
Sets `vulpea-db-sync-directories' to `org-graph/index-roots', enables
`vulpea-db-autosync-mode', and triggers an initial (async) full scan.

Idempotent: re-running overwrites the directory list, leaves autosync
enabled, and re-scans with smart change detection.  Interactive so it
can be invoked on demand as a manual re-index."
  (interactive)
  (setq vulpea-db-sync-directories (org-graph/index-roots))
  (vulpea-db-autosync-mode 1)
  (vulpea-db-sync-full-scan))
#+end_src

* Seed org-id-locations

vulpea registers ids lazily (per file touch) and offers no bulk seed, so
on a fresh session a previously-indexed note may not be =id:=-link
resolvable until its file is re-touched.  Walk the vulpea DB once and
register every id → path with =org-id-add-location= to close that gap.

#+begin_src emacs-lisp
(defun org-graph/seed-org-id-locations ()
  "Seed Emacs's global `org-id-locations' from the vulpea DB.
Iterate every note returned by `vulpea-db-query' and register its
id -> path with `org-id-add-location'.  Notes missing an id or path are
skipped.  Cheap; intended to run once per session — the org-graph loader
defers it to `emacs-startup-hook' — so `id:' links resolve on a fresh
session without waiting for vulpea's lazy per-file-touch registration."
  (dolist (note (vulpea-db-query))
    (let ((id (vulpea-note-id note))
          (path (vulpea-note-path note)))
      (when (and id path)
        (org-id-add-location id path)))))
#+end_src

* Post-init seed (deferred by the loader)

The seed calls =vulpea-db-query=, which opens the vulpea DB, so it MUST
NOT run when this module loads: module load stays *DB-free* (a load-time
DB open would break the DB-free-load contract and the cold-load guard).
The deferral itself is owned by the *loader*, not this module: the
=org-graph= loader (=config/org-graph/org-graph.org=, "Deferred
DB-touching registrations") wires
=org-graph--seed-org-id-locations-deferred= onto =emacs-startup-hook=
alongside the typed-edge extractor registration, through the shared
resilient-deferral idiom (=org-graph--run-deferred-op= — failures are
logged via =display-warning=, never abort startup).

* Parser hardening
:PROPERTIES:
:CUSTOM_ID: parser-hardening
:END:

Two runtime guards on vulpea's indexer, installed here because this
module already owns the vulpea sync surface.  Both are =:around= advice
on functions of the pinned vulpea v2.4.0 (=vulpea-db-extract.el= /
=vulpea-db-sync.el=), added idempotently at module load — before any
sync can run — rather than carried as a vulpea fork: two stable seams,
a few lines each, and =advice-add= is a no-op when the advice is
already present.  Both entry points are private (=--=) vulpea
functions, so the spec asserts =advice-member-p= on each: a vulpea
bump that renames either fails the suite loudly instead of silently
reopening the hole.

** Hazard 1 — file-local variables evaluated during indexing

With =vulpea-db-parse-method= at its default =temp-buffer=, every
parse sets =buffer-file-name= to the file and re-runs =(org-mode)= with
hooks.  =run-mode-hooks= calls =hack-local-variables= whenever the
buffer has a file name, so a =Local Variables:= block at the end of an
indexed file is read and — subject to =enable-local-variables= — its
=eval:= entries are evaluated.  The incident that started this change
was exactly that: a third-party org file under a recursively indexed
workspace home carried =eval: (org-hugo-auto-export-mode -1)=, which
ran from the sync timer and dropped into the debugger.  Vault-only
discovery removes that particular file, but the exposure is
root-independent (any file dropped in the vault can carry an =eval:=
local), so it is closed at the parser
(=register/invariant/index-parser-never-evaluates-file-locals=).

The advised seam is =vulpea-db--parse-file=, the single dispatcher
that =vulpea-db-update-file= calls for every indexed file.  It
selects among the three parse methods — =single-temp-buffer=,
=temp-buffer= (both via =vulpea-db--parse-with-temp-buffer=) and
=find-file= (=find-file-noselect=, which also runs =hack-local-variables=
and additionally honours =.dir-locals.el=; forced for
=vulpea-db-extra-extensions= such as =.org.gpg=).  Binding the two
variables around the dispatcher covers all three, so the guarantee does
not depend on the parse-method setting.  =enable-local-variables= nil
makes =hack-local-variables= read nothing at all (no filter, no
confirmation prompt, no =eval=); =enable-dir-local-variables= nil is
belt-and-braces for the =find-file= branch.  The parse itself is
untouched: org keywords (=#+title=, =#+filetags=, =#+property=) are not
local variables and are still honoured.

#+begin_src emacs-lisp
(declare-function vulpea-db--parse-file "vulpea-db-extract" (path))
(declare-function vulpea-db-sync--update-file-if-changed "vulpea-db-sync"
                  (path &optional hash-cache))
#+end_src

#+begin_src emacs-lisp
(defun org-graph--vulpea-parse-safely (orig &rest args)
  "Call ORIG, vulpea's per-file parser, with file-local variables disabled.
Binds `enable-local-variables' and `enable-dir-local-variables' to nil
for the whole parse so a `Local Variables' block (in particular its
`eval:' entries) is never read, evaluated, or confirmed while indexing,
whatever the user's global settings.  Installed `:around'
`vulpea-db--parse-file' by `org-graph--install-vulpea-hardening'."
  (let ((enable-local-variables nil)
        (enable-dir-local-variables nil))
    (apply orig args)))
#+end_src

** Hazard 2 — one bad file takes down the sync timer

=vulpea-db-sync--update-file-if-changed= is the per-file unit of both
the autosync queue processor (=vulpea-db-sync--process-queue=, run from
a timer) and =vulpea-db-sync-full-scan=; each caller loops over its
batch and calls it once per path.  Wrapping that unit in a
=condition-case= bounds the blast radius of any per-file failure — a
malformed drawer, an encoding error, a future extractor bug — to a
single logged skip: the wrapper returns nil (the caller counts the file
as unchanged and moves on), the file's stored hash is left as it was so
the next scan retries it, and the batch continues
(=register/invariant/index-sync-per-file-errors-contained=).

The skip is recorded as =(FILE . ERROR)= in the =*org-graph*= buffer
and echoed with =message=, through the small =org-graph--log= helper
below (this module's first logging need; other modules use
=display-warning= for startup-time failures).

Precision about the debugger: a =condition-case= keeps the debugger
out for errors that *reach* it unhandled — with =debug-on-error= t,
Emacs only enters the debugger for errors no =condition-case= handles.
It cannot intercept a frame deeper in the call that handles the error
itself with a =debug= condition (=condition-case-unless-debug= /
=with-demoted-errors=), because the debugger is entered at signal time
inside that frame.  =run-mode-hooks= wraps =hack-local-variables= in
exactly such a frame, which is how the incident reached the debugger
despite vulpea's own per-file handler — and why Hazard 1 is the
load-bearing fix for it, with this guard as the independent backstop.

#+begin_src emacs-lisp
(defconst org-graph--log-buffer-name "*org-graph*"
  "Name of the buffer `org-graph--log' appends to.")

(defun org-graph--log (format-string &rest args)
  "Append a timestamped line to `org-graph--log-buffer-name' and echo it.
FORMAT-STRING and ARGS are as for `format'.  Returns the formatted line."
  (let ((line (apply #'format format-string args)))
    (with-current-buffer (get-buffer-create org-graph--log-buffer-name)
      (let ((inhibit-read-only t))
        (goto-char (point-max))
        (insert (format-time-string "[%Y-%m-%d %H:%M:%S] ") line "\n")))
    (message "org-graph: %s" line)
    line))
#+end_src

#+begin_src emacs-lisp
(defun org-graph--vulpea-update-safely (orig path &rest args)
  "Call ORIG, vulpea's per-file sync update, on PATH; contain any error.
On error, log (PATH . ERROR) via `org-graph--log' and return nil so the
sync loop treats the file as skipped and continues with the next one.
ARGS are passed through.  Installed `:around'
`vulpea-db-sync--update-file-if-changed' by
`org-graph--install-vulpea-hardening'."
  (condition-case err
      (apply orig path args)
    (error
     (org-graph--log "sync: skipped %S -- %s  (%S . %S)"
                     path (error-message-string err) path err)
     nil)))
#+end_src

** Installer

Named and idempotent so it can be re-run from a module reload; the
advice functions are added by symbol, so a redefinition of either
=defun= above does not stack a second copy.  Installed at load: with
vulpea already loaded by the loader's =use-package= the advice wraps
the live definitions, and if vulpea were to load later =advice-add= on
a not-yet-defined symbol still takes effect when the =defun= runs.

#+begin_src emacs-lisp
(defun org-graph--install-vulpea-hardening ()
  "Install the parser and sync-containment advice on vulpea (idempotent).
Adds `org-graph--vulpea-parse-safely' `:around' `vulpea-db--parse-file'
and `org-graph--vulpea-update-safely' `:around'
`vulpea-db-sync--update-file-if-changed'.  `advice-add' is a no-op when
the advice is already present, so repeated calls are harmless."
  (advice-add 'vulpea-db--parse-file
              :around #'org-graph--vulpea-parse-safely)
  (advice-add 'vulpea-db-sync--update-file-if-changed
              :around #'org-graph--vulpea-update-safely))

(org-graph--install-vulpea-hardening)
#+end_src
