* Overview

The =workspace-integrations= capability is a generic registry that lets
peripheral subsystems attach behaviour to the workspace creation flow
*without* the workspaces core knowing anything about them.  Workspaces
publishes a stable extension surface; consumers (e.g. a gptel-sessions
attachment) register against it from their own side.  This module names
*no* consumer symbol — the registry is entirely generic.

Three extension surfaces exist per integration:

- =:on-create= — a handler invoked once per workspace creation, given a
  flat *anchor payload* plist.  Returns one of =ok= / =skipped= /
  =(failed . REASON)=.
- =:menu= — a =(KEY . COMMAND)= pair consumed by the (later) transient
  menu task.  Stored here as opaque data; this module does not act on it.
- =:on-purge= — a handler invoked once per workspace purge (teardown),
  given the same flat *anchor payload* plist.  Returns one of =ok= /
  =skipped= / =(failed . REASON)=.  Teardown is a generic lifecycle
  event, so it lives as a registry surface rather than ad-hoc advice
  from any one consumer.

Design references: design.md §Decisions 1–4; spec =workspace-integrations=.

The single hard dependency is =data-model.el=, whose accessors
(=workspace--name=, =workspace--home=, =workspace-node-id=) the payload
constructor reads off the live workspace record.  The dispatchers also
consult =workspace--registry= (defined in =tabs.el=, which loads after
this module and calls into it) to re-read the current record per
handler; it is forward-declared here and treated as optional so the
registry surface stays loadable on its own.  No path logic lives here
and the package has no session concept: the payload carries the
workspace's own self-knowledge and nothing derived from it.

* Registry storage

An *ordered alist* =((ID . PLIST) ...)= — not a hash table.  Both
creation-time dispatch and the (later) menu must iterate in
registration order, and re-registration must preserve an entry's
existing position (Decision 1).

#+begin_src emacs-lisp
(defvar workspace--integrations nil
  "Alist of (ID . PLIST) registered workspace integrations, in order.
ID is a symbol.  PLIST may carry `:label' (string), `:on-create'
\(payload -> ok|skipped|(failed . reason)), `:menu' ((KEY . COMMAND)),
and `:on-purge' (payload -> ok|skipped|(failed . reason)).
Insertion order is significant: dispatch and menu rendering both
follow it, and re-registering an existing ID updates in place.")
#+end_src

* Registration entry point

A =cl-defun= (not a macro) so the registry stays pure data and tests can
register fakes with keyword args.  Requires at least one extension
surface (=:on-create=, =:menu=, or =:on-purge=); re-registering an ID
overwrites its plist *in place*, preserving order.

#+begin_src emacs-lisp
(cl-defun workspace-register-integration (id &key label on-create menu on-purge)
  "Register workspace integration ID (a symbol).
LABEL is a display string.  ON-CREATE is an optional handler called
with the anchor payload at workspace-creation time, returning `ok',
`skipped', or (failed . REASON).  MENU is an optional (KEY . COMMAND)
pair for the integration transient.  ON-PURGE is an optional handler
called with the anchor payload at workspace-purge (teardown) time,
returning `ok', `skipped', or (failed . REASON).

At least one of ON-CREATE, MENU, or ON-PURGE must be supplied;
otherwise signal a `user-error' (a registration with none of the three
surfaces is inert and almost certainly a mistake).

Re-registering an already-present ID replaces its plist IN PLACE,
preserving the entry's position in `workspace--integrations'.  A new
ID is appended to the end, so registration order == dispatch/menu
order.  Returns ID."
  (unless (or on-create menu on-purge)
    (user-error "workspace-register-integration: %s has none of :on-create, :menu, :on-purge" id))
  (let ((plist (list :label label :on-create on-create :menu menu :on-purge on-purge))
        (cell (assq id workspace--integrations)))
    (if cell
        (setcdr cell plist)
      (setq workspace--integrations
            (append workspace--integrations (list (cons id plist))))))
  id)
#+end_src

* Anchor payload constructor

The single source of payload shape (Decision 2).  A flat, extensible
plist so future keys (β's =:integration-choices=) extend freely.  The
keys are =:name=, =:home=, =:node-id=, and =:context=
(register/shape/workspace-integration-anchor-payload).

The constructor takes the *live workspace record*, not a name/home
snapshot.  This is what makes the ordering contract hold: an
=:on-create= handler may set the workspace's =:node-id= through the
public =workspace-set-node-id=, and every handler that runs after it in
the same dispatch must see the new value.  The dispatchers below
therefore rebuild the payload once per handler rather than once before
the loop, and — crucially — *re-read the record from the registry* for
each rebuild rather than reusing the object they were handed.  Object
identity is not a guarantee this package offers: every other mutator
(=workspace--sync-registry-from-bufferlo=, layout autosave, the
tab-switch advice that drives both) is copy-on-write and *replaces*
the registry entry, so a handler that switches tabs or triggers an
autosave before calling the setter would otherwise leave the
dispatcher holding a stale record and later handlers reading
=:node-id nil=.  =workspace--integration-live-record= performs the
re-read and falls back to the handed-over record when the name is not
registered — which is what lets purge-time dispatch carry =:node-id=
after =workspace-purge= has already removed the entry.

#+begin_src emacs-lisp
(defun workspace--integration-payload (ws context)
  "Build the anchor payload plist for workspace record WS.
WS is the live workspace plist (see `workspace--make'); CONTEXT is the
symbol describing why the payload is being built (`fresh',
`anchored-scaffolded', `anchored-existing', `menu-invoke', `purge').
The payload carries WS's self-knowledge only: `:name', `:home',
`:node-id' (an opaque string or nil, read from WS at call time), and
`:context'.  It is flat and extensible: handlers read only the keys
they need.  Callers that must observe a `:node-id' written mid-flight
rebuild the payload from the registry's CURRENT record for WS's name
\(see `workspace--integration-live-record') rather than caching one."
  (list :name (workspace--name ws)
        :home (workspace--home ws)
        :node-id (workspace-node-id ws)
        :context context))
#+end_src

* Live-record lookup

The dispatchers hand each handler a payload built from the registry's
*current* record for the workspace, not from the record captured when
dispatch began.  The package's mutators are copy-on-write (they
=copy-sequence= the plist and =puthash= the copy), so the captured
object can be superseded mid-loop; only a fresh =gethash= sees what a
previous handler wrote through =workspace-set-node-id= after such a
replacement.  When the name is not in the registry (purge-time
dispatch runs after =workspace-purge= has unregistered it) or the
registry is not loaded at all (this module is loadable standalone —
=workspace--registry= lives in =tabs.el=), the handed-over record is
used as-is.

#+begin_src emacs-lisp
(defun workspace--integration-live-record (ws)
  "Return the registry's current record for workspace WS, else WS.
WS is a workspace plist.  Look up its `:name' in `workspace--registry'
and return the record stored there, so a caller rebuilding a payload
mid-dispatch observes replacements made by copy-on-write mutators and
any `:node-id' written to the replacement.  Fall back to WS itself
when the name is unregistered (purge-time dispatch) or when
`workspace--registry' is not bound (the registry module is not
loaded)."
  (or (and (boundp 'workspace--registry)
           (gethash (workspace--name ws) workspace--registry))
      ws))
#+end_src

* Per-integration runner

Runs one entry's handler (the =:on-create= surface by default, or any
surface named by SURFACE-KEY) under an error guard and normalizes the
result (Decision 3).  Returns =(ID . OUTCOME)= where OUTCOME is one of
=ok=, =skipped=, or =(failed . REASON)=.  Unknown handler return values
are treated leniently as =ok=; a signalled error normalizes to
=(failed . MESSAGE)=.  One normaliser serves every lifecycle surface
(=:on-create=, =:on-purge=, ...).

#+begin_src emacs-lisp
(defun workspace--run-one-integration (entry payload &optional surface-key)
  "Run ENTRY's SURFACE-KEY handler on PAYLOAD; return (ID . OUTCOME).
ENTRY is a (ID . PLIST) cell.  SURFACE-KEY names the handler slot to
run and defaults to `:on-create'; pass `:on-purge' to run the purge
surface.  OUTCOME is `ok', `skipped', or (failed . REASON).  The
handler call is wrapped in `condition-case': a signalled error
normalizes to (failed . ERROR-MESSAGE).  Handler return values are
mapped as `ok' -> ok, `skipped' -> skipped, (failed . R) ->
\(failed . R); any other value is treated leniently as `ok'."
  (let ((id (car entry))
        (handler (plist-get (cdr entry) (or surface-key :on-create))))
    (condition-case err
        (cons id
              (pcase (funcall handler payload)
                ('ok 'ok)
                ('skipped 'skipped)
                (`(failed . ,reason) (cons 'failed reason))
                (_ 'ok)))
      (error (cons id (cons 'failed (error-message-string err)))))))
#+end_src

* Creation-time dispatch

Additive, never signals (Decision 4).  Runs every registered
=:on-create= once in registration order, skips entries lacking
=:on-create=, =message='s each failure, and returns the result alist.
The payload is rebuilt for *each* handler from the record re-read
out of the registry at that moment (=workspace--integration-live-record=),
so a =:node-id= set by an earlier handler is visible to later ones even
when an intervening copy-on-write mutation replaced the registry entry
(the ordering contract in the =workspace-integrations= spec,
"Creation-time dispatch").  The creation pipeline in =tabs.el= calls
this after the record is registered.

#+begin_src emacs-lisp
(defun workspace--dispatch-create-integrations (ws context)
  "Dispatch all integration `:on-create' handlers for new workspace WS.
WS is the just-registered live workspace record; CONTEXT is the
creation context symbol (see `workspace--integration-payload').  Each
registered integration with an `:on-create' handler is run once, in
registration order, on a payload rebuilt immediately before that
handler runs from the registry's CURRENT record for WS's name (see
`workspace--integration-live-record') — so a `:node-id' written by an
earlier handler via `workspace-set-node-id' is present in every later
handler's payload, even if a copy-on-write mutator replaced the
registry entry in between.  Entries lacking `:on-create' are skipped.  Each (failed . REASON)
outcome is surfaced via `message' as
\"workspace: integration %s failed: %s\".  Returns the alist of
\(ID . OUTCOME) results.  NEVER signals: handler errors are caught by
`workspace--run-one-integration'."
  (let ((results nil))
    (dolist (entry workspace--integrations)
      (when (plist-get (cdr entry) :on-create)
        (let* ((payload (workspace--integration-payload
                         (workspace--integration-live-record ws) context))
               (result (workspace--run-one-integration entry payload))
               (outcome (cdr result)))
          (when (and (consp outcome) (eq (car outcome) 'failed))
            (message "workspace: integration %s failed: %s"
                     (car result) (cdr outcome)))
          (push result results))))
    (nreverse results)))
#+end_src

* Purge-time dispatch

Additive, never signals — the purge mirror of creation-time dispatch
(design.md §D3).  Builds the same anchor payload via the shared
constructor (per handler, mirroring creation-time dispatch), runs
every registered =:on-purge= once in registration order via the
generalised runner, skips entries lacking =:on-purge=, =message='s
each failure, and returns the result alist.  Teardown is a generic
lifecycle event (a consumer might retire the workspace's external
identity on it).  The per-handler re-read goes through the same
=workspace--integration-live-record=; because =workspace-purge= has
already unregistered the entry by the time purge dispatches, the
lookup falls through to the record =workspace-purge= hands over, which
still carries =:home= and =:node-id=.

#+begin_src emacs-lisp
(defun workspace--dispatch-purge-integrations (ws context)
  "Dispatch all integration `:on-purge' handlers for purged workspace WS.
WS is the workspace record being torn down (already removed from the
registry by `workspace-purge'; the record itself still carries `:home'
and `:node-id'); CONTEXT is the teardown context symbol (see
`workspace--integration-payload').  Each registered integration with
an `:on-purge' handler is run once, in registration order, on a
payload rebuilt per handler via `workspace--integration-live-record'
\(which falls back to WS, the name being unregistered) and run via
`workspace--run-one-integration' (surface key `:on-purge').  Entries lacking `:on-purge' are skipped.  Each
\(failed . REASON) outcome is surfaced via `message' as
\"workspace: integration %s purge-teardown failed: %s\".  Returns the
alist of (ID . OUTCOME) results.  NEVER signals: handler errors are
caught by `workspace--run-one-integration'."
  (let ((results nil))
    (dolist (entry workspace--integrations)
      (when (plist-get (cdr entry) :on-purge)
        (let* ((payload (workspace--integration-payload
                         (workspace--integration-live-record ws) context))
               (result (workspace--run-one-integration entry payload :on-purge))
               (outcome (cdr result)))
          (when (and (consp outcome) (eq (car outcome) 'failed))
            (message "workspace: integration %s purge-teardown failed: %s"
                     (car result) (cdr outcome)))
          (push result results))))
    (nreverse results)))
#+end_src
