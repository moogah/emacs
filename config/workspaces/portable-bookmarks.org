* Overview

Workspace-relative resolution of Emacs bookmarks.  A bookmark records an
absolute =filename=; when the same file lives in several checkouts of one
repository (a canonical clone plus one git worktree per workspace),
jumping to that bookmark opens whichever checkout happened to be current
when the bookmark was made.  This module stamps portable coordinates onto
new bookmark records and resolves them against the current workspace at
jump time.

** Boundary

This module is a *consumer* of the workspaces package, not part of its
core (=register/boundary/portable-bookmarks-consumer=).  The one-way rule:

- It MAY name =bookmark=, =git=, and workspaces registry internals
  (=workspace--registry=, =workspace--current-name=, =workspace--broken-p=,
  =workspace-restore=), and it reads core's one signal to consumers,
  =workspace--restoring-layout-leaf= (bound by =layouts.el= while a
  layout leaf is restored), guarded by =boundp=.  It also reads core's
  integration registry, =workspace--integrations=, guarded by =boundp=,
  for one question only: whether git-worktrees' add-worktree command is
  registered (see "What is offered, and why not").
- Workspaces CORE (=data-model= / =integrations= / =workspaces= / =tabs= /
  =persistence= / =layouts= / =workspaces-mode= / =workspaces-transient=)
  MUST NEVER name a =workspace-bookmark-*= symbol.  The single permitted
  mention in core is the loader PATH STRING "portable-bookmarks.el" in
  =workspaces.org= — a string, not a live symbol.
- One sibling CONSUMER module, =git-worktrees.el=, calls into this one:
  it calls =workspace-bookmark-canonical-checkouts-in-view= and the
  scope =workspace-bookmark-call-with-discovery-memo= and nothing else,
  never =require=s this module, and guards each call with =fboundp= at
  call time and with an error barrier.  Those two functions are
  cross-module interfaces with a stability promise (see "Cross-module
  interface: the canonical checkouts in view"); every
  =workspace-bookmark--= symbol stays private.

** No magit, no projectile

Git is reached by subprocess (=process-file=), never through magit.  This
is deliberately the OPPOSITE choice from =git-worktrees.el=, which reaches
worktrees via =magit-list-worktrees= and therefore carries a hard magit
dependency.  Bookmark resolution must not inherit it: bookmarks are a
stock-Emacs facility and this module has to keep working in a session that
has never loaded magit.  The two worktree enumerations are a known,
accepted overlap for this slice
(=register/boundary/portable-bookmarks-consumer= =known_overlap=).

** Droppable

Removing the single =jf/load-module= line in =workspaces.org= removes the
advice and returns behaviour to stock.  Records already stamped keep their
absolute =filename= and keep working — the stamp is additive.  Rollback is
one line.

** Load order

Loaded from the package loader =config/workspaces/workspaces.org=, NOT
from =jf/enabled-modules= in =init.org= (which holds the single entry
=("workspaces/workspaces" …)= for this whole package).  It loads after
=tabs.el= (owner of =workspace--registry= and =workspace--current-name=)
and after =persistence.el= (which defines =workspace-restore=), so the
loader line sits between =workspaces-mode.el= and
=workspaces-transient.el=.

** Status

Both advice seams are live.  The STAMP seam stamps a new bookmark
record for a single tracked file or directory inside a repository that
has a remote with the repository's identity, the location's
repository-relative path, and the stamp-format version.  The RESOLVER
(see "Resolution") decides, for a record and a workspace, which of six
outcomes applies.  The JUMP seam acts on that decision: it opens the
current workspace's copy, declines with a report, or hands
=missing-repo= to a bounded choice (see "Seam 2" and "Missing repo"),
and with no current workspace it first establishes one (see
"Off-workspace").  No route of the seam opens a stamped record's
stored absolute path for an outcome; the one residual is the seam's
error barrier, stated under "The barrier".

* Stamped property names

The three properties written into the user's bookmark file.  They are
named here and ONLY here: these symbols end up serialised into
=bookmark-default-file= on the user's disk, so renaming one later would
orphan every existing stamp.  The indirection is cheap insurance against
that.

They are =defconst=, not =defcustom=.  The names are an ON-DISK FORMAT,
not a preference: a user who customised one would silently orphan every
record stamped under the old name, and two machines sharing a bookmark
file with different settings would each read the other's stamps as
unstamped.  Nothing about the format is the user's to choose.

The three are written and read together — a record carries ALL THREE or
NONE (=register/shape/portable-bookmark-coordinates=).  A record carrying
some but not all is malformed and must resolve as =non-portable=, never
to a guess.

The format version exists so that a later change to what the coordinates
MEAN (a different identity normalization, a different relpath convention)
can be told apart from records stamped under this one, instead of being
discovered as a wrong-file open.  A reader that does not recognise the
version treats the record as unstamped.

* Git subprocess

Every git question this module asks goes through one runner.  Three of
its properties are contractual
(=register/boundary/git-derived-checkout-discovery= =subprocess_contract=):

- =process-file=, never =shell-command-to-string=.  No shell means no
  quoting, which matters concretely here: directory names on this machine
  contain spaces (=~/src/Archived Repos/=).
- =default-directory= is bound to the target directory for every
  invocation, so git answers about the checkout we mean rather than about
  wherever the current buffer happens to live.
- Failure returns nil and NEVER signals.  These helpers run inside
  =bookmark-make-record= and inside a bookmark jump; an error escaping
  into the bookmark machinery would break a core Emacs interaction for a
  peripheral feature.  A non-zero exit, a missing =git= executable, a
  directory that has since been deleted, and empty output all collapse to
  the same nil, and callers map nil to a degraded outcome.

stderr is discarded rather than captured: git writes diagnostics there on
exactly the failures we are deliberately ignoring, and folding them into
stdout would turn a clean nil into a bogus "value".

DIR may name a file rather than a directory — callers hand this helper
bookmark =filename= values.  An EXISTING file is resolved to its
directory.  A DIR that does not exist yields nil; it is NOT resolved to
its parent.  Querying the parent of a missing path answers for whatever
repository encloses that parent, which is a different repository from
the one the caller asked about.  Measured: a checkout named =proj = (with
a trailing space) inside a home that is itself a repository.  A trimmed
=--show-toplevel= spelling =proj= does not exist, and running git in its
parent returned the HOME's identity for a checkout of a different
repository.

*Only =default-directory= decides which repository git answers for.*
Binding it is not enough on its own: git gives =GIT_DIR=,
=GIT_WORK_TREE=, =GIT_COMMON_DIR= and their relatives precedence over the
working directory.  They reach Emacs's =process-environment= when Emacs is
started by git (as =GIT_EDITOR=, or from a hook, which exports =GIT_DIR=),
from a shell that exported them for a bare "dotfiles" repository, or by
=setenv=.  Measured with =GIT_DIR= set: every checkout took the identity of
the repository it named, and the workspace-checkout lookup (then a
singular helper, now =--workspace-checkouts=) returned a checkout of
a different repository.  The runner therefore unsets every variable git
lists as repository-local (=git rev-parse --local-env-vars=) plus the two
that steer repository discovery (=GIT_CEILING_DIRECTORIES=,
=GIT_DISCOVERY_ACROSS_FILESYSTEM=) and =GIT_NAMESPACE=.  An element
without === in =process-environment= removes that variable from the
subprocess environment, and putting the removals FIRST makes them win over
any duplicate later in the list.

*Output is not trimmed.*  Only the single line terminator git appends is
removed.  Whitespace at either end of a path is part of the path:
=string-trim= turned a checkout named =proj = into =proj=.  Callers that
read several lines split the output themselves.

LOCAL PATHS ONLY.  A remote (TRAMP) DIR is rejected before anything
touches the filesystem, and the whole body sits inside the error barrier.
Three distinct failures are being prevented, in increasing order of harm:

1. =file-directory-p= on a remote name SIGNALS rather than returning nil
   — measured: =/nosuchmethod:host:/tmp= raises =user-error=,
   =/ssh:nonexistent.invalid:/tmp= raises =file-error=.  The caller is
   =bookmark-make-record=, so the contract breach lands in a core Emacs
   interaction.
2. A reachable host is worse than an unreachable one: the probe becomes a
   synchronous network round trip — and =/sudo::= blocks on a password
   prompt — inside bookmark creation.  A hang is not a signal, so the
   =condition-case= would not save us.
3. Worst: =process-file= is TRAMP-aware, so on a reachable host git runs
   ON THAT HOST.  A bookmark for =/ssh:build-box:/srv/emacs/foo.el= would
   be stamped with the identity of the REMOTE checkout, and the resolver
   would later re-point it at a LOCAL worktree — a different machine's
   file, opened silently.  That is exactly
   =register/invariant/no-silent-wrong-file-open=.

A remote file is not portable in this capability's sense anyway: its
identity is the host, not a repo the workspace could hold.  Rejecting it
yields nil, which degrades to the record's stored absolute filename.

#+begin_src emacs-lisp
(defconst workspace-bookmark--git-unset-environment
  '("GIT_DIR" "GIT_WORK_TREE" "GIT_COMMON_DIR" "GIT_INDEX_FILE"
    "GIT_OBJECT_DIRECTORY" "GIT_ALTERNATE_OBJECT_DIRECTORIES"
    "GIT_NAMESPACE" "GIT_CEILING_DIRECTORIES"
    "GIT_DISCOVERY_ACROSS_FILESYSTEM" "GIT_IMPLICIT_WORK_TREE"
    "GIT_PREFIX" "GIT_CONFIG" "GIT_CONFIG_PARAMETERS" "GIT_CONFIG_COUNT"
    "GIT_GRAFT_FILE" "GIT_NO_REPLACE_OBJECTS" "GIT_REPLACE_REF_BASE"
    "GIT_SHALLOW_FILE")
  "Environment variables removed for every git subprocess this module runs.
Each one can make git answer about a repository other than the one
`default-directory' names.")

(defun workspace-bookmark--git (dir &rest args)
  "Run git with ARGS in DIR and return its stdout, or nil.

Only the one line terminator git appends is removed from the output;
other leading and trailing whitespace is kept, because it can be part of
a path.  Returns nil — never signals — when DIR is nil, remote or
missing, when git exits non-zero, or when git produces no output.  If
DIR names an existing file, git is run in the file's directory; a DIR
that does not exist is never resolved to its parent.  stderr is
discarded.  The variables in `workspace-bookmark--git-unset-environment'
are removed from git's environment, so `default-directory' alone decides
which repository git answers for.

DIR must be LOCAL.  A remote (TRAMP) name returns nil without touching
the filesystem: probing one can signal, can block on a password prompt,
and — on a reachable host — would run git remotely and stamp the wrong
machine's identity."
  (condition-case nil
      (let ((path (and (stringp dir)
                       (not (file-remote-p dir))
                       (expand-file-name dir))))
        (when (and path (not (file-remote-p path)))
          (let ((cwd (cond ((file-directory-p path)
                            (file-name-as-directory path))
                           ((file-exists-p path)
                            (file-name-directory (directory-file-name path))))))
            (when (and cwd (file-directory-p cwd))
              (let ((default-directory cwd)
                    (process-environment
                     (append workspace-bookmark--git-unset-environment
                             process-environment)))
                (with-temp-buffer
                  (when (eq 0 (apply #'process-file "git" nil '(t nil) nil args))
                    (let ((out (string-remove-suffix "\n" (buffer-string))))
                      (unless (string-empty-p out) out)))))))))
    (error nil)))
#+end_src

* Same file

Every "are these two paths the same file?" question in this module goes
through workspaces core's ONE identity predicate, =workspace--same-file-p=
(=data-model.org= § File identity): the device and inode numbers of the
two paths' truenames.  Spelling does not matter (trailing slash, =~=,
symlinks, letter case on a case-insensitive disk), and neither does
anything that can change while the file stays the same file.  Nil when
either path is not a local string or does not exist; remote names are
rejected before any filesystem call, as everywhere else in this module.

The module keeps no copy of its own.  The predicate was born here; core
needed the same answer, core may never name a symbol of this module, and
two bodies would drift, so the body moved to core and every call below
names the core symbol.

=file-equal-p= is NOT used.  It compares the two paths' WHOLE attribute
lists, access and modification times included, so a directory that is
modified, or merely read, between the two stats compares unequal to
itself.  In the ownership test, "not equal" means "not inside this
home", and ownership-first classification then calls a workspace's full
clone =canonical=.  The reviewer measured 4,817 wrong =canonical= answers
in 20,000 =--classify= calls while a shell loop created and removed one
file in the home.

* Repository identity

** Which repository this is

=origin= is preferred.  When there is no =origin= and there is EXACTLY
ONE remote, that one is used, so a checkout whose only remote is named
=upstream= still has an identity instead of silently degrading to "no
remote".  A repository with no remote at all returns nil, and that is the
whole answer: NO REMOTE MEANS NO IDENTITY.  A path-based fallback would be
meaningless on another machine, which is the one thing this capability
exists to survive.  On this machine 9 of 51 repositories under =~/src=
have no remote, so the nil branch is a normal case, not an edge case.

Two corrections to the obvious implementation, both of which produce a
CONFIDENTLY WRONG identity rather than a missing one:

=git remote get-url=, NOT =git config --get remote.origin.url=.  The
config value is raw; =get-url= is the effective URL.  Measured on a
throwaway repo: with =url."git@github.com:".insteadOf "gh:"=, the config
read returns =gh:moogah/emacs.git=, which normalizes to the fabricated
host =gh/moogah/emacs= — an identity that exists only in one machine's
gitconfig, and therefore precisely the cross-machine breakage this
capability exists to prevent.  =get-url= returns the expanded
=git@github.com:moogah/emacs.git=.  The same command also reads the LAST
value of a multi-valued =remote.origin.url= while git fetches the FIRST.
(The common =https= ↔ =ssh= =insteadOf= rewrite is harmless here, because
both spellings normalize equal; it is the shorthand aliases that break.)

SOLE remote, not FIRST remote.  =git remote= lists alphabetically, so
"first" makes the identity depend on remote NAMES: adding a remote called
=backup= to a repo whose only remote was =upstream= would silently re-key
every bookmark already stamped from it — the stamps are persisted, so they
are orphaned, not recomputed.  Ambiguity must degrade to nil, not to a
guess.

#+begin_src emacs-lisp
(defun workspace-bookmark--remote-url (dir)
  "Return the effective remote URL of the repository containing DIR, or nil.

`origin' is preferred.  When the repository has no `origin' but has
exactly ONE remote, that remote is used.  Returns nil when the repository
has no remote, when it has several and none is `origin', or when DIR is
in no repository.

Uses `git remote get-url', which expands `url.*.insteadOf' rewrites and
yields the URL git actually uses.  `git config --get remote.origin.url'
would return the raw, machine-local spelling."
  (or (workspace-bookmark--git dir "remote" "get-url" "origin")
      (let ((remotes (split-string
                      (or (workspace-bookmark--git dir "remote") "")
                      "\n" t "[ \t\r]+")))
        (when (= 1 (length remotes))
          (workspace-bookmark--git dir "remote" "get-url" (car remotes))))))
#+end_src

** Normalizing a remote URL to an identity

The single canonical translation between git's several spellings of one
remote and the single string persisted in
=register/shape/portable-bookmark-coordinates=.  Inlining it at a second
site is exactly the boundary-translation drift the register tier exists to
catch, so every producer goes through this function.

These must all normalize to =github.com/moogah/emacs=:

: git@github.com:moogah/emacs.git
: https://github.com/moogah/emacs
: ssh://git@github.com/moogah/emacs.git

*** The colon is two different things

git's remote syntax has two forms, and the colon means something different
in each:

- With an explicit scheme (=ssh://=, =https://=, =git://=) the URL is
  =scheme://[userinfo@]host[:PORT]/path= — a colon after the host
  introduces a PORT.
- Without a scheme, git reads the scp-like form =[userinfo@]host:path= —
  the colon is the path separator and there is NO port.  In
  =git@example.com:2222/team/repo.git= the =2222= is a directory name.

The scheme therefore selects the branch EXCLUSIVELY: a URL that has a
scheme but does not parse as one is nil, never retried as scp-like
syntax.  Falling through would read =https://github.com= as scp-like,
taking =https= for the host and =github.com= for the path — a WRONG
identity rather than an absent one, which is the difference between a
bookmark that degrades and a bookmark that resolves somewhere else.

So the disambiguation has to happen BEFORE the scheme is stripped: a rule
set that strips =scheme://= first and only then "converts the SSH
=host:path= colon to =/=" cannot tell the two apart any more, and turns
=ssh://git@example.com:2222/team/repo.git= into
=example.com/2222/team/repo= — which does not match the HTTPS spelling of
the same repository, defeating the whole point of normalizing.  A port is
transport, not identity, so with a scheme present the port is DROPPED.

*** Userinfo is stripped, and that is a privacy property too

=https://TOKEN@github.com/moogah/emacs.git= is a real shape for a
credential-embedded remote.  Since the identity is written into the user's
bookmark file on disk, keeping userinfo would persist a secret into a file
this capability had no business writing secrets into.  Everything before
the =@= goes, password form included.

*** Host is downcased, path is not

Hosts are case-insensitive, so downcasing the host is free.  Paths are NOT
downcased even though the major forges treat them case-insensitively,
because the two failure modes are not symmetric: keeping path case can at
worst make two spellings of ONE repository look like two (which degrades
to an unstamped or non-portable bookmark — safe), while downcasing can
make two DIFFERENT repositories on a case-sensitive host collide, which
would open the wrong file (=register/invariant/no-silent-wrong-file-open=).

*** No host, no identity

Anything that does not yield an explicit =host/path= returns nil.  This is
load-bearing, not merely tidy: a local remote (=/srv/git/repo.git=,
=file:///srv/git/repo.git=, =../sibling=) names a location on THIS
machine, so it is no more portable than the absolute filename the bookmark
already carries.  The two regexps below reject those by construction — a
local absolute path cannot start a host, and a relative path has no colon
before its first slash.

#+begin_src emacs-lisp
(defconst workspace-bookmark--scheme-prefix-re
  "\\`[a-zA-Z][a-zA-Z0-9+.-]*://"
  "Match the leading SCHEME:// of a remote URL.
Which branch of `workspace-bookmark--normalize-identity' applies is
decided by this alone.  A URL that has a scheme but does not parse is
nil, never retried as scp-like syntax: \"https://github.com\" read as
scp-like would yield the host \"https\".")

(defconst workspace-bookmark--scheme-url-re
  "\\`[a-zA-Z][a-zA-Z0-9+.-]*://\\(?:[^/@]*@\\)?\\([^/:]*\\)\\(?::[0-9]*\\)?/+\\(.*\\)\\'"
  "Match a remote URL carrying an explicit scheme.
Group 1 is the host, group 2 the path.  Any userinfo and any :PORT are
matched and discarded.  A `file://' URL has an empty host and is
therefore rejected downstream.")

(defconst workspace-bookmark--scp-url-re
  "\\`\\(?:[^/@]*@\\)?\\([^/:]+\\):\\(.*\\)\\'"
  "Match git's scp-like remote syntax, [USERINFO@]HOST:PATH.
Group 1 is the host, group 2 the path.  There is no port in this form:
git reads everything after the colon as the path.")
#+end_src

#+begin_src emacs-lisp
(defun workspace-bookmark--normalize-identity (url)
  "Return the normalized repository identity of URL, or nil.

The identity is HOST/PATH, with the scheme, any userinfo, any port, a
trailing \".git\" (in any case) and any trailing slash removed, runs of
slashes collapsed, and the host — but not the path — downcased.  The SSH, HTTPS and ssh:// spellings of one
repository therefore compare `equal'.

Returns nil for anything that does not name a host: local paths,
`file://' URLs, and malformed input."
  (when (stringp url)
    (let ((url (string-trim url))
          host path)
      (cond
       ((string-match-p workspace-bookmark--scheme-prefix-re url)
        (when (string-match workspace-bookmark--scheme-url-re url)
          (setq host (match-string 1 url)
                path (match-string 2 url))))
       ((string-match workspace-bookmark--scp-url-re url)
        (setq host (match-string 1 url)
              path (match-string 2 url))))
      (when (and host path)
        (setq host (downcase host))
        (setq path (replace-regexp-in-string "/+" "/" path))
        (setq path (replace-regexp-in-string "\\`/+" "" path))
        (setq path (replace-regexp-in-string "/+\\'" "" path))
        (when (string-suffix-p ".git" path t)
          (setq path (substring path 0 -4)))
        (setq path (replace-regexp-in-string "/+\\'" "" path))
        (unless (or (string-empty-p host) (string-empty-p path))
          (concat host "/" path))))))
#+end_src

** The identity of a checkout root

The remote is looked up at the checkout's ROOT, never at an arbitrary
directory inside it: the root is guaranteed to exist and to be a
directory, and it keeps the "which repository" question anchored to
the checkout git actually resolved.  For a linked worktree this still
works, because =remote.origin.url= lives in the shared config the
worktree reads through.

Every caller already knows the root before it asks: the stamp path and
discovery both place a directory with ONE =rev-parse= (its POSITION,
=workspace-bookmark--checkout-position=: root, shared git directory
and prefix together), and ask for the identity of the root that
position names, through the memo below.  So the question here is only
"given a root, what is its identity?".  There is no second function
that finds the root itself with a =rev-parse --show-toplevel= of its
own: once discovery moved onto the position, such a function (and its
root finder) had no caller outside the specs, and was removed rather
than kept alive by them.

#+begin_src emacs-lisp
(defun workspace-bookmark--root-identity (root)
  "Return the normalized identity of the checkout whose root is ROOT, or nil.
ROOT must already be a checkout root, as the first element of
`workspace-bookmark--checkout-position' names it.  Callers ask through
`workspace-bookmark--memoised-identity'."
  (workspace-bookmark--normalize-identity
   (workspace-bookmark--remote-url root)))
#+end_src

** Memoised per repository root

Stamping runs inside =bookmark-make-record=, and workspaces' own layout
save calls =bookmark-make-record= for EVERY live buffer on EVERY save —
including the idle-tick autosave.  Unmemoised, each of those records
would pay one to three extra =git remote= subprocesses to rediscover an
answer that almost never changes.  So identity is computed at most once
per repository root, and only the per-location questions (where is this
path, is it tracked) are asked each time.

Two decisions about what the memo holds:

- *A nil answer is memoised too.*  "No remote" is the normal case for 9
  of 51 repositories here, and it is exactly the case that would
  otherwise re-query on every save, forever.
- *It is validated, not trusted.*  Each entry carries the modification
  time of the repository's shared =config= file, which is where =git
  remote add=, =git remote set-url= and =git remote remove= write.  The
  stamp path already learns that file's location from the =rev-parse= it
  runs anyway (=--git-common-dir=), so checking it costs one =stat= and no
  subprocess.  Without this, re-pointing =origin= mid-session would keep
  stamping the OLD identity into new, persisted records.
- *The checkout's own =config.worktree= is part of the stamp.*  Under
  =extensions.worktreeConfig=, =git config --worktree= writes to
  =<git-dir>/config.worktree= — the shared =.git= for the main worktree,
  =.git/worktrees/<name>/= for a linked one — and =git remote get-url=
  reads that file (measured, git 2.49): a =url.*.insteadOf= rule set
  there rewrites the URL in that worktree only, and a remote defined
  only there is that worktree's sole remote.  A =remote.<name>.url= set
  there is appended to the shared one, so =get-url= still reports the
  shared URL first — but only while the shared one exists.  None of
  these writes touch the shared =config=, so its mtime alone would keep
  reusing the OLD identity for exactly the worktree whose identity
  changed.  The stamp is therefore the PAIR of modification times,
  shared =config= and the checkout's =config.worktree= (nil while that
  file does not exist, so its creation is a change too).  Finding the
  checkout's git directory costs no subprocess: it is =<root>/.git= when
  that is a directory, and the one-line =gitdir:= file git leaves at the
  root of a linked worktree otherwise.  What the stamp still does NOT
  see: anything outside the repository that =git remote get-url=
  honours — =url.*.insteadOf= rewrites in the global (=~/.gitconfig=,
  =~/.config/git/config=) or system gitconfig, or an =include.path= /
  =includeIf= target.  That blind spot is accepted and documented:
  =M-x workspace-bookmark-clear-identity-cache= covers it.  (Filesystems
  with coarse mtimes can also hide two config writes within one tick;
  the same command covers that.)
- *No stamp, no reuse.*  When the config file's modification time
  cannot be read, the stamp is nil.  An entry with a nil stamp would
  match every later nil stamp and never be revalidated, so a nil stamp
  never counts as a hit: identity is recomputed.  This is the failure
  that let a wrongly-resolved common dir freeze a stale identity (see
  "Where a location sits in its checkout").
- *It does not survive a reload.*  The memo holds the OUTPUT of
  =workspace-bookmark--normalize-identity=.  A =defvar= keeps its value
  when the file is loaded again, so after an edit to the normalizer
  followed by =jf/reload-module=, the session would go on persisting
  identities the OLD normalizer produced until each repository's config
  happened to change.  The memo is therefore emptied every time this file
  is loaded (the top-level form after the definitions below).

The key is the checkout ROOT, not the shared git directory, so each
linked worktree has its own entry.  That costs one lookup per worktree
per session and keeps the key identical to what =--show-toplevel=
reports — and, since the stamp includes that worktree's own
=config.worktree=, the key is exactly the granularity the stamp needs.

Discovery shares this memo (see "Checkout discovery" below): every
checkout a resolution or the repository picker asks about pays one
=rev-parse= for its position and, on a warm memo, nothing for its
identity.  A nil identity is memoised there too, and the same stamp
revalidates it: a checkout that gains a remote after a memoised-nil
lookup has its shared =config= written by =git remote add=, and is seen
on the next lookup.

#+begin_src emacs-lisp
(defvar workspace-bookmark--identity-memo (make-hash-table :test #'equal)
  "Memoised repository identities, keyed by checkout root.
Each value is (STAMP . IDENTITY), where STAMP is the value
`workspace-bookmark--config-stamp' returned when IDENTITY was computed
and IDENTITY may be nil.")

(defun workspace-bookmark-clear-identity-cache ()
  "Forget every memoised repository identity.

Each memoised identity is revalidated against the modification times of
its repository's own git config and of its checkout's `config.worktree',
so `git remote add', `set-url' and `remove', and `git config --worktree'
changes, are picked up without this command.  It is needed only after a
change the memo cannot see: a `url.*.insteadOf' rule (or anything else
`git remote get-url' honours) added to the global, XDG or system
gitconfig, or to an included config file.  Loading this module clears
the memo too."
  (interactive)
  (clrhash workspace-bookmark--identity-memo))

(defun workspace-bookmark--checkout-git-dir (root)
  "Return the git directory of the checkout at ROOT, or nil.  Runs no git.

ROOT's `.git' entry is the git directory itself when it is a directory
\(a main worktree), and names it when it is a file — the one-line
`gitdir: PATH' that git leaves at the root of a linked worktree, a
`--separate-git-dir' main worktree or a submodule, PATH being absolute
or relative to ROOT.  Nil when ROOT has no readable `.git' entry of
either kind.  Never signals."
  (condition-case nil
      (let ((dot-git (expand-file-name ".git" root)))
        (cond
         ((file-directory-p dot-git) dot-git)
         ((file-regular-p dot-git)
          (with-temp-buffer
            (insert-file-contents dot-git nil 0 4096)
            (goto-char (point-min))
            (when (looking-at "gitdir: \\(.+\\)$")
              (expand-file-name (match-string 1) root))))))
    (error nil)))

(defun workspace-bookmark--config-stamp (git-common-dir &optional root)
  "Return the stamp that validates a memoised identity, or nil.

The stamp is the list of two modification times: of GIT-COMMON-DIR's
`config', which `git remote' writes, and of the `config.worktree' in
the git directory of the checkout at ROOT (`workspace-bookmark--checkout-git-dir'),
which `git config --worktree' writes and `git remote get-url' honours
under `extensions.worktreeConfig'.  The second is nil while that file,
or ROOT, does not exist.  The whole stamp is nil when the shared
config's modification time cannot be read."
  (let ((shared (and git-common-dir
                     (file-attribute-modification-time
                      (file-attributes
                       (expand-file-name "config" git-common-dir))))))
    (and shared
         (list shared
               (let ((git-dir (and root
                                   (workspace-bookmark--checkout-git-dir root))))
                 (and git-dir
                      (file-attribute-modification-time
                       (file-attributes
                        (expand-file-name "config.worktree" git-dir)))))))))

(defun workspace-bookmark--memoised-identity (root git-common-dir)
  "Return the identity of the checkout at ROOT, memoised per ROOT.
GIT-COMMON-DIR is the repository's shared git directory.  The memoised
value is reused only while `workspace-bookmark--config-stamp' — the
shared config's modification time and that of ROOT's own
`config.worktree' — is unchanged, and never when the shared config's
modification time cannot be read.  A nil identity is memoised like any
other."
  (let ((stamp (workspace-bookmark--config-stamp git-common-dir root))
        (hit (gethash root workspace-bookmark--identity-memo)))
    (if (and hit stamp (equal (car hit) stamp))
        (cdr hit)
      (let ((identity (workspace-bookmark--root-identity root)))
        (puthash root (cons stamp identity) workspace-bookmark--identity-memo)
        identity))))
#+end_src

* Seam 1 — stamp on ~bookmark-make-record~

=:filter-return= advice on =bookmark-make-record=.  It receives the record
Emacs just built and returns it either stamped or byte-identical.  It must
never prompt, message, or alter the bookmark name the user chose, and a
failure to stamp must never prevent a bookmark from being created — hence
the =condition-case= returning the ORIGINAL record
(=register/boundary/bookmark-advice-seams= seam 1).

Every record =bookmark-make-record= builds passes through here — a
user's =C-x r m=, and also workspaces' own layout save, which calls it
for every live buffer.  Layout records are stamped exactly like a user's
bookmarks, deliberately: the caller is not detected or excluded.

** Which records are Tier 1

The gate.  It answers "is this value even a path?" before anything
treats it as one, and it answers WITHOUT running git, so a record it
rejects costs no subprocess at all.

- The =filename= must be a string and ABSOLUTE.  A relative value is not
  a location this record can be said to have: the real bookmark file
  here has four =tab-bookmark= records whose =filename= is the label
  ="3 buffers"=, and =expand-file-name= would happily turn that into a
  path under whatever =default-directory= happens to be.
- It must be LOCAL.  A TRAMP name is rejected before any filesystem
  call, for the reasons given under the git runner (a probe can signal,
  hang on a password prompt, or run git on the remote host).
- It must name something that EXISTS.
- A =buffer= or =window= property holding anything but a string marks
  a nested sub-record or a window tree — Tier 2 territory, where
  rewriting naively would corrupt shared or circular structure.

=filename= is often abbreviated (=bookmark-buffer-file-name= writes
=~/…=), so the returned location is expanded.

#+begin_src emacs-lisp
(defun workspace-bookmark--record-location (record)
  "Return the single local file or directory RECORD refers to, or nil.

RECORD is a bookmark record (NAME . ALIST).  Returns the expanded
`filename' only when it is an absolute, local (non-TRAMP) path naming an
existing file or directory, and RECORD carries no nested sub-record or
window tree (a `buffer' or `window' property whose value is not a
string).  Runs no subprocess."
  (let ((filename (bookmark-prop-get record 'filename)))
    (and (stringp filename)
         (file-name-absolute-p filename)
         (not (file-remote-p filename))
         (not (seq-some (lambda (prop)
                          (let ((value (bookmark-prop-get record prop)))
                            (and value (not (stringp value)))))
                        '(buffer window)))
         (let ((location (expand-file-name filename)))
           (and (not (file-remote-p location))
                (file-exists-p location)
                location)))))
#+end_src

** Where a location sits in its checkout

One =rev-parse= answers three questions at once: the checkout root
(=--show-toplevel=), the shared git directory whose =config= validates the
identity memo (=--git-common-dir=), and the path from the root to the
directory git ran in (=--show-prefix=).  git prints one per line, in
argument order.

Two spellings need care:

- At the repository root the prefix is the EMPTY string: git prints an
  empty line.  The runner removes only git's final line terminator, so
  that empty line is still there and three lines come back, the last
  one empty.
- =--git-common-dir= is asked with =--path-format=absolute=.  Without
  it git answers RELATIVE to the directory it ran in (=../../.git=),
  and it runs in the RESOLVED directory, not in the spelling the caller
  passed.  Through a symlink to a repository SUBDIRECTORY
  (=L/linksub -> R/sub=), expanding =../../.git= against the caller's
  =L/linksub/deep/= named =L/.git= instead of =R/.git=.  The memo then
  validated against a config file that does not exist, got a nil stamp
  and matched it forever, so a =git remote set-url= was never noticed
  and the OLD identity kept being stamped (measured).  The flag needs
  git 2.31; an older git exits non-zero and the position is nil.

Anything other than three lines (a checkout path containing a newline,
say) is refused rather than parsed.

For a DIRECTORY location the same call also asks a fourth question:
=HEAD:./=, the object id of DIR's own tree in HEAD.  That is the bounded
"does git know this directory?" check (see "The repository-relative path"
below): git resolves one tree entry per path component and prints one
line, however large the subtree.  If DIR is not in HEAD — or there is no
HEAD — =rev-parse= exits non-zero and the whole position is nil.  With
the fourth argument exactly FOUR lines come back.

#+begin_src emacs-lisp
(defun workspace-bookmark--checkout-position (dir &optional committed)
  "Return (ROOT GIT-COMMON-DIR PREFIX [TREE]) for directory DIR, or nil.

ROOT is the checkout root as a directory name, GIT-COMMON-DIR the
absolute shared git directory, and PREFIX DIR's path relative to ROOT as
git spells it (\"sub/dir/\", or \"\" at the root).  One git subprocess.
Nil when DIR is in no work tree.

With COMMITTED non-nil, also return TREE, the object id of DIR's tree in
HEAD, and return nil when DIR is not in HEAD or there is no HEAD.  The
cost is bounded by DIR's depth, not by the size of its subtree."
  (let* ((out (apply #'workspace-bookmark--git
                     dir "rev-parse"
                     "--path-format=absolute" "--show-toplevel" "--git-common-dir"
                     "--show-prefix"
                     (and committed '("HEAD:./"))))
         (lines (and out (split-string out "\n"))))
    (when (and (= (length lines) (if committed 4 3))
               (file-name-absolute-p (nth 0 lines))
               (file-name-absolute-p (nth 1 lines)))
      (append (list (file-name-as-directory (nth 0 lines))
                    (nth 1 lines)
                    (nth 2 lines))
              (and committed (list (nth 3 lines)))))))
#+end_src

** The repository-relative path

The relpath comes from GIT, never from string arithmetic on two paths.
Asking git settles, in one move, the questions arithmetic gets wrong:
symlinked temp directories (=/var= vs =/private/var=), case-insensitive
filesystems, and whether the location is in this repository at all.

*UNTRACKED MEANS UNSTAMPED.*  A location git does not report is returned
as nil and the record is left exactly as stock Emacs made it — no
fallback path computation.

*Files.*  =git ls-files --full-name= on the file's BASENAME, run in its
directory.  Three flags are load-bearing:

- =-z=: without it git C-quotes any path with non-ASCII, ="= or =\=
  (=café.txt= comes back as ="caf\303\251.txt"=, quotes included).
  =-z= prints raw bytes, NUL-terminated.
- =--literal-pathspecs=: pathspecs are GLOBS by default.  Measured: in a
  repository tracking both =glob[1].txt= and =glob1.txt=, asking about
  =glob[1].txt= returns BOTH.  Literal pathspecs return exactly one.
- =--=: a file named =-v= is a path, not an option.

During a merge conflict the index holds the path once per STAGE (base,
ours, theirs), and =ls-files= prints it once for each.  The reported names
are deduplicated before the "exactly one path" rule is applied, so a file
bookmarked mid-merge, which is when people bookmark, is still stamped.

The basename rather than the absolute name, because it is the question
git is built for: the runner has already put =default-directory= in the
file's directory.  (Measured: an absolute name through the =/tmp= →
=/private/tmp= symlink also works with git 2.49, but the basename leaves
nothing to depend on.)

*Directories.*  =ls-files= is the WRONG question for a directory — it
lists every tracked file beneath it, not the directory's own path.  The
git-native answer is =--show-prefix= from inside it, which
=--checkout-position= already has.

"Tracked", for a directory, means git knows it: it is a tree in HEAD.
That is asked in the SAME =rev-parse= (=HEAD:./=), so a directory record
costs ONE subprocess and its cost does not depend on how many files it
holds.  An earlier revision asked =ls-files -- .= for "at least one
tracked file under it", which prints the entire subtree just to test it
for emptiness — measured by the architect at 39 ms and 2.6 MB of output
for the root of a 50,000-file repository, and the root is the common
case (a Dired or =magit-status= buffer on a checkout root).  =ls-files=
has no way to stop at the first match, so the check moved to HEAD.

- *The root* is a tree in HEAD whenever there is a HEAD, so it is
  tracked by definition and pays nothing extra.  An unborn repository
  (no commit yet) has no HEAD, and its root is unstamped.
- *The cost of asking HEAD rather than the index*: a NEW directory whose
  files are staged but never committed is unstamped until its first
  commit.  That degrades (the record keeps its absolute =filename=); it
  never stamps a wrong path.  Files inside it are still stamped, because
  files are asked of the index.
- An empty or wholly untracked directory is not in HEAD, so it is
  unstamped, exactly as before.

*The repository root* has an empty prefix.  It is stored as =./=, not as
=""=:

- all three properties must be present AND meaningful, and an empty
  string is the value every emptiness check (=string-empty-p=,
  =seq-empty-p=, a sloppy =(and relpath …)= in another language) reads
  as "missing";
- every directory relpath then ends in =/=, so file and directory
  relpaths stay distinguishable by spelling alone;
- it re-anchors with the same call as every other relpath:
  =(expand-file-name "./" root)= is =root= itself, with its slash.

*Verification.*  The relpath git reports is accepted only if, anchored
back on the root, it names the SAME file as the location
(=workspace--same-file-p= compares the files, not the strings).
This turns any git answer we misparsed into "unstamped" instead of into a
persisted wrong path.

Output is decoded as UTF-8 regardless of locale: a GUI Emacs can start
with a non-UTF-8 =default-process-coding-system=, and the raw =-z= bytes
would then decode into a relpath naming nothing.

#+begin_src emacs-lisp
(defconst workspace-bookmark--root-relpath "./"
  "The relpath stamped for the repository root itself.
git spells the root's prefix as the empty string; see
`workspace-bookmark-relpath-property' for why it is stored as \"./\".")

(defun workspace-bookmark--relpath (location position)
  "Return LOCATION's repository-relative path, or nil when git does not track it.

POSITION is (ROOT GIT-COMMON-DIR PREFIX) from
`workspace-bookmark--checkout-position' for the directory holding
LOCATION (LOCATION itself, when it is a directory).  A file's relpath is
what `git ls-files --full-name' reports for it.  A directory's is its
PREFIX (`workspace-bookmark--root-relpath' at the root), and only when
POSITION carries the directory's HEAD tree (see
`workspace-bookmark--checkout-position').  Merge-conflict stages are
collapsed, so a conflicted file still has one relpath.  The result must
re-anchor on ROOT to the same file as LOCATION, or nil is returned."
  (let* ((root (nth 0 position))
         (relpath
          (if (file-directory-p location)
              (and (nth 3 position)
                   (let ((prefix (nth 2 position)))
                     (if (string-empty-p prefix)
                         workspace-bookmark--root-relpath
                       prefix)))
            (let ((reported (split-string
                             (or (workspace-bookmark--git
                                  location "--literal-pathspecs" "ls-files"
                                  "-z" "--full-name" "--"
                                  (file-name-nondirectory location))
                                 "")
                             "\0" t)))
              (setq reported (delete-dups reported))
              (and (= 1 (length reported)) (car reported))))))
    (and relpath
         (workspace--same-file-p (expand-file-name relpath root) location)
         relpath)))
#+end_src

** Coordinates

The sole producer of the identity/relpath pair
(=register/shape/portable-bookmark-coordinates=).  The order of the
questions is chosen for the hot path: place the location (one
subprocess), then ask whether git tracks it (one more for a file; for a
directory the placing call has already answered), and only then ask for
identity — which, through the memo, is usually free.  A file outside any
repository costs one subprocess; an untracked file costs two and never
reaches the remote lookup; a directory, at any depth and of any size,
costs one.

#+begin_src emacs-lisp
(defun workspace-bookmark--coordinates (location)
  "Return (IDENTITY . RELPATH) for the local file or directory LOCATION, or nil.

Nil when LOCATION is in no git work tree, when git does not track it,
or when its repository has no usable remote.  LOCATION must already
have passed `workspace-bookmark--record-location'."
  (let* ((coding-system-for-read 'utf-8-unix)
         (coding-system-for-write 'utf-8-unix)
         (directory-p (file-directory-p location))
         (dir (if directory-p
                  (file-name-as-directory location)
                (file-name-directory location)))
         (position (workspace-bookmark--checkout-position dir directory-p))
         (relpath (and position (workspace-bookmark--relpath location position)))
         (identity (and relpath
                        (workspace-bookmark--memoised-identity
                         (nth 0 position) (nth 1 position)))))
    (and identity (cons identity relpath))))
#+end_src

** Stamping

The stamped record is built FRESH rather than by =bookmark-prop-set= on
the record Emacs handed us.  That is what makes "all three or none" hold
by construction: every fallible step (the gate, git, the memo) finishes
before anything is built, and building is a single =cons= onto a copied
list, so there is no state in which one property has been written and
the next has not.  It also means the record we return on the error path
really is the ORIGINAL, unmutated — and a handler that returned a shared
or literal record is never written through.

Every original property is kept, in order, with =filename= untouched: it
is the absolute fallback every degraded outcome relies on and the reason
a stock Emacs can still read the file.  Any stale copies of the three
stamped properties are dropped before the fresh ones are appended, so a
record can never carry two of one.

#+begin_src emacs-lisp
(defun workspace-bookmark--with-coordinates (record coordinates)
  "Return a new record: RECORD's name and properties plus COORDINATES.

COORDINATES is (IDENTITY . RELPATH).  The three stamped properties are
appended together after RECORD's own properties, replacing any earlier
copies of them.  RECORD itself is not modified."
  (let ((stamped (list (cons workspace-bookmark-repo-property (car coordinates))
                       (cons workspace-bookmark-relpath-property (cdr coordinates))
                       (cons workspace-bookmark-format-property
                             workspace-bookmark-format-version))))
    (cons (car record)
          (append (seq-remove (lambda (prop)
                                (and (consp prop) (assq (car prop) stamped)))
                              (bookmark-get-bookmark-record record))
                  stamped))))
#+end_src

#+begin_src emacs-lisp
(defun workspace-bookmark--stamp-record (record)
  "Return RECORD with portable coordinates added, or RECORD unchanged.

Intended as `:filter-return' advice on `bookmark-make-record'.  A record
for a single tracked file or directory inside a repository with a remote
comes back as a NEW record carrying all three stamped properties
\(`workspace-bookmark-repo-property', `workspace-bookmark-relpath-property',
`workspace-bookmark-format-property'); any other record comes back
unchanged and `eq' to RECORD.

Never prompts, never messages, never touches the bookmark name.  Any
internal error is swallowed and the original RECORD returned: failing to
stamp must not prevent a bookmark from being created."
  (condition-case nil
      (let* ((location (workspace-bookmark--record-location record))
             (coordinates (and location
                               (workspace-bookmark--coordinates location))))
        (if coordinates
            (workspace-bookmark--with-coordinates record coordinates)
          record))
    (error record)))
#+end_src

* Seam 2 — substitute on ~bookmark-handle-bookmark~

Advice on =bookmark-handle-bookmark= (bookmark.el:1339), chosen because
=bookmark--jump-via= calls it and that is the shared path behind
=bookmark-jump=, =bookmark-jump-other-window=, =bookmark-jump-other-frame=
and completion front-ends such as =consult-bookmark=.  Advising
=bookmark-jump= instead would silently miss the others.

The seam parameter =BOOKMARK-NAME-OR-RECORD= may be a STRING NAME or a
record; resolution normalizes it with =bookmark-get-bookmark= before
reading coordinates.  The substituted copy keeps its own =handler=
property — this module NEVER installs a handler of its own, which is what
leaves dired / org / pdf-view restoration intact.

Combinator: =:around=, not =:filter-args=.  =:filter-args= can substitute
the record but cannot decline to call through, and
=register/invariant/no-silent-wrong-file-open= requires that a cancelled
resolution "open nothing AND signal nothing" — an explicit no-op that only
an =:around= can express.

** What the seam does with each outcome

The seam is a thin actor over the resolver's closed vocabulary
(=register/vocabulary/bookmark-resolution-outcome=).  It normalizes
its argument with =bookmark-get-bookmark=, decides on a PLAN — call
through with some argument, or decline with a message — and acts on
it.  The decision and the action are separate functions so that the
error barrier (below) can wrap the decision alone.

| outcome         | plan                                                                  |
|-----------------+-----------------------------------------------------------------------|
| =non-portable=  | call through with the ORIGINAL argument, untouched                    |
| =resolved=      | call through with a COPY whose =filename= is =:path=                  |
| =not-on-branch= | decline: report, open nothing                                         |
| =ambiguous=     | decline: report the =:candidates=, choose nothing                     |
| =no-clone=      | decline: report, open nothing                                         |
| =missing-repo=  | offer: hand the resolution to the bounded choice (see "Missing repo") |

Two decisions are made BEFORE the resolver is asked:

- A value =bookmark-get-bookmark= cannot turn into a record — an
  unknown name, nil — passes through: the host signals its own
  "Invalid bookmark" error exactly as stock Emacs does.
- No current workspace AND a stamped record is the off-workspace
  hand-off (section "Off-workspace"): the seam first ESTABLISHES a
  workspace — a prompt over the registry, then =workspace-restore= —
  and re-enters this decision with the chosen name, so the outcome is
  decided by the same table against that workspace.  With no workspace
  chosen the record is resolved with none and the fallback never calls
  through.  An unstamped record off-workspace is an ordinary
  =non-portable= pass-through and needs no arm of its own.

=missing-repo= hands the whole resolution plist to
=workspace-bookmark--offer-missing-repo= (section "Missing repo"),
which prompts and returns a plan of its own: a read-only =view= of the
canonical copy, a =call-through= once a worktree was added and the
record re-resolved, a =decline=, or =cancel=.  The seam never
dispatches on anything but the closed set: an outcome it has no arm
for signals, and the barrier turns that into stock behaviour rather
than into an open.  The plan vocabulary is closed the same way — the
advice has an arm per plan and signals for any other.

** The copy rule

=resolved= substitutes =:path= VERBATIM — confinement is lexical and
already decided inside the resolver (DD-16); the seam checks neither
links nor staleness — into a copy of the record made with =copy-tree=
on the =(NAME . ALIST)= cons.  =copy-tree=, not =copy-alist= and not
=copy-sequence=: the alist AND every property cons are fresh, so
=bookmark-prop-set= on the copy cannot reach =bookmark-alist=
(=register/invariant/stored-record-never-mutated-by-jump=).  With
=bookmark-save-flag= at 1 an in-place edit would be written to disk
on the first jump and destroy the absolute fallback that makes every
degraded outcome safe.  The copy keeps every other property — the
handler above all, which is what leaves dired, org and pdf-view
restoration intact.  =workspace-bookmark--substituted-record= is the
ONLY place a substituted record is built.

** Declining is a ~user-error~

A decline signals =user-error=; it does not return silently.  Measured
against bookmark.el 30.2: when =bookmark-handle-bookmark= returns nil
without changing the current buffer, =bookmark--jump-via= carries on
as if the jump had happened — it runs the display function on the
buffer the user was already in, drops a bookmark fringe mark there,
and runs =bookmark-after-jump-hook=.  A stray fringe mark in an
unrelated buffer is exactly the quiet wrongness this capability
exists to remove.  =user-error= aborts the whole jump at the command
loop with the report in the echo area, and it is not
=bookmark-error-no-filename=, the condition the host's relocate arm
catches (=register/invariant/no-silent-wrong-file-open=).  The
missing-repo prompt's =cancel= is an answer the user gave, not a
declined outcome; it ends the jump with =quit= for reasons given in
"Missing repo".

** The record handed to the host

On substitution the host receives a RECORD, never the bookmark's
name.  The host's relocate arm is gated on =(stringp
bookmark-name-or-record)=, so a substituted jump can never turn into
an offer to relocate the bookmark to the stored path.  Measured
against bookmark.el 30.2: for a record argument the host does not
merely skip the =y-or-n-p=, it swallows =bookmark-error-no-filename=
altogether and returns nil — and a nil return is exactly the silent
tail the previous section describes: the display function on the
buffer the user was already in, a fringe mark there, the after-jump
hook.  The seam therefore never lets a substituted record reach the
host unless its location exists.  The =resolved= arm PRE-FLIGHTS
=:path= with =file-exists-p= (a directory counts) immediately before
building the copy, and declines with =user-error= — the same shape as
every other non-opening case — when the location has vanished since
the resolver looked.  That is a seam-local decline reason, not a
seventh outcome: the seam re-verifies the one precondition it
substitutes on.  What remains is a race of microseconds between the
pre-flight and the handler's own =file-readable-p=, plus the separate
case of a file that exists but is unreadable; both end in the host's
silent nil.  That is a bounded residual, stated here, and one this
configuration already carries for every record argument (see
=bufferlo= below).

Stock Emacs ends a jump by name by setting =bookmark-current-bookmark=
to that name, the default that the next =C-x r b= and =C-x r m=
offer.  The host does that only for a string argument, so after a
substituted jump the seam does it itself — but only when the jump
actually landed somewhere: the current buffer changed, or now visits
the substituted location.  The host's silent nil can therefore never
stamp the ORIGINATING buffer with a bookmark it did not jump to.

In THIS configuration the string case is rarer than bookmark.el
suggests: =bufferlo-mode= (=buffer-membership.org=) advises
=bookmark--jump-via= and calls it with the RECORD
(=bufferlo--bookmark--jump-via-advice=, bufferlo 1.2), so every jump
that goes through =bookmark-jump= already reaches the host with a
cons.  The host's string-gated tail — the relocate offer and the
=bookmark-current-bookmark= default — is therefore skipped for every
jump here, substituted or not.  Nothing above depends on which form
arrives: normalization accepts both, and the seam's bookkeeping is
what a stock Emacs, or a caller reaching =bookmark-handle-bookmark=
with a name, observes.

** The barrier

The seam's =condition-case= is the SECOND barrier: the resolver's own
already maps discovery errors to =no-clone= and reads to
=non-portable=.  This one covers the seam's own code — normalization,
the copy, the message — and falls through to ORIG-FN with the
ORIGINAL argument, so a failure affecting one bookmark cannot affect
another or the bookmark file.  It wraps the DECISION only: the call
to ORIG-FN sits outside it, so the handler's own errors propagate
exactly as in stock Emacs and the host is never called twice.
=quit= is not an =error= and propagates through both barriers: C-g is
not a failure.

The residual is stated rather than hidden: a programming error in the
seam degrades to today's behaviour, which for a stamped record is the
stored absolute path.  It is reached only by a bug in this section,
never by an outcome.

#+begin_src emacs-lisp
(defun workspace-bookmark--substituted-record (record path)
  "Return a copy of bookmark RECORD whose `filename' is PATH.

The copy shares no cons cell with RECORD: `copy-tree' copies the
\(NAME . ALIST) cons, the alist and every property cons, so setting
`filename' on the copy cannot reach `bookmark-alist'.  Every other
property — the handler above all — is kept.  This is the ONLY place a
substituted record is built.  Signals when PATH is not a string."
  (unless (stringp path)
    (error "Not a path to substitute into %S: %S"
           (bookmark-name-from-full-record record) path))
  (let ((copy (copy-tree record)))
    (bookmark-prop-set copy 'filename path)
    copy))
#+end_src

#+begin_src emacs-lisp
(defun workspace-bookmark--plan-to-open (record resolution kind)
  "Return the plan that opens RESOLUTION's :path for RECORD, or a decline.

KIND is `call-through' — the seam's own `resolved' jump — or `view',
the canonical read-only view chosen at the missing-repo prompt.  The
:path is pre-flighted with `file-exists-p' immediately before the copy
is built (a directory counts); one that has vanished since the resolver
looked declines with `workspace-bookmark--vanished-message'.  The copy
comes from `workspace-bookmark--substituted-record', the only place one
is built.  Returns (call-through . COPY), (view COPY . CHECKOUT) or
\(decline . MESSAGE); signals for any other KIND, and for a `view'
whose RESOLUTION names no :checkout — a view that cannot say which
canonical checkout it shows is never opened unmarked."
  (let ((path (plist-get resolution :path))
        (checkout (plist-get resolution :checkout)))
    (cond
     ((not (and (stringp path) (file-exists-p path)))
      (cons 'decline (workspace-bookmark--vanished-message record resolution)))
     ((eq kind 'call-through)
      (cons 'call-through (workspace-bookmark--substituted-record record path)))
     ((eq kind 'view)
      (unless (stringp checkout)
        (error "No canonical checkout to view %S from: %S"
               (bookmark-name-from-full-record record) checkout))
      (cons 'view (cons (workspace-bookmark--substituted-record record path)
                        checkout)))
     (t (error "Not a jump plan kind: %S" kind)))))

(defun workspace-bookmark--landed-p (origin record)
  "Return non-nil when the jump of the substituted RECORD landed somewhere.
ORIGIN is the buffer that was current before the host was called.  The
jump landed when the current buffer is no longer ORIGIN, or now visits
RECORD's `filename' (compared by file identity)."
  (or (not (eq (current-buffer) origin))
      (let ((file (buffer-file-name)))
        (and file
             (workspace--same-file-p
              file (bookmark-get-filename record))))))

#+begin_src emacs-lisp
(defun workspace-bookmark--jump-plan (bookmark-name-or-record &optional workspace)
  "Decide what the jump seam does with BOOKMARK-NAME-OR-RECORD.

Returns (call-through . ARG), meaning hand ARG to the host — ARG is
the original argument, or a substituted copy for `resolved' —
\(decline . MESSAGE), meaning open nothing and report MESSAGE, or,
from the missing-repo prompt, (view COPY . CHECKOUT) — hand COPY to
the host, then mark the buffer as a read-only view of CHECKOUT — or
\(cancel), meaning open nothing and say nothing.

WORKSPACE is the name of the workspace to resolve against; it
defaults to the current one.  Decided before the resolver is asked: a
value that is not a bookmark record calls through (the host signals
for it); no workspace on a STAMPED record is the off-workspace
hand-off, `workspace-bookmark--off-workspace-plan', which establishes
a workspace and re-enters here with its name.  A `resolved' :path is
pre-flighted with `file-exists-p' right before the copy is built; one
that has vanished declines.  `missing-repo' is handed to
`workspace-bookmark--offer-missing-repo'.  May signal; the seam's
barrier catches."
  (let ((record (bookmark-get-bookmark bookmark-name-or-record 'noerror))
        (workspace (or workspace (workspace-bookmark--current-workspace))))
    (cond
     ((not (consp record))
      (cons 'call-through bookmark-name-or-record))
     ((and (null workspace)
           (workspace-bookmark--stamped-coordinates record))
      (workspace-bookmark--off-workspace-plan record bookmark-name-or-record))
     (t
      (let ((resolution (workspace-bookmark--resolve record workspace)))
        (pcase (plist-get resolution :outcome)
          ('non-portable
           (cons 'call-through bookmark-name-or-record))
          ('resolved
           (workspace-bookmark--plan-to-open record resolution 'call-through))
          ('missing-repo
           (workspace-bookmark--offer-missing-repo record resolution))
          ((or 'not-on-branch 'ambiguous 'no-clone)
           (cons 'decline
                 (workspace-bookmark--decline-message record resolution)))
          (outcome
           (error "Not a bookmark-resolution outcome: %S" outcome))))))))
#+end_src

#+begin_src emacs-lisp
(defun workspace-bookmark--handle-bookmark-advice (orig-fn bookmark-name-or-record &rest args)
  "Resolve BOOKMARK-NAME-OR-RECORD against the current workspace, then jump.

Intended as `:around' advice on `bookmark-handle-bookmark'; ORIG-FN is
the advised function and ARGS its remaining arguments.  Acts on the
plan `workspace-bookmark--jump-plan' returns: calls ORIG-FN with the
original argument (`non-portable' only: a record with no usable
stamp), with a substituted copy (`resolved', or the canonical
read-only view chosen at the missing-repo prompt), or not at all — a
decline signals a `user-error' naming the bookmark and opens nothing;
a cancel at that prompt signals `quit'.  A stamped record with no
current workspace goes through the off-workspace plan
\(`workspace-bookmark--off-workspace-plan'), which establishes a
workspace and resolves against it, and never calls through with the
original argument.  Any error in this seam's own
decision falls through to ORIG-FN with the ORIGINAL argument, so a
failure affecting one bookmark cannot affect another or the bookmark
file; `quit' propagates.  After a substituted jump that landed in a
buffer (the current buffer changed, or visits the substituted
location): a view is marked read-only there by
`workspace-bookmark--mark-canonical-view', and a jump by name sets
`bookmark-current-bookmark' there as the host sets it for a plain one.
Before either, the host call is offered to
`workspace-bookmark--note-jump-target', which records where the jump
landed when it is the outer jump of a restore-then-jump.  The
originating buffer is never touched."
  (let ((plan (condition-case nil
                  (workspace-bookmark--jump-plan bookmark-name-or-record)
                (error (cons 'call-through bookmark-name-or-record))))
        (origin (current-buffer)))
    (pcase plan
      (`(decline . ,message)
       (user-error "%s" message))
      (`(cancel)
       (signal 'quit nil))
      ((or `(call-through . ,arg) `(view ,arg . ,_))
       (let ((checkout (and (eq (car plan) 'view) (cddr plan))))
         (prog1 (apply orig-fn arg args)
           (workspace-bookmark--note-jump-target origin arg)
           (when (and (not (eq arg bookmark-name-or-record))
                      (workspace-bookmark--landed-p origin arg))
             (when (eq (car plan) 'view)
               (workspace-bookmark--mark-canonical-view arg checkout))
             (when (stringp bookmark-name-or-record)
               (setq bookmark-current-bookmark bookmark-name-or-record))))))
      (_ (error "Not a jump plan: %S" plan)))))

* Missing repo

=missing-repo= is the one outcome where a useful action exists but the
user has to choose it.  The workspace holds no checkout of the
repository; exactly one canonical checkout is in view; the canonical
checkout usually HAS the file.  Opening it silently would be the
tempting thing and the wrong one: an edit there is an edit of =main=
without anyone noticing, which is what worktrees exist to prevent
(=register/invariant/no-silent-wrong-file-open= prohibition 2: the
canonical checkout is opened ONLY on an explicit choice, never as a
fallback).

So the seam hands the whole resolution plist to a bounded choice.
=read-multiple-choice=, not =completing-read= over action strings: the
option set is closed by construction, each option carries its own help
text, and nothing free-form can be typed.  The set is the nested
"missing-repo action" vocabulary of
=register/vocabulary/bookmark-resolution-outcome=: =add-worktree=,
=view-canonical-read-only=, =cancel=.  Adding a fourth answer is a
deliberate two-place change — the table below and the dispatch in
=workspace-bookmark--offer-missing-repo=, which has no permissive arm.

The chooser is a function of =(record resolution)= so that the
off-workspace flow (task =off-workspace-restore=) can call the same
prompt for its empty-registry fallback; it reads the current workspace
itself, and with no current workspace =add-worktree= is simply not
offered.

** What is offered, and why not

Every option is offered unless a stated reason withholds it, and the
prompt says so, so the user knows what is missing where:

| option                      | withheld when                                                             |
|-----------------------------+---------------------------------------------------------------------------|
| =add-worktree=              | no current workspace; the add-worktree command cannot run; no home        |
| =view-canonical-read-only=  | =:path= is nil — the relpath is absent under the canonical checkout      |
| =cancel=                    | never                                                                     |

=jf/workspace--add-worktree= is git-worktrees' command and git-worktrees
is magit's; this module requires neither (DD-6).  The symbol is quoted
and =fboundp=-guarded at call time, the same discipline git-worktrees
uses towards this module (DD-10).  =fboundp= alone is not enough,
though: git-worktrees.el is loaded whether or not magit is, so the
command is always defined, and only its REGISTRATION as the
=git-worktree= integration's menu command waits for magit.  Without
magit, calling it fails on its first magit call and nothing opens.  So
the command counts as runnable only when it is also registered as some
integration's menu command in core's =workspace--integrations= — the
same condition under which the workspace menu offers it as "w".  With
magit absent the option is therefore absent, with its reason, rather
than an error.  The question is asked of core's registry, so this
module still names no magit symbol and no second git-worktrees symbol.

A nil =:path= is a real case, not a defensive one: the resolver anchors
the relpath under the canonical checkout and answers =missing-repo=
with =:path= nil when nothing of the relpath's kind is there — a file
that exists only on the workspace branch where it was bookmarked (ask
16).  There is nothing to view, and visiting a path that does not exist
would hand the user a fresh empty buffer, the quiet trap
=not-on-branch= already closes.  With both options withheld the prompt
is cancel-only and still states both reasons.

  "Return non-nil when git-worktrees' add-worktree command can run.
That is when `jf/workspace--add-worktree' is defined AND registered as
the menu command of an integration in core's `workspace--integrations'
\(read only when bound).  git-worktrees defines the command whether or

  (and (fboundp 'jf/workspace--add-worktree)

(defun workspace-bookmark--missing-repo-withheld (resolution workspace)
  "Return the `missing-repo' actions not offered for RESOLUTION, with reasons.

An alist of (ACTION . REASON), REASON a phrase for the prompt.
`add-worktree' needs a current WORKSPACE (a name) with a home and the
git-worktrees command `jf/workspace--add-worktree' runnable
\(`workspace-bookmark--add-worktree-runnable-p');
`view-canonical-read-only' needs a non-nil :path, the relpath present
under the canonical checkout.  `cancel' is always offered."
  (let ((withheld nil))
    (cond
     ((null workspace)
      (push (cons 'add-worktree "no workspace is current to add a worktree to")
            withheld))
     ((not (workspace-bookmark--add-worktree-runnable-p))
      (push (cons 'add-worktree "the git worktree integration is not loaded")
            withheld))
     ((not (workspace-bookmark--workspace-home workspace))
      (push (cons 'add-worktree
                  (format "workspace %S has no home to add a worktree to" workspace))
            withheld)))
    (unless (plist-get resolution :path)
      (push (cons 'view-canonical-read-only
                  (format "%s is absent there" (plist-get resolution :relpath)))
            withheld))
    (nreverse withheld)))

(defun workspace-bookmark--missing-repo-choices (withheld)
  "Return the `read-multiple-choice' entries for the actions not in WITHHELD."
  (seq-keep (lambda (entry)
              (unless (assq (car entry) withheld) (cdr entry)))
            workspace-bookmark--missing-repo-actions))

(defun workspace-bookmark--missing-repo-action (answer)
  "Return the action symbol for ANSWER, the entry `read-multiple-choice' returned."
  (or (car (seq-find (lambda (entry) (eq (nth 1 entry) (car answer)))
                     workspace-bookmark--missing-repo-actions))
      (error "Not a missing-repo answer: %S" answer)))

** The prompt

The prompt names the bookmark, the current workspace, the repository
identity and the canonical checkout, then every withheld option with
its reason.  =read-multiple-choice= appends the offered keys itself.

  "Return the prompt for RECORD, whose RESOLUTION is `missing-repo', in WORKSPACE.
Names the bookmark, WORKSPACE (a name, or nil for none), the repository
identity and the canonical checkout, then states each entry of WITHHELD

** The choice

The chooser returns a jump PLAN for the seam to act on — it opens
nothing itself, so the host is still called at most once, by the
advice, outside the barrier.  Three properties are deliberate:

- *Cancel is a =quit=, not a return and not an error.*  The register
  asks that cancel "open nothing and signal nothing".  Inside
  =bookmark--jump-via= a silent return is not nothing: the host then
  runs the display function on the buffer the user was already in
  (=bookmark-jump-other-window= would show it in another window), drops
  a bookmark fringe mark on the current line there, and runs
  =bookmark-after-jump-hook= — the same tail that made declining a
  =user-error= (see "Declining is a ~user-error~").  A =user-error=
  would be wrong the other way: it is caught by every caller's
  =(error ...)= barrier, and =layouts.el='s reincarnation chain answers
  a caught error by opening the leaf's STORED filename — prohibition 4
  by way of a cancel.  =quit= is the one signal that means "the user
  chose not to": no error, no debugger, not caught by =(error ...)=,
  and already the answer the seam lets through both barriers for C-g.
  C-g at the prompt and the =cancel= option therefore do the same
  thing, which is what a user expects of both.
- *An error inside the choice declines.*  The seam's barrier answers an
  error in its decision by calling through with the ORIGINAL argument,
  which for a stamped record is the stored absolute path — tolerable
  for a programming error in the seam, not for one in the prompt for
  the very outcome that exists to keep that path shut.  The chooser
  has its own barrier: any error in the choice becomes a decline
  naming the error.  =quit= passes.
- *The stored record is never touched.*  Every open goes through a
  copy built by =workspace-bookmark--plan-to-open=, the seam's own
  pre-flighted path to =workspace-bookmark--substituted-record=; this
  section builds no record of its own.
- *No prompt where nobody can answer, and none where nobody may ask.*
  A non-interactive Emacs (=noninteractive=: =--batch=, the test
  harness) has no one at the keyboard; =read-multiple-choice= would
  read stdin and block or fail.  A caller that has bound
  =inhibit-interaction= has said no prompt may be put.  And while a
  layout leaf is being restored — core's =layouts.el= binds
  =workspace--restoring-layout-leaf= around each leaf's jump — a
  question per leaf is exactly what a restore must never become.  In
  each case the chooser declines with the seam's own =missing-repo=
  report instead of prompting.  For the reincarnation chain that
  decline is the answer it wants: it treats a =user-error= from a leaf
  as "skip this leaf's filename", shows the reason in the leaf's
  window and reports every declined leaf in ONE message after the walk
  (see layouts.org, "A decline is not a failure").  Core suppresses
  nothing itself; the decision not to ask is this module's.  The
  =inhibit-interaction= check has to happen HERE, before
  =read-multiple-choice= is called, and not be left to the primitive:
  rmc.el wraps its =read-event= in =(condition-case nil ... (error
  nil))=, which swallows the =inhibited-interaction= signal and loops
  on the prompt forever (measured, Emacs 30.2).

#+begin_src emacs-lisp
(defvar workspace--restoring-layout-leaf)

(defun workspace-bookmark--can-prompt-p ()
  "Return non-nil when a prompt may be put and someone can answer it.
Nil in a non-interactive Emacs; nil while `inhibit-interaction' is
bound, because `read-multiple-choice' does not honour that variable
itself (it swallows the `inhibited-interaction' signal and loops); and
nil while core restores a layout leaf (`workspace--restoring-layout-leaf',
read only when bound), where a prompt would be one question per leaf."
  (and (not noninteractive)
       (not inhibit-interaction)
       (not (and (boundp 'workspace--restoring-layout-leaf)
                 workspace--restoring-layout-leaf))))

(defun workspace-bookmark--offer-missing-repo (record resolution)
  "Offer the bounded choice for RECORD, whose RESOLUTION is `missing-repo'.

Prompts with `read-multiple-choice' over the actions
`workspace-bookmark--missing-repo-withheld' leaves offered — add a
worktree of the canonical checkout to the current workspace, view the
canonical copy read-only, or cancel — and returns the seam's plan for
the answer: (view COPY . CHECKOUT), (call-through . COPY) once a
worktree was added and RECORD re-resolved, (decline . MESSAGE), or
\(cancel).  Opens nothing itself.  Signals `quit' when the prompt is
quit; any other error inside the choice declines, so the seam's
barrier can never answer it with the stored path.  When no one can
answer (`workspace-bookmark--can-prompt-p' is nil) declines with the
seam's `missing-repo' report instead of prompting."
  (condition-case err
      (if (not (workspace-bookmark--can-prompt-p))
          (cons 'decline (workspace-bookmark--decline-message record resolution))
        (let* ((workspace (workspace-bookmark--current-workspace))
               (withheld (workspace-bookmark--missing-repo-withheld
                          resolution workspace))
               (answer (read-multiple-choice
                        (workspace-bookmark--missing-repo-prompt
                         record resolution workspace withheld)
                        (workspace-bookmark--missing-repo-choices withheld))))
          (pcase (workspace-bookmark--missing-repo-action answer)
            ('cancel (list 'cancel))
            ('view-canonical-read-only
             (workspace-bookmark--plan-to-open record resolution 'view))
            ('add-worktree
             (workspace-bookmark--add-worktree-and-replan
              record resolution workspace))
            (action (error "Not a missing-repo action: %S" action)))))
    (error
     (cons 'decline
           (format "Bookmark %S: the missing-repo choice failed (%s); nothing opened"
                   (bookmark-name-from-full-record record)
                   (error-message-string err))))))

** View read-only

The copy is opened by the host through the record's own handler, like
any substituted jump; the seam then calls
=workspace-bookmark--mark-canonical-view= in the buffer it landed in —
and only if it landed (the host's silent nil must never make the
ORIGINATING buffer read-only).  Three things make the view
unmistakable, and they are layered because each one alone fades:

- =view-mode=: read-only plus the standard view keymap.  Not in Dired,
  which is read-only already and whose keymap view-mode would shadow.
- A buffer-local suffix on =mode-line-buffer-identification= naming the
  canonical checkout.  It is set once and it is NOT tied to view-mode:
  a message disappears, and =view-mode= ends with =C-x C-q=, but the
  marker stays for the life of the buffer, so the buffer still says
  what it is after the user has made it writable.
- One =message= naming the path and the branch the canonical checkout
  has checked out (a stale stamp may show a pre-relocation path; ask 5
  accepts that and nothing is said about it here).

A stock =C-x C-q= (=read-only-mode=) leaves view-mode and makes the
buffer writable.  That is the deliberate way out and the only one;
nothing here binds or advises it.

A =revert-buffer= that re-runs the major mode (=M-x revert-buffer=,
=C-x x g=; not =auto-revert-mode=, which preserves modes) kills every
ordinary buffer-local variable, which would take the marker and
view-mode with it and leave a buffer that is read-only for no visible
reason.  So the viewed checkout is recorded in a permanent-local
variable, and a permanent buffer-local entry on
=revert-buffer-restore-functions= (Emacs 30) puts the marker back.
That hook, not =after-revert-hook=, because it sees the buffer before
the revert and acts after the stock read-only restore: it brings
view-mode back only when view-mode was on before the revert, so after
=C-x C-q= the user has left the view and a revert does not put them
back in it.

#+begin_src emacs-lisp
(defvar-local workspace-bookmark--canonical-view nil
  "The canonical checkout this buffer views from the missing-repo prompt, or nil.
Set once by `workspace-bookmark--mark-canonical-view'; survives `C-x C-q'
and, being permanent-local, a `revert-buffer' that re-runs the major mode.")
(put 'workspace-bookmark--canonical-view 'permanent-local t)

(defun workspace-bookmark--canonical-branch (checkout)
  "Return the branch CHECKOUT has checked out, or a phrase for a detached HEAD."
  (or (workspace-bookmark--git checkout "symbolic-ref" "--short" "--quiet" "HEAD")
      "detached HEAD"))

(defun workspace-bookmark--canonical-marker-p (element)
  "Return non-nil when mode-line ELEMENT is the canonical-view marker."
  (and (stringp element)
       (> (length element) 0)
       (get-text-property 0 'workspace-bookmark-canonical-view element)))

(defun workspace-bookmark--show-canonical-marker (checkout)
  "Append a marker naming CHECKOUT to the buffer's mode-line identification.
Buffer-local, and never twice: a marker already present is left alone."
  (unless (and (proper-list-p mode-line-buffer-identification)
               (seq-some #'workspace-bookmark--canonical-marker-p

    (setq mode-line-buffer-identification
          (list "" mode-line-buffer-identification
                (propertize
                 (format " [canonical %s]"

(defun workspace-bookmark--restore-canonical-view ()
  "Return a function that puts the canonical view back after a revert.
Buffer-local on `revert-buffer-restore-functions', and permanent like
`workspace-bookmark--canonical-view', so it outlives the revert's
`kill-all-local-variables'.  Called before the revert; the function it
returns runs after it, once the stock read-only state is restored, and
re-adds the marker and — only if it was on before the revert —
`view-mode', so a revert never undoes a deliberate `C-x C-q'."
  (let ((buffer (current-buffer))
        (viewing view-mode))
    (lambda ()
      (when (buffer-live-p buffer)
        (with-current-buffer buffer
          (when workspace-bookmark--canonical-view
            (when (and viewing (not view-mode))
              (view-mode 1))

             workspace-bookmark--canonical-view)))))))

(defun workspace-bookmark--mark-canonical-view (record checkout)
  "Make the current buffer an unmistakable read-only view of CHECKOUT's copy.

The current buffer is where the host landed RECORD's substituted copy.
Turns on `view-mode' (not in Dired, which is read-only already), appends
a marker naming CHECKOUT to the buffer's `mode-line-buffer-identification'
— once, buffer-locally, so it outlives the echo-area message, a later
`C-x C-q' and a mode-resetting `revert-buffer' — and reports the path
and CHECKOUT's branch in one message."
  (unless (derived-mode-p 'dired-mode)
    (view-mode 1))
  (unless workspace-bookmark--canonical-view
    (setq workspace-bookmark--canonical-view checkout))
  (workspace-bookmark--show-canonical-marker workspace-bookmark--canonical-view)
  (add-hook 'revert-buffer-restore-functions
            #'workspace-bookmark--restore-canonical-view nil t)
  (message "Bookmark %S: viewing %s read-only in the canonical checkout %s (branch %s)"
           (bookmark-name-from-full-record record)
           (abbreviate-file-name (or (buffer-file-name) default-directory))
           (abbreviate-file-name (directory-file-name checkout))
           (workspace-bookmark--canonical-branch checkout)))

** Add worktree here

Worktree creation is magit's job and lives in git-worktrees'
=jf/workspace--add-worktree=, the =:menu= command of the =git-worktree=
integration.  It takes the anchor payload
(=register/shape/workspace-integration-anchor-payload=), so the payload
is built by the shape's ONE constructor, core's
=workspace--integration-payload= (=:name=, =:home=, =:sessions-dir=,
=:context=, here =bookmark-jump=), with =:source-repo= appended: the
canonical checkout the resolver chose.  The constructor is reached the
way this module reaches the rest of core — declared, =fboundp=-guarded
at call time, never required — and only when it is unbound is the same
plist spelled out here, so the two cannot drift while core is loaded.
The source is decided, not discovered: discovery already ran once and
=:checkout= is its answer; running it again would be a second prompt
over the same candidates.  The payload is the channel the shape entry
leaves open ("flat and extensible: handlers read only the keys they
need"), and git-worktrees' command honours =:source-repo= in place of
its source prompt: given one, it asks for no source and runs no
discovery.

On =ok= the resolver runs ONCE more against the workspace, and a
=resolved= answer continues through the seam's normal path, pre-flight
included.  The add changed the repository, so that second resolve runs
in a FRESH discovery memo (=workspace-bookmark--discovery-memo= bound to
nil), never in one a caller may have opened around this function: an
enclosing memo holds the repository's worktree listing from before the
add (see "One discovery call asks git each question once").  Any other answer declines with its report — a worktree
added off =main= lacks a file that exists only on the bookmarked
branch, and that is =not-on-branch=, reported like any other — and
never prompts again.  =(failed . REASON)= and =skipped= decline naming
the reason; the outcome vocabulary is closed
(=register/vocabulary/workspace-integration-outcome=), and anything
else is an error the chooser's barrier turns into a decline.

#+begin_src emacs-lisp
(declare-function workspace--integration-payload "integrations" (name home context))
(defvar workspace-bookmark--discovery-memo)

(defun workspace-bookmark--add-worktree-payload (workspace checkout)
  "Return the anchor payload for adding a worktree of CHECKOUT to WORKSPACE.
What `workspace--integration-payload' builds for WORKSPACE, its home
and the context `bookmark-jump', plus :source-repo, the canonical
checkout the resolver chose, so the git-worktrees command need not ask
for one.  When that constructor is not loaded, the same keys but
:sessions-dir are listed here."
  (let ((home (workspace-bookmark--workspace-home workspace)))
    (append (if (fboundp 'workspace--integration-payload)
                (workspace--integration-payload workspace home 'bookmark-jump)
              (list :name workspace :home home :context 'bookmark-jump))
            (list :source-repo checkout))))

(defun workspace-bookmark--after-add-message (record resolution)
  "Return the report for RECORD when RESOLUTION opens nothing after a worktree add."
  (let ((outcome (plist-get resolution :outcome)))
    (if (memq outcome '(not-on-branch ambiguous missing-repo no-clone))
        (format "%s (after adding a worktree)"
                (workspace-bookmark--decline-message record resolution))
      (format "Bookmark %S: resolves %s after adding a worktree; nothing opened"
              (bookmark-name-from-full-record record) outcome))))

(defun workspace-bookmark--add-worktree-and-replan (record resolution workspace)
  "Add a worktree of RESOLUTION's :checkout to WORKSPACE, then replan RECORD.

Calls git-worktrees' `jf/workspace--add-worktree', which must be
`fboundp', with `workspace-bookmark--add-worktree-payload'.  On `ok'
the resolver runs once more against WORKSPACE, outside any enclosing
discovery memo (the add changed the repository): a `resolved' answer

prompt.  (failed . REASON) and `skipped' decline naming the reason.

  (unless (fboundp 'jf/workspace--add-worktree)

      ('skipped

             (format "Bookmark %S: the git worktree integration skipped the add; nothing opened"

      (_ (error "Not a workspace-integration outcome: %S" result)))))

* Off-workspace

A FILE bookmark resolves within a workspace (DD-1/DD-2).  When the
current tab is not a workspace tab the seam has no workspace to resolve
against, so it first ESTABLISHES one: it asks which registered
workspace should serve the jump, restores it through the package's own
=workspace-restore=, and only then resolves — by re-entering
=workspace-bookmark--jump-plan= with the chosen name, so from that
point on the outcome is decided by the seam's normal table
(=register/vocabulary/bookmark-resolution-outcome=; after a restore
=ambiguous= is as possible as anywhere else, and is reported with its
candidates, nothing opened).  This section chooses and restores a
workspace; it decides nothing about the location.

Entering the workspace, rather than opening the file in the
non-workspace tab, is what keeps the buffer coherent: membership is
per tab (bufferlo), so a file opened outside the workspace would belong
to no workspace at all — a half-state where the buffer is nowhere.

** Restore, not switch

Candidates come from the REGISTRY (=workspace--registered-names=), not
from live tabs.  The moment bookmarks are most useful is right after a
restart, when the target workspace has no tab yet; a picker over live
tabs would be empty exactly then.  =workspace-restore= is already
written for lazy materialization — it creates or selects the tab,
applies =:working-state= else =:saved-state=, falls back to the home
builder when no layout was saved, and refuses a broken workspace — so
this section calls it and reimplements none of it (design D8).
=workspace-switch= is not used here.

Broken workspaces — =workspace--broken-p= on the registry plist, the
flag persistence sets when a =:home= is missing at load — are not
offered: the package refuses to switch to or restore them with a
=user-error= naming =workspace-re-anchor= / =workspace-purge=, and an
offer the package would refuse is noise.

** Holders first

A workspace that already holds a checkout of the bookmark's repository
resolves at once; every other workspace leads straight into
=missing-repo= and its prompt.  So the candidates are ORDERED — holders
first, in registry order, then the rest in registry order — and
ANNOTATED, so the order is legible rather than accidental: the
completion table pins =display-sort-function= (and the cycle sort) to
=identity=, because a front-end's alphabetical sort would undo the
grouping, and carries an =annotation-function= that says "holds a
checkout of IDENTITY" or "no checkout".  The first holder, when there
is one, is the default.  Holding is asked with the plural
=workspace-bookmark--workspace-checkouts=, once per registered
workspace and never a second time; the resolver's own call for the
chosen workspace is the resolver's business.

** One prompt; C-g ends the jump

=completing-read= with =require-match=, the first holder as the
default.  =C-g= at this prompt is NOT caught: =quit= ends the jump
there — nothing restored, nothing opened, nothing else asked.  The user
has abandoned the jump, and answering a C-g with the fallback's own
question would be a second prompt for one gesture (DD-4: one prompt,
one message).  An EMPTY answer is different: it is an answer, "no
workspace", and the fallback below acts on it.  An empty registry asks
nothing and goes straight to the fallback.

*No prompt where no one can answer.*  The picker sits behind the same
guard as the missing-repo chooser, =workspace-bookmark--can-prompt-p=:
in a non-interactive Emacs, under =inhibit-interaction=, or while core
restores a layout leaf, the jump declines with a message saying no
workspace could be chosen, instead of calling =completing-read= (which
in batch would read stdin, and under =inhibit-interaction= would only
be declined by this section's barrier).

** The fallback never opens the stored path

With no workspace chosen — empty registry, or an empty answer — the
seam still holds a stamped record with a stored absolute path, and the
one thing it must not do is open that path as though it were a
workspace copy (=register/invariant/no-silent-wrong-file-open=,
prohibition 4; the fallback is "read-only canonical, or cancel").  The
record is resolved with NO workspace — rows 4–6 of the resolver's
table — and the fallback has no arm that calls through:

- =missing-repo=, one canonical checkout in view, goes to the SAME
  bounded chooser the in-workspace outcome uses,
  =workspace-bookmark--offer-missing-repo= (section "Missing repo").
  It reads the current workspace itself, finds none, and withholds
  =add-worktree=; what remains is =view-canonical-read-only= — offered
  only when =:path= is non-nil (ask 16) — and =cancel=.  One chooser
  and one action vocabulary, not a second prompt with a second set.
- =ambiguous= and =no-clone= decline with their usual report.
- Nothing else can be reached by a stamped record; anything else
  declines as well.

** Remembered like any visit

A jump-triggered restore is navigation INTO a workspace, and it is
remembered exactly as any =find-file= inside that workspace is (user
decision, 2026-09-27): this module adds nothing to
=workspace-anti-save-predicates=, so the next ordinary autosave — the
tab switch that leaves the workspace, the idle tick, the kill-emacs
flush — records the arrangement on screen, the jumped-to file in the
selected window of the restored layout, as the workspace's
=:working-state=.  =:saved-state= is untouched, as by every autosave;
an explicit =workspace-save= captures what is on screen, as always.

*The layout is painted, THEN the file is shown* (design D9's display
half).  =layouts.el= paints a restored layout with =window-state-put=
DEFERRED through =run-at-time= (to avoid racing =bookmark--jump-via='s
own display call).  The host opens the bookmark's file synchronously,
in the selected window of the tab the restore selected — so bufferlo
membership and point are settled — and the deferred paint then covers
it.  The finish step, =workspace-bookmark--finish-restore=, re-shows
that buffer in the selected window of the painted layout: same window,
no split.

*Only the outer jump names that buffer.*  The restore itself
reincarnates the layout's leaves through =bookmark-jump=, that is,
through this very seam, and none of those is the jump.  So the target
is recorded only once =workspace-restore= has RETURNED:
=workspace-bookmark--restore-for-jump= clears any target and raises
=workspace-bookmark--awaiting-jump-target= after the call, and the
first host call after that — the outer jump's own — records where it
landed and lowers the flag.  "Landed" is
=workspace-bookmark--landed-p=: the current buffer changed, OR it now
visits the substituted location, which is the case when the file is
the very buffer the new tab inherited from the tab the jump started
in.  A jump that declines or is cancelled after the restore never
reaches the host and records nothing, so the restored layout is left
exactly as painted.  That flag is all that is left of the anti-save
flag this section once had: it does not touch autosave, it only scopes
the target to the outer jump.  (When a post-restore prompt runs the
event loop — the missing-repo chooser waiting in =read-event= — the
paint and the finish step fire while the prompt is up; the host then
displays the chosen buffer itself, in the already painted layout.)

*Strictly after the paint, by construction.*  The finish step is
queued with =run-at-time= =workspace-bookmark--finish-delay= seconds
from now, not with =nil=.  timer.el keeps its list sorted by time and
inserts a timer BEFORE any already queued at an equal time, so two
=run-at-time nil= calls that read the same clock value fire newest
first — the finish step would run before the paint, and the paint
would cover the file.  The paint was stamped while the restore ran,
before the finish step is queued; a time strictly past the current
clock is strictly later than that stamp, so the paint fires first
whatever the clock's resolution.

*Released on every path.*  The finish step is queued from an
=unwind-protect= cleanup around =workspace-restore=, so a restore that
signals or is quit still queues it, and the finish step clears the
target and the flag in an =unwind-protect= cleanup of its own.

*Errors in this flow decline; they do not fall through.*  The seam's
barrier answers an error in its decision by calling through with the
ORIGINAL argument — tolerable for a programming error elsewhere in the
seam, but here the original argument IS the stored path, and a restore
that failed half-way is no reason to open it.  So this section has its
own barrier: an error in choosing, restoring or resolving becomes a
decline naming the error, and a plan that would call through with the
original argument is turned into a decline as well.  After a restore
that plan can only come from =non-portable=, which a record that took
this hand-off (its stamp already read as usable) reaches only through
the resolver's pre-identity error barrier — whose =:path= is the
stored filename — so declining it is the invariant, not a loss.
=quit= passes.

#+begin_src emacs-lisp
(defun workspace-bookmark--broken-workspace-p (name)
  "Return non-nil when the registered workspace NAME is broken.
Reads the registry plist's flag through `workspace--broken-p'; nil when
NAME is not registered or the registry is not loaded."
  (and name
       (boundp 'workspace--registry)
       (hash-table-p workspace--registry)

       (let ((ws (gethash name workspace--registry)))
         (and ws (workspace--broken-p ws) t))))

(defun workspace-bookmark--offerable-workspaces (identity)
  "Return the workspaces that may serve a jump into IDENTITY, holders first.
An ordered list of (NAME . HOLDS-P): every registered workspace that is
not broken, those holding one or more checkouts of IDENTITY (HOLDS-P
non-nil) before those holding none, registry order within each group.
Asks `workspace-bookmark--workspace-checkouts' once per workspace."
  (let (holders others)
    (dolist (name (workspace-bookmark--registered-names))
      (unless (workspace-bookmark--broken-workspace-p name)
        (if (workspace-bookmark--workspace-checkouts identity name)
            (push (cons name t) holders)
          (push (cons name nil) others))))
    (nconc (nreverse holders) (nreverse others))))

#+begin_src emacs-lisp
(defun workspace-bookmark--workspace-table (candidates identity)
  "Return a completion table over CANDIDATES that keeps their order and annotates them.
CANDIDATES is what `workspace-bookmark--offerable-workspaces' returned
for IDENTITY.  The metadata pins `display-sort-function' and
`cycle-sort-function' to `identity', so a front-end cannot sort the
holders-first order away, and annotates each name with whether it
holds a checkout of IDENTITY."
  (let ((names (mapcar #'car candidates)))
    (lambda (string predicate action)
      (if (eq action 'metadata)
          `(metadata
            (category . workspace)
            (display-sort-function . identity)
            (cycle-sort-function . identity)
            (annotation-function
             . ,(lambda (name)
                  (if (cdr (assoc name candidates))
                      (format "  holds a checkout of %s" identity)
                    "  no checkout"))))
        (complete-with-action action names string predicate)))))

(defun workspace-bookmark--choose-workspace (candidates identity)
  "Ask which of CANDIDATES should serve a jump into IDENTITY; return its name, or nil.

returned for IDENTITY; it is offered through `completing-read' with a
required match, the first holder as the default when there is one.

acts on.  Does not catch `quit': C-g ends the jump, nothing else is
asked.  The caller has checked `workspace-bookmark--can-prompt-p'."
  (let* ((default (and (cdr (car candidates)) (car (car candidates))))
         (choice (completing-read
                  (format-prompt "Restore a workspace for %s" default identity)

#+begin_src emacs-lisp
(defun workspace-bookmark--finish-restore ()
  "Deferred tail of a restore-then-jump: show the jump's buffer in the painted layout.
Queued by `workspace-bookmark--restore-for-jump' to fire strictly after
the layout's own deferred `window-state-put' (see
`workspace-bookmark--finish-delay').  Shows
`workspace-bookmark--jump-target', when the outer jump landed in a live
buffer, in the selected window of the painted layout — same window, no
split — then clears the target and
`workspace-bookmark--awaiting-jump-target'.  The clearing is an
`unwind-protect' cleanup, so a display that signals still clears both."
  (unwind-protect
      (let ((target workspace-bookmark--jump-target))
        (when (buffer-live-p target)
          (pop-to-buffer-same-window target)))
    (setq workspace-bookmark--jump-target nil
          workspace-bookmark--awaiting-jump-target nil)))

(defun workspace-bookmark--restore-for-jump (name)
  "Restore workspace NAME for a bookmark jump; return NAME.
Calls `workspace-restore', and only once it has RETURNED clears any
target and raises `workspace-bookmark--awaiting-jump-target', so the
restore's own leaf jumps are never taken for the jump.  Queues
`workspace-bookmark--finish-restore' from an `unwind-protect' cleanup —
whether the restore returned, signalled or was quit — at
`workspace-bookmark--finish-delay' seconds from now: strictly later
than the restore's own `run-at-time' nil paint, so the paint fires
first."
  (setq workspace-bookmark--jump-target nil
        workspace-bookmark--awaiting-jump-target nil)
  (unwind-protect
      (progn
        (workspace-restore name)
        (setq workspace-bookmark--jump-target nil
              workspace-bookmark--awaiting-jump-target t))
    (run-at-time workspace-bookmark--finish-delay nil
                 #'workspace-bookmark--finish-restore))
  name)

(defun workspace-bookmark--note-jump-target (origin arg)
  "Record where the outer jump of a restore-then-jump landed.
Called by the seam right after every host call, with ORIGIN the buffer
current before the host ran and ARG the argument it was handed.  A
no-op unless `workspace-bookmark--awaiting-jump-target' is raised — only
the first host call after a jump-triggered restore returned, the outer
jump's own, gets past it — and it lowers the flag.  The current buffer
is recorded when the jump landed (`workspace-bookmark--landed-p'): it is
no longer ORIGIN, or it visits ARG's location, as it does when the file
is the buffer the new tab inherited."
  (when workspace-bookmark--awaiting-jump-target
    (setq workspace-bookmark--awaiting-jump-target nil)
    (when (workspace-bookmark--landed-p origin arg)
      (setq workspace-bookmark--jump-target (current-buffer)))))

(defun workspace-bookmark--no-workspace-plan (record)
  "Plan the jump to stamped RECORD when no workspace will serve it.
Resolves RECORD with no workspace (rows 4–6 of the resolver's table)
and acts on the outcome without ever calling through: `missing-repo' is
handed to `workspace-bookmark--offer-missing-repo', whose chooser

  (let ((resolution (workspace-bookmark--resolve record nil)))
    (pcase (plist-get resolution :outcome)
      ('missing-repo
       (workspace-bookmark--offer-missing-repo record resolution))
      ((or 'ambiguous 'no-clone)
       (cons 'decline (workspace-bookmark--decline-message record resolution)))
      (outcome
       (cons 'decline
             (format "Bookmark %S: no workspace chosen, and it cannot be resolved without one (%s); nothing opened"
                     (bookmark-name-from-full-record record) outcome))))))

(defun workspace-bookmark--off-workspace-plan (record bookmark-name-or-record)
  "Plan the jump to stamped RECORD when no workspace is current.
Establishes a workspace first — `workspace-bookmark--choose-workspace',
then `workspace-bookmark--restore-for-jump' — and re-enters
`workspace-bookmark--jump-plan' with the chosen name, so the outcome is
decided by the seam's normal path against that workspace.  With nothing
offerable (empty or all-broken registry) or an empty answer, the plan
is `workspace-bookmark--no-workspace-plan''s.  When workspaces are
offerable but no one can be asked (`workspace-bookmark--can-prompt-p'
is nil) the jump declines without prompting.  BOOKMARK-NAME-OR-RECORD
is the seam's original argument, passed on for the plan.  Any error in
this flow declines naming the error, and a plan that would call
through with the ORIGINAL argument — the stored path — declines too;
`quit', at the prompt or anywhere else, passes."
  (let ((name (bookmark-name-from-full-record record)))
    (condition-case err
        (let* ((identity (car (workspace-bookmark--stamped-coordinates record)))
               (candidates (workspace-bookmark--offerable-workspaces identity)))
          (cond
           ((null candidates)
            (workspace-bookmark--no-workspace-plan record))
           ((not (workspace-bookmark--can-prompt-p))
            (cons 'decline
                  (format "Bookmark %S: no workspace is current, and no one can be asked which to restore; nothing opened"
                          name)))
           (t
            (let ((workspace (workspace-bookmark--choose-workspace
                              candidates identity)))
              (if (null workspace)
                  (workspace-bookmark--no-workspace-plan record)
                (let ((plan (workspace-bookmark--jump-plan
                             bookmark-name-or-record
                             (workspace-bookmark--restore-for-jump workspace))))

                           (eq (cdr plan) bookmark-name-or-record))
                      (cons 'decline
                            (format "Bookmark %S: cannot be resolved in workspace %s; nothing opened"
                                    name workspace))
                    plan)))))))
      (error
       (cons 'decline
             (format "Bookmark %S: could not establish a workspace for it (%s); nothing opened"
                     name (error-message-string err)))))))

* Checkout discovery

Where else is this repository checked out, and which of those checkouts —
if any — may be offered as THE canonical one?  These are pure queries: no
buffer is opened, nothing prompts, nothing is cached.  Every git question
goes through =workspace-bookmark--git=, every identity through
=workspace-bookmark--memoised-identity= (on the root a position names),
and every function here returns nil (or,
for the classifier, =other=) rather than signalling
(=register/boundary/git-derived-checkout-discovery=).

The vocabulary is closed: each checkout is =canonical=,
=workspace-owned= or =other= (=register/vocabulary/checkout-classification=).
Its whole reason to exist is one NEGATIVE rule: a workspace-owned checkout
is never canonical, and neither is a linked worktree that no workspace
owns.  Offering either as "the canonical checkout" would reintroduce the
defect this capability removes — one workspace's files opened while the
user is in another, or a stale branch shown as if it were the repository.

** What counts as a checkout

A directory is a usable checkout when it is LOCAL, exists, and contains a
=.git= entry.  The =.git= entry may be a directory (a main worktree) or a
file (a linked worktree, a submodule, a =--separate-git-dir= checkout);
either way git will treat the directory as a checkout root.

The existence test is load-bearing, not tidy.  =git worktree list= reports
worktrees whose directory is gone (=prunable=), a bare repository as its
first entry, and — for a submodule or a =--separate-git-dir= repository —
the GIT DIRECTORY in place of the main worktree (measured, git 2.49).  All
of those are real directories or recorded paths that are not checkouts,
and a consumer handed one would open files that are not there.

#+begin_src emacs-lisp
(defun workspace-bookmark--checkout-dir-p (dir)
  "Return non-nil when DIR is an existing local checkout root.
That is: DIR is a local directory containing a `.git' file or directory.
Never signals; a remote DIR is rejected without touching the network."
  (and (stringp dir)
       (not (file-remote-p dir))
       (condition-case nil
           (let ((dir (expand-file-name dir)))
             (and (file-directory-p dir)
                  (file-exists-p (expand-file-name ".git" dir))))
         (error nil))))

** Reading =git worktree list --porcelain=

The porcelain form, not the human-readable one: the latter is
column-aligned and lossy.  Porcelain is one attribute per line; each entry
starts with =worktree <path>= and git lists the MAIN worktree first.  The
flag lines that matter here are =bare=, =detached=, =locked [reason]= and
=prunable [reason]=; =HEAD= and =branch= are ignored.

=-z= is deliberately NOT used.  It is the only fully faithful form (a
worktree path containing a newline splits across two lines without it),
but it needs git 2.36, and on an older git the call exits non-zero, which
this module maps to "no checkouts" — a silent loss of the whole feature
on, for example, Ubuntu 22.04's git 2.34, traded for a path spelling
nobody uses.  Without =-z= such a path is read truncated at the newline;
the truncated path does not name a checkout, so the existence test in
=workspace-bookmark--checkout-dir-p= drops it: the entry goes missing, it
is never replaced by a different directory.

#+begin_src emacs-lisp
(defun workspace-bookmark--parse-worktree-porcelain (text)
  "Parse TEXT, output of `git worktree list --porcelain', into entries.

Returns a list of plists in git's order, the main worktree first:

  (:path PATH :bare BOOL :detached BOOL :locked BOOL :prunable BOOL)

Lines before the first `worktree' line, and attribute lines this parser
does not know, are ignored.  TEXT nil yields nil."
  (let (entries current)
    (dolist (line (split-string (or text "") "\n"))
      (cond
       ((string-match "\\`worktree \\(.+\\)\\'" line)
        (when current (push current entries))
        (setq current (list :path (match-string 1 line)
                            :bare nil :detached nil
                            :locked nil :prunable nil)))
       ((null current))
       ((string-match-p "\\`bare\\'" line)
        (setq current (plist-put current :bare t)))
       ((string-match-p "\\`detached\\'" line)
        (setq current (plist-put current :detached t)))
       ((string-match-p "\\`locked\\(?: \\|\\'\\)" line)
        (setq current (plist-put current :locked t)))
       ((string-match-p "\\`prunable\\(?: \\|\\'\\)" line)
        (setq current (plist-put current :prunable t)))))
    (when current (push current entries))
    (nreverse entries)))

(defun workspace-bookmark--worktree-entries (dir)
  "Return the parsed worktree listing of the repository containing DIR.
See `workspace-bookmark--parse-worktree-porcelain' for the entry shape.
Returns nil when git fails."
  (workspace-bookmark--parse-worktree-porcelain
   (workspace-bookmark--git dir "worktree" "list" "--porcelain")))

** Every checkout of a repository

Only USABLE checkouts are returned, in git's order:

| porcelain entry         | returned? | why                                         |
|-------------------------+-----------+---------------------------------------------|
| plain, directory exists | yes       |                                             |
| =detached=              | yes       | a detached HEAD is still a checkout         |
| =locked=, exists        | yes       | =~/.emacs.d= is exactly this shape          |
| =locked=, missing       | no        | locked entries are never marked prunable    |
| =prunable=              | no        | its directory is gone                       |
| =bare=                  | no        | a bare repository has no working tree       |
| a git dir in main slot  | no        | submodule / =--separate-git-dir= (no =.git=) |

Paths come back as git reports them — absolute and already truenamed
(=/private/var/…= on macOS) — with a trailing slash, the same shape as
the root of a position (=--checkout-position=).

The listing is asked through the discovery memo of the next section:
DIR's position supplies the repository's shared git directory, which
keys the listing, so within one discovery call every checkout of a
repository shares ONE =git worktree list=, and DIR's position is shared
with whoever else asks it.  Outside a discovery call nothing is shared
and the two questions (position, listing) simply run.  The canonical
predicate's candidate — a repository's MAIN-WORKTREE ENTRY — is the
first element of this list (=--main-worktree-of=, "The one canonical
predicate"), so this is the one function that reads the listing into
checkouts.

** One discovery call asks git each question once

Discovery asks git the same two questions about many directories: where
a checkout sits (=--checkout-position=: root and shared git directory in
one =rev-parse=) and which worktrees its repository has (=git worktree
list --porcelain=).  Within ONE discovery call the answers overlap: the
position of a checkout in view is also the position of the main
worktree the canonical test examines when the two are the same
directory, and every checkout of one repository lists the same
worktrees.  The audit at 20944160 measured the picker at about four
subprocesses per magit entry and =missing-repo= at ten with three
checkouts in view (end-of-cycle finding 6), most of them re-asking
these two questions.

So a discovery call carries a memo of git's answers for its own
duration — =workspace-bookmark--discovery-memo=, bound by
=workspace-bookmark--with-discovery-memo= around each plural discovery
function and shared by nested calls — and the two questions are asked
through it:

- A POSITION is keyed by the directory's truename, so a checkout as a
  workspace home or magit spells it and the same directory as =git
  worktree list= spells it (resolved, =/private/var/…=) share one
  answer.  Nothing is normalised beyond that: two different directories
  are two questions.  The truename is taken only AFTER =file-remote-p=
  has said the name is local — the same barrier the runner keeps, and
  for the same reason: =file-truename= on a TRAMP name opens the
  connection.  A remote or non-string name has no position, which is
  the answer the runner gave it before the memo existed.
- A WORKTREE LISTING is keyed by the repository's shared git directory,
  which the position supplies; git's listing is a property of the
  repository, not of the checkout it was asked in.  Without a position
  (a directory git does not treat as a work tree) there is no key and
  the listing is simply asked.
- The TRACKED-FILE CHECK of a canonical candidate (=git ls-files=, the
  fourth check of =--canonical-checkout=) is keyed by the candidate's
  truename, like a position.  Within one plural call the candidates are
  de-duplicated before the predicate runs, so it is asked once anyway;
  the key matters when one call reaches a repository twice — the
  picker's two sources, both inside one scope (below).

What this memo is NOT: it is not a cache across calls.  It exists only
inside one =--workspace-checkouts=, =--canonical-checkouts-among= or
=--canonical-checkouts-for-identity= call — or one
=--resolve-coordinates= decision, which binds it once around the two
plural calls it makes so the current home's checkouts are positioned
once, not once per call, or one call of the public
=workspace-bookmark-call-with-discovery-memo=, which the git-worktrees
picker wraps around its whole candidate build ("Cross-module
interface") — and is dropped on return, so
it can never answer from a layout that has changed since; the only
state that survives a call is the identity memo above, which is
revalidated on every use.  Outside a discovery call the memo is nil and
each question simply runs git, so the helpers below behave exactly like
the functions they wrap.

The resulting costs, on a warm identity memo, are the cost contract of
=register/boundary/git-derived-checkout-discovery=, pinned by
=portable-bookmarks-cost-spec.el= and =git-worktrees-spec.el=:

- =--workspace-checkouts=: ONE subprocess per checkout of the home (its
  position); the identity is a memo hit.
- =--canonical-checkouts-for-identity=: one per checkout in view, plus,
  per matching repository, one worktree listing and one =ls-files= for
  the main worktree's tracked-file check (the =--show-toplevel= check
  is answered by the position already held).  Inside a resolve
  decision the workspace's own checkouts were positioned by
  =--workspace-checkouts= in the same scope and cost nothing again.
  Four checkouts in view, one of them the workspace's own, one matching
  repository: 4 + 2 = 6 subprocesses, against 16 before (the cost spec's
  =missing-repo= fixture).
- the picker, per magit entry that is a canonical main clone: THREE
  (position, worktree listing, tracked-file check); each further
  checkout of a repository already seen: ONE.  Against about five.  The
  picker's two sources — the checkouts in view and magit's list — are
  classified in ONE discovery call, so a repository reached from both
  pays its three once: its main clone in magit's list then costs
  nothing more.

Three is the floor, not a target that was missed: a canonical answer
needs the shared git directory, git's own main-worktree slot and a
tracked file present on disk, and those are three different git
commands.  (The plan's "≤ 2 per entry" and "missing-repo ≤ 1 + in-view
count" assumed the canonical test could collapse to one subprocess; it
cannot without dropping one of the four signals, which is an outcome
change.)

#+begin_src emacs-lisp
(defvar workspace-bookmark--discovery-memo nil
  "Answers git gave earlier in the current discovery call, or nil outside one.
A hash table (test `equal') keyed by (QUESTION . KEY) — see
`workspace-bookmark--shared-position',
`workspace-bookmark--shared-worktree-entries' and
`workspace-bookmark--shared-tracked-file-p' — and bound by
`workspace-bookmark--with-discovery-memo'.  It never outlives the call
that bound it.")

(defmacro workspace-bookmark--with-discovery-memo (&rest body)
  "Run BODY as one discovery call, asking git each question at most once.
A call nested inside another shares the outer call's memo rather than
starting its own."
  (declare (indent 0) (debug t))
  `(let ((workspace-bookmark--discovery-memo
          (or workspace-bookmark--discovery-memo
              (make-hash-table :test #'equal))))
     ,@body))

(defun workspace-bookmark--memoised-in-call (key function &rest args)
  "Return (apply FUNCTION ARGS), asked once per KEY within a discovery call.
Outside a discovery call (`workspace-bookmark--discovery-memo' nil)
FUNCTION is simply applied.  A nil answer is memoised like any other."
  (let ((memo workspace-bookmark--discovery-memo))
    (if (null memo)
        (apply function args)
      (let ((hit (gethash key memo 'workspace-bookmark--unasked)))
        (if (eq hit 'workspace-bookmark--unasked)
            (puthash key (apply function args) memo)
          hit)))))

      (let ((dir (directory-file-name (expand-file-name dir))))

** The canonical checkout

The repository's MAIN worktree, established by two independent signals
that must agree, and then confirmed against the candidate itself:

1. =git rev-parse --path-format=absolute --git-common-dir= — the shared
   git directory.  When it is a directory literally named =.git=, its
   parent is the main worktree.  It is asked as part of DIR's POSITION
   (=--checkout-position=, which adds =--show-toplevel= to the same
   =rev-parse=), so that within a discovery call the answer is shared
   with whoever already positioned DIR, and so that DIR's own top level
   is known for check 3.  When DIR is in no work tree the position is
   nil and the shared git directory is asked on its own, as before —
   the layouts in the table below all still answer.
2. The FIRST entry of =git worktree list --porcelain=, which git documents
   as the main worktree.  It must not be =bare=.  Shared per repository
   within a discovery call (=--shared-worktree-entries=).
3. =git rev-parse --show-toplevel=, run IN the candidate, must name the
   candidate.  This catches the one layout where 1 and 2 agree and are
   both wrong (see the =core.worktree= row below).  When DIR's own top
   level (from check 1's =rev-parse=) IS the candidate, the answer is
   already in hand: git run at the root of the work tree containing DIR
   names that root.  Otherwise — DIR is a linked worktree, or the
   candidate's tree lives elsewhere — it costs one more subprocess, paid
   only once 1 and 2 have agreed.
4. The candidate must HOLD the work tree: at least one path =git
   ls-files= lists there exists under it.  This catches the layouts
   where all three checks above agree on a directory that holds nothing
   but the git directory (the two =.git=-named rows below).  One more
   subprocess, paid only once 1–3 have passed, and shared per candidate
   within a discovery call (=--shared-tracked-file-p=).

Asked about a main clone that is canonical, the whole test therefore
costs THREE subprocesses (position, worktree listing, tracked-file
check); about a linked worktree, four.  No subprocess-free form exists:
the three are different git commands.

=--path-format=absolute= is required, not cosmetic.  Asked in the main
worktree, plain =--git-common-dir= answers =.git=, and from a
subdirectory =../.git= — relative to wherever git happened to run.  The
runner resolves a file argument to its directory before running git, so
re-expanding that answer against the caller's DIR would be wrong whenever
DIR names a file.  The flag needs git 2.31; an older git exits non-zero
and the answer is nil.

The signals disagree in exactly the cases where the naive answer is a
GUESS, and every one of them resolves to nil (measured, git 2.49):

| layout                                  | common dir        | first entry         | parent-of-common would give  |
|-----------------------------------------+-------------------+---------------------+------------------------------|
| ordinary clone                          | =R/.git=          | =R=                 | =R= (correct — agree)        |
| bare =R.git= + linked worktrees         | =R.git=           | =R.git=, =bare=     | the directory ABOVE =R.git=  |
| bare repo stored as =D/.git= + worktrees | =D/.git=          | =D/.git=, =bare=    | =D=, which has no work tree  |
| =git init --separate-git-dir G W=       | =G=               | =G= (not =W=!)      | the parent of =G=            |
| submodule =S/m=                         | =S/.git/modules/m= | =S/.git/modules/m=  | =S/.git/modules=             |
| =D/.git= with =core.worktree = T=       | =D/.git=          | =D=                 | =D= — but the work tree is =T= |
| =git init --separate-git-dir P/.git W=  | =P/.git=          | =P=                 | =P= — a husk holding only =.git= |
| =W/.git= a symlink to =P/.git=          | =P/.git=          | =P=                 | =P= — a husk holding only =.git= |

The =--separate-git-dir= row holds only when the git directory is NOT
named =.git=.  When it is — =git init --separate-git-dir=<elsewhere>/.git=,
or a main worktree whose =.git= is a symlink to a directory kept on
another disk or outside a sync folder — the last two rows apply, and
every signal agrees on the wrong directory.  Git's absolute common dir is
the RESOLVED git directory =P/.git=; its main-worktree slot is that path
minus =/.git=; and git run IN =P= finds =P/.git= and treats =P= as a
work tree, so =--show-toplevel= names =P= and =P='s own git dir IS the
common dir.  Nothing git says distinguishes =P= from a real main
worktree.  Only the disk does: =P= holds none of the files git's index
lists (measured, git 2.49).  Hence check 4.

Check 4 asks for a TRACKED path, not merely "something besides =.git=":
a husk that Finder, Spotlight or a sync client has visited holds a
=.DS_Store= or similar, and would pass the weaker test.  The price is
that a main worktree tracking no files, or one whose every tracked file
has been deleted, has no canonical checkout — which costs nothing, since
an untracked location is never stamped.

A tracked path is not enough on its own either.  Repositories edited on
a Mac often COMMIT a =.DS_Store=, and Windows and sync clients leave
=Thumbs.db=, =desktop.ini= or =Icon\r= that get committed the same way.
When the repository tracks such a file and the OS writes one into the
husk, "a tracked path exists" is true of the husk (measured, git 2.49,
with the since-deleted singular canonical lookup: it returned the husk).  So check 4 SKIPS every
listed path whose basename is an OS or sync-client artifact, and answers
t only for another tracked path that exists.  The list is short, closed
and compared without regard to letter case (Windows names are
case-insensitive, and so is this Mac's disk):

| name          | written by                                        |
|---------------+---------------------------------------------------|
| =.DS_Store=   | macOS Finder, in any directory it displays        |
| =._*=         | macOS AppleDouble files, on non-HFS volumes and in archives |
| =.localized=  | macOS, for folders with a localized display name  |
| =Icon\r=      | macOS custom folder icons (Finder, Dropbox, Google Drive) |
| =Thumbs.db=, =ehthumbs.db= | Windows Explorer thumbnail caches    |
| =desktop.ini= | Windows Explorer and OneDrive folder settings     |
| =.directory=  | KDE Dolphin folder settings                       |

A denylist rather than "a meaningful fraction of the tracked paths must
exist".  A fraction has to read the WHOLE index on every call, where the
denylist still stops at the first real hit (one stat for a real main
worktree).  It also refuses real main worktrees: a checkout in the
middle of a large deletion, or a sparse checkout, has most tracked paths
absent, and any threshold would be arbitrary.  The denylist removes
exactly the names that something other than git writes into arbitrary
directories, and nothing else.

Residuals, stated because they are accepted: a husk that still holds an
OLD copy of the tree passes check 4, and so does a husk into which some
other program wrote a file the repository also tracks under a name not
on the list (an editor's project settings, say).  No git-derived signal
can tell either from the real work tree.

The real main worktree =W= in those two rows is not recoverable from a
linked worktree: git records no path to it.  When =W= itself is the
checkout in view the answer is also nil — =W= is not the parent of the
common dir.  Nil over a guess.

The =D/.git= row is why the first signal alone is not enough: =D= even
passes the classifier's cheap =.git=-is-a-directory test.  The last two
rows before it are why the second signal alone is not enough: git reports
its own git directory as the "main worktree".  In the =core.worktree= row
the two signals AGREE on =D=, because git's main-worktree slot is always
the parent of the common dir and ignores =core.worktree= — while the
repository's files live in =T=.  Re-anchoring a relpath under =D= would
find nothing, or a stale copy.  Only the third check sees it: run in =D=,
=--show-toplevel= answers =T=.  (A LINKED worktree of such a repository
ignores =core.worktree= and is its own top level, measured on git 2.49.)

Check 4 reads =ls-files -z= (no quoting of unusual names) and stops at
the first listed path that exists, so a real main worktree costs one
stat.  Paths are joined to the candidate by concatenation, with file
name handlers off: a tracked name is data, and =expand-file-name= would
read a leading =~= in it as a home directory.  =file-attributes= does not
follow symlinks, so a tracked symlink counts as present even when it
dangles.

#+begin_src emacs-lisp
(defun workspace-bookmark--holds-tracked-file-p (dir)
  "Return non-nil when DIR holds at least one path git tracks there.

Runs `git ls-files -z' in DIR and returns t at the first listed path
that exists under DIR.  A listed path whose basename is an OS or
sync-client artifact (`workspace-bookmark--os-artifact-p') is skipped:
Finder and friends write those into any directory, the husk of a
`.git'-named git directory included.  Nil when git fails, lists
nothing, or no other listed path exists — the shape of a directory that
holds only a git directory.  Never signals."
  (let ((out (workspace-bookmark--git dir "ls-files" "-z")))
    (when out
      (condition-case nil
          (let ((root (file-name-as-directory (expand-file-name dir)))
                (file-name-handler-alist nil)
                (start 0)
                (found nil))
            (while (and (not found) (< start (length out)))
              (let* ((end (or (string-search "\0" out start) (length out)))
                     (path (substring out start end)))
                (when (and (> end start)
                           (not (workspace-bookmark--os-artifact-p path))
                           (file-attributes (concat root path)))
                  (setq found t))
                (setq start (1+ end))))
            found)
        (error nil)))))
#+end_src

#+begin_src emacs-lisp
(defun workspace-bookmark--canonical-checkout (dir)
  "Return the main worktree of the repository containing DIR, or nil.

The value is an absolute directory name with a trailing slash.  Two
signals must agree: the parent of the shared git directory
\(`git rev-parse --path-format=absolute --git-common-dir'), which must
be a directory named `.git', and the first, non-bare entry of `git
worktree list --porcelain'.  The candidate must then be its own top
level: `git rev-parse --show-toplevel' run in it names it, and it must
hold the work tree: at least one path git tracks exists under it (see
`workspace-bookmark--holds-tracked-file-p').  When the signals disagree
— a bare main repository, a `--separate-git-dir' layout, a submodule —
or the candidate's work tree is elsewhere (`core.worktree'), or the
candidate is a husk holding only a `.git'-named git directory whose
work tree lives elsewhere (`--separate-git-dir=<dir>/.git', or a `.git'
symlink), or any answer is unavailable, the answer is nil: no canonical
checkout is better than a guessed one.  Never signals.

Within a discovery call (`workspace-bookmark--with-discovery-memo') the
position, the worktree listing and the tracked-file check are shared
with the rest of the call, and the top-level check is answered from
DIR's own position when DIR's top level is the candidate; the answer is
the same either way."
  (let* ((position (workspace-bookmark--shared-position dir))
         (common (if position
                     (nth 1 position)
                   (workspace-bookmark--git
                    dir "rev-parse" "--path-format=absolute" "--git-common-dir"))))
    (when (and common
               (file-name-absolute-p common)
               (equal ".git" (file-name-nondirectory
                              (directory-file-name common)))
               (condition-case nil (file-directory-p common) (error nil)))
      (let ((candidate (file-name-directory
                        (directory-file-name (expand-file-name common))))
            (first (car (workspace-bookmark--shared-worktree-entries
                         dir common))))
        (when (and first
                   (not (plist-get first :bare))
                   (workspace--same-file-p (plist-get first :path)
                                           candidate))
          (let ((top (if (and position
                              (workspace--same-file-p (nth 0 position)
                                                      candidate))
                         (nth 0 position)
                       (workspace-bookmark--git
                        candidate "rev-parse" "--show-toplevel"))))
            (when (and top
                       (workspace--same-file-p top candidate)
                       (workspace-bookmark--shared-tracked-file-p candidate))
              (file-name-as-directory candidate))))))))

** Classification

Three symbols, tested in THIS order — ownership before structure:

1. =workspace-owned= — the checkout really lies within some registered
   workspace's =:home=, or is that home (an anchored workspace), or
   really CONTAINS that home (a workspace anchored at a subdirectory of
   the checkout — unless the home is another worktree of the same
   repository).  Only a home that exists counts.  Symbolic links confer
   nothing (see "Symbolic links
   are ignored" below).
2. =canonical= — =.git= is a directory.  A linked worktree's =.git= is a
   FILE (=~/.emacs.d/.git= on this machine is a 54-byte file); a main
   worktree's is a directory.  No subprocess.
3. =other= — everything else, including anything this function cannot
   test (a remote path, a non-string).

Ownership comes first because a workspace can hold a full clone rather
than a linked worktree.  That clone's =.git= is a directory, so a
structure-first test calls it =canonical= — and the safety rule would then
offer workspace A's files to a user standing in workspace B, the exact
defect this capability exists to remove.  The price is conservative: a
main worktree that sits inside a workspace home is never offered as
canonical, and the resolver reports =no-clone= instead.  Nil over a guess.

*A home inside a checkout makes that checkout workspace-owned* (user
decision, 2026-09-25).  A workspace anchored at a SUBDIRECTORY of a main
clone — =~/emacs/config=, or "my package in the monorepo" — is working
in that clone's files, so the clone is the workspace's as surely as a
clone inside its home would be.  (=workspace--new-anchor-existing= sees
no =.git= in the subdirectory and =git init=s a nested repository there,
which has no remote; so the anchored home never gives the clone's
identity itself, and only this rule keeps the clone from being offered
to another workspace.)  The test is the same containment walk with its
arguments reversed: the home's truename, or one of its ancestors, is the
checkout.

What this rule can withdraw from offer is exactly the checkouts that
contain a registered home, and nothing else: the clause is a
disjunction, so a checkout's classification changes only when some
home's truename really lies within it.  It inherits the walk's
properties: =/a/ws-old= does not contain =/a/ws=, and a symbolic link
inside the checkout that points at a home confers nothing (only the
home's own truename is walked, never a link into it).  The cost is the
conservative one again: a clone that holds a workspace home anywhere
below it is never offered, and the resolver says =no-clone=.  A
repository whose work tree is =$HOME= (a "dotfiles" repository with a
real =~/.git= directory) contains every home under =~=, so it is never
offered; that is the rule as decided, not a side effect.

*One exception: a home that is another worktree of the SAME repository.*
The rule exists because a workspace anchored inside a clone is working
in that clone's files.  A linked worktree kept INSIDE its own main clone
— =<main>/.worktrees/feat=, Claude Code's =<main>/.claude/worktrees/x= —
is not: a workspace anchored there works in its own tree, on its own
branch, and nobody is working in the main clone.  So a home that
spatially lies within the checkout confers ownership only when it is
NOT a checkout root of the checkout's own repository.  The test runs
only when containment already holds: one =rev-parse= in the home asks
for its top level and its shared git directory, and the home is the
same repository's worktree when its top level IS the home and its
shared git directory is, by =--same-file-p=, the checkout's (the
checkout's =.git= directory itself for a main worktree, which costs no
subprocess; git is asked only for a checkout whose =.git= is a file).
A plain subdirectory home is not its own top level (git answers with
the enclosing clone), and the nested repository
=workspace--new-anchor-existing= creates in a subdirectory has a
different shared git directory, so both still own the clone.

*Only a home that exists confers ownership.*  A registered home can
have been deleted (a broken workspace, =workspace--broken-p=).  A path
that no longer exists lies in no directory (see the containment walk
below), so a deleted home owns nothing — neither what it used to
contain nor what used to contain it.

Containment is tested by FILE IDENTITY, never by comparing strings.
The checkout path is truenamed, then it and each of its parent
directories in turn is compared to the home with
=workspace--same-file-p= (device and inode; see "Same file"),
not by spelling.  A trailing slash, a =~= spelling, macOS's =/var= →
=/private/var= symlink and — the case that matters — a difference in
LETTER CASE on a case-insensitive filesystem all compare correctly, and
because whole directories are compared, =/a/ws-old= is not inside =/a/ws=.
Because only device and inode are compared, a home that is being written
to while the walk runs still compares equal to itself.  The first
implementation used =file-equal-p=, which also compares timestamps, and
under a concurrent writer it failed OPEN: see "Same file".

String comparison is rejected even after truenaming.  =file-in-directory-p=
(the first implementation) truenames both sides and then compares path
components with =string-equal=, and =file-truename= does not fold case.
On this Mac's case-insensitive disk a home registered as
=/root/wsdir/myws= for the on-disk =/Root/Wsdir/myws= is reachable —
=read-directory-name= accepts the typed case, and =workspace--make= keeps
it — and =file-in-directory-p= then says the workspace's own full clone
is NOT inside it.  Ownership-first classification turns that miss into a
=canonical= verdict for git's (on-disk-case) spelling of the clone, and
=--canonical-checkouts-for-identity= would offer workspace A's clone to a
user in workspace B.  Comparing file identity says t for the same pair.

The walk stops at the filesystem root.  A path that does not exist cannot
be proven inside anything, so it is not: =--path-within-p= requires BOTH
arguments to exist.  That matters since ownership is asked in both
directions — the reverse direction passes a registered HOME as the path,
and a home can have been deleted.  (Before the existence test, a deleted
home under a clone still owned the clone, because the walk truenames and
climbs a missing path as readily as a real one.)

Remote paths are rejected before any filesystem call: =file-truename= on a
TRAMP name would open a connection, and a remote home cannot own a local
checkout anyway.

*Symbolic links are ignored* (user decision, 2026-09-24).  A child of a
home that is a symbolic link is not one of the workspace's checkouts —
=--home-checkouts= skips it, whatever it points to — and no link, of
any kind, makes anything =workspace-owned=.  Only real directories
count: a checkout is owned when its truename really lies inside a home,
is the home, or really contains the home's truename.  Nothing in the workspaces tooling creates links in a
home: worktrees are added with =git worktree add=, homes are scaffolded
with real directories, and an anchored home is the repository itself.

KNOWN LIMITATION — stated here because it is accepted, not fixed.  If a
user symlinks a main clone into a workspace home (=ws/A/x ->
~/src/main=) instead of adding a worktree, workspace A is editing that
clone, yet the clone is not A's: it classifies =canonical=, and
=--canonical-checkouts-for-identity= may offer it to a user standing in
workspace B.  That is the defect the safety rule exists to prevent, reached
through a layout the tooling never builds.  The user's guidance is
simply: do not symlink checkouts into a workspace home; add a worktree.
The same holds for a link to a directory inside a clone, to a file
inside it, or to a directory above it.  An earlier revision owned the
targets of such links; it was removed because the rule was either too
broad (a single linked notes file silenced every bookmark into a
repository, with no diagnostic) or, once narrowed, still a partial
answer to a layout the tooling does not produce.

The flip side is conservative: because the link is not a checkout of
the workspace, a repository reachable ONLY through such a link is not
in view, and =--workspace-checkouts= never lists it.

#+begin_src emacs-lisp
(defun workspace-bookmark--path-within-p (path dir)
  "Return non-nil when PATH is DIR or lies inside it.

Both must be local and exist (a missing PATH is inside nothing); DIR
must be a directory.  Containment is
by file identity: PATH is truenamed, then it and each of its ancestors
is compared to DIR with `workspace--same-file-p', so
differences of spelling — trailing slash, `~', symlinked prefixes, and
letter case on a case-insensitive filesystem — do not matter, and
neither do DIR's timestamps changing during the walk.  Never signals."
  (and (stringp path) (stringp dir)
       (not (file-remote-p path))
       (not (file-remote-p dir))
       (condition-case nil
           (let ((current (directory-file-name
                           (file-truename (expand-file-name path))))
                 (previous nil)
                 (found nil))
             (when (and (file-exists-p (expand-file-name path))
                        (file-directory-p (expand-file-name dir)))
               (while (and (not found) (not (equal current previous)))
                 (if (workspace--same-file-p current dir)
                     (setq found t)
                   (setq previous current
                         current (directory-file-name
                                  (file-name-directory current))))))
             found)
         (error nil))))

(defun workspace-bookmark--same-repository-worktree-p (home checkout)
  "Return non-nil when HOME is a checkout root of CHECKOUT's own repository.
HOME must be its own top level (`git rev-parse --show-toplevel' run in it
names it), and its shared git directory must be CHECKOUT's, by
`workspace--same-file-p'.  CHECKOUT's shared git directory is
its `.git' directory when it has one; otherwise git is asked.  One
subprocess, two when CHECKOUT's `.git' is a file.  Never signals."
  (let* ((out (workspace-bookmark--git
               home "rev-parse" "--path-format=absolute"
               "--show-toplevel" "--git-common-dir"))
         (lines (and out (split-string out "\n"))))
    (and (= 2 (length lines))
         (workspace--same-file-p (nth 0 lines) home)
         (workspace--same-file-p
          (nth 1 lines)
          (let ((dotgit (expand-file-name ".git" checkout)))
            (if (file-directory-p dotgit)
                dotgit
              (workspace-bookmark--git
               checkout "rev-parse" "--path-format=absolute"
               "--git-common-dir")))))))

(defun workspace-bookmark--owning-workspace (checkout)
  "Return the name of a registered workspace that owns CHECKOUT, or nil.
A workspace owns CHECKOUT when CHECKOUT is its `:home', really lies
inside it, or really contains it, by file identity (see
`workspace-bookmark--path-within-p').  A contained home owns CHECKOUT
only when it is not itself a worktree of CHECKOUT's repository (see
`workspace-bookmark--same-repository-worktree-p'), and only a home
that exists owns anything.  Symbolic links confer nothing: a clone
linked into a home from outside it is not owned, and neither is a clone
holding a link to a home.  Never signals."
  (seq-find (lambda (name)
              (let ((home (workspace-bookmark--workspace-home name)))
                (or (workspace-bookmark--path-within-p checkout home)
                    (and (workspace-bookmark--path-within-p home checkout)
                         (not (workspace-bookmark--same-repository-worktree-p
                               home checkout))))))
            (workspace-bookmark--registered-names)))

(defun workspace-bookmark--classify (checkout)
  "Classify CHECKOUT as `canonical', `workspace-owned' or `other'.

`workspace-owned' when a registered workspace owns CHECKOUT (see
`workspace-bookmark--owning-workspace'); otherwise `canonical' when
its `.git' is a directory (a main worktree); otherwise `other'.  Ownership is tested FIRST: a full clone
inside a workspace home, or containing one, is workspace-owned, never
canonical.  A remote or non-string CHECKOUT is `other'.

`canonical' here is structural only, and NOT sufficient to offer
CHECKOUT as a repository's canonical checkout: see
`workspace-bookmark--offerable-canonical-p'.  Never signals."
  (condition-case nil
      (cond
       ((not (and (stringp checkout) (not (file-remote-p checkout))))
        'other)
       ((workspace-bookmark--owning-workspace checkout)
        'workspace-owned)
       ((file-directory-p (expand-file-name ".git" checkout))
        'canonical)
       (t 'other))
    (error 'other)))

** A workspace's checkouts

A workspace holds its checkouts as the IMMEDIATE children of its =:home=:
=~/emacs-workspaces/<name>/<repo>/=.  Grandchildren are not searched —
this is enumeration of a known layout, not scanning.  A child that is a
symbolic link is skipped, whatever it points to: only real directories
count (see "Symbolic links are ignored" under Classification).

The home ITSELF is a checkout of the workspace too, when it is one (user
decision, 2026-09-24).  A workspace anchored at an existing repository
(=workspace-new= with a prefix argument, =workspace--new-anchor-existing=)
has that repository AS its =:home=, not as a child of it; without this
such a workspace could never resolve a bookmark into its own repository,
and the resolver would say =no-clone= while the user stands in the
clone.  The home comes first, then the children, sorted.  This does not
widen what may be offered as canonical: a home is always inside itself,
so it classifies =workspace-owned=.  A scaffolded home is a git
repository too (=git init=), usually with no remote and so no identity;
it is enumerated like any other and never matches.

*One identity, several checkouts.*  A home can hold two sibling worktrees
of one repository (=project-alpha/=, =project-zeta/=), or be a checkout
of a repository and also hold a worktree of it.
=workspace-bookmark--workspace-checkouts= returns EVERY checkout of the
identity in the home, in the order above, and that list is the whole
answer: whether it is unique is the consumer's decision, read off the
list's length.  The first implementation returned the
alphabetically-first match, which is a choice of branch made by
=directory-files=' sort order; the consumer could not tell, and might
open the other branch's copy of the file.  Several matches is
AMBIGUITY, not absence, and a list keeps the two apart where a single
value (a checkout, or nil) could not.  How ambiguity maps onto the
resolver's outcomes is the resolver's decision, not this section's.

*Only checkout ROOTS count.*  =--home-checkouts= asks only whether a
child holds a =.git= entry, and an EMPTY =.git= directory (or any other
=.git= git does not accept) passes that test without making the child a
repository.  Git run in such a child walks up and answers for the
repository ENCLOSING it — in an anchored home, the home's own — so the
child would report the home's identity and be listed next to the home,
turning a unique answer into a false ambiguity.  A candidate is
therefore kept only when git's own top level for it IS it
(the root of its position, compared with =--same-file-p=).  The identity is then
read from that root, so the guard costs no extra subprocess.

Each checkout costs ONE subprocess — the =rev-parse= of its position
(=--shared-position=), which yields the root for the guard above and the
shared git directory that validates the identity memo — and its
identity comes from =--memoised-identity=, the same memo the stamp path
fills: a hit costs nothing, a miss one =remote get-url= (two more when
there is no =origin=) once per root per session.  Because uniqueness
needs them all, every checkout of the home is asked; there is no early
stop at the first match.

#+begin_src emacs-lisp
(defun workspace-bookmark--home-checkouts (home)
  "Return HOME and its immediate children that are checkouts.

HOME comes first when it is itself a checkout (a workspace anchored at
an existing repository), then the checkout children, sorted.  A child
that is a symbolic link is skipped, whatever it points to.  Each is an
absolute directory name with a trailing slash.  Returns nil when HOME
is nil, remote, or not an existing directory.  Never signals."
  (when (and (stringp home) (not (file-remote-p home)))
    (condition-case nil
        (let ((home (file-name-as-directory (expand-file-name home))))
          (when (file-directory-p home)
            (mapcar #'file-name-as-directory
                    (seq-filter #'workspace-bookmark--checkout-dir-p
                                (cons home
                                      (seq-remove
                                       #'file-symlink-p
                                       (directory-files
                                        home t
                                        directory-files-no-dot-files-regexp)))))))
      (error nil))))

(defun workspace-bookmark--workspace-checkouts (identity workspace-name)
  "Return every checkout of IDENTITY in WORKSPACE-NAME's home.

The candidates are those of `workspace-bookmark--home-checkouts' — the
home itself when it is a checkout, then its immediate children — and
the value keeps their order.  A candidate that is not its own checkout
root (a child whose `.git' git does not accept, which git resolves to
the repository enclosing it) is dropped.  Each is an absolute directory
name with a trailing slash.  Returns nil when IDENTITY or
WORKSPACE-NAME is nil, when the workspace is not registered, or when
nothing matches.  Never signals.

One subprocess per candidate (its position); the identity comes from
`workspace-bookmark--memoised-identity'."

    (workspace-bookmark--with-discovery-memo
      (seq-filter (lambda (checkout)
                    (let ((position (workspace-bookmark--shared-position checkout)))
                      (and position
                           (workspace--same-file-p (nth 0 position) checkout)
                           (equal identity
                                  (workspace-bookmark--memoised-identity
                                   (nth 0 position) (nth 1 position))))))
                  (workspace-bookmark--home-checkouts
                   (workspace-bookmark--workspace-home workspace-name))))))

** Checkouts in view

The checkouts in view, in order: the current workspace's checkouts (its
home, when that is a checkout, then its children; see "A workspace's
checkouts"), then those of every other registered workspace, then the
configuration repository this Emacs was loaded from (=jf/emacs-dir=).
That last one is what makes the =emacs= repository resolvable from a workspace that holds
no checkout of it: =~/.emacs.d= is itself a linked worktree, and git
expands it to its main worktree =~/emacs=.

#+begin_src emacs-lisp
(defun workspace-bookmark--checkouts-in-view ()
  "Return the checkouts in view, most relevant first, without duplicates.
The current workspace's checkouts, then every other registered
workspace's, then `jf/emacs-dir'.  A workspace's checkouts are its
home, when that is a checkout, and its home's checkout children (see
`workspace-bookmark--home-checkouts')."
  (let* ((current (workspace-bookmark--current-workspace))
         (others (remove current (workspace-bookmark--registered-names)))
         (config (bound-and-true-p jf/emacs-dir)))
    (delete-dups
     (append
      (and current
           (workspace-bookmark--home-checkouts
            (workspace-bookmark--workspace-home current)))
      (seq-mapcat (lambda (name)
                    (workspace-bookmark--home-checkouts
                     (workspace-bookmark--workspace-home name)))
                  others)
      (and (stringp config)
           (not (file-remote-p config))
           (list (file-name-as-directory (expand-file-name config))))))))

** The one canonical predicate

"May this directory be offered as a repository's canonical checkout?"
has exactly ONE answer in this capability, and every path that offers a
checkout as canonical — =--canonical-checkouts-for-identity= (the
resolver's canonical arm), =workspace-bookmark-canonical-checkouts-in-view= (the public
entry point), and through it the git-worktrees repository picker — asks
it here.  Two earlier derivations disagreed: the resolver path ran
=--canonical-checkout='s four checks and then =--classify=, while the
git-worktrees picker trusted =--classify= alone, and so offered the
husk of a =.git=-named git directory while omitting the real main
worktree.

The predicate is the conjunction of both halves, and neither half is
enough alone:

- =--classify= answers =canonical= — no registered workspace owns DIR,
  and DIR's =.git= is a directory.  NECESSARY, NOT SUFFICIENT: the husk,
  a =core.worktree= directory and a bare repository stored as =D/.git=
  all pass it.
- DIR is, by file identity, what =--canonical-checkout= says is the main
  worktree of DIR's own repository — so DIR is that repository's root,
  git agrees it is the main worktree, and it holds the work tree.
  NECESSARY, NOT SUFFICIENT: a workspace's full clone passes it.

The classification is asked first because it is the cheaper half: it
runs git only when a registered workspace's home lies inside DIR (the
same-repository test, one or two subprocesses per such home), and a
workspace-owned candidate never pays for =--canonical-checkout='s four.
Nothing here catches errors: every step it composes already returns nil
(or =other=) rather than signalling.

#+begin_src emacs-lisp
(defun workspace-bookmark--offerable-canonical-p (dir)
  "Return non-nil when DIR may be offered as its repository's canonical checkout.

DIR must classify `canonical' (`workspace-bookmark--classify': no
registered workspace owns it and its `.git' is a directory) AND be, by
file identity, the main worktree `workspace-bookmark--canonical-checkout'
finds for DIR's own repository.  Neither condition is sufficient alone.
This is the ONLY test that may admit a checkout as canonical.  Never
signals."
  (and (stringp dir)
       (eq 'canonical (workspace-bookmark--classify dir))
       (workspace--same-file-p
        dir (workspace-bookmark--canonical-checkout dir))))
#+end_src

Given some checkouts, the canonical checkouts of their repositories are
found by asking git for each repository's MAIN-WORKTREE ENTRY (the first
usable entry of its worktree listing: the first of =--checkouts-of=)
and putting that candidate to the predicate.  The
candidate need not itself be in view: that is the point of asking git.
Only the main worktree can pass, because the predicate requires the
candidate to BE the main worktree =--canonical-checkout= names; any
other entry in the candidate slot (a linked worktree, when the main is
bare or missing) fails closed.  Candidates are de-duplicated by file
identity BEFORE the predicate runs, so two checkouts of one repository
cost one test, and the order of first appearance is kept.

The whole of this runs as ONE discovery call (see "One discovery call
asks git each question once"), so the position a checkout pays for
here is the position the predicate's =--canonical-checkout= reuses when
that checkout IS the main worktree, and N checkouts of one repository
pay for one worktree listing, not N.

#+begin_src emacs-lisp
(defun workspace-bookmark--main-worktree-of (checkout)
  "Return the first usable checkout git lists for CHECKOUT's repository, or nil.
The first of `workspace-bookmark--checkouts-of': within a discovery
call CHECKOUT's position and its repository's worktree listing are
shared with the rest of the call."
  (car (workspace-bookmark--checkouts-of checkout)))

(defun workspace-bookmark--canonical-checkouts-among (checkouts)
  "Return the canonical checkouts of the repositories of CHECKOUTS.

For each of CHECKOUTS, in order, the main-worktree entry git lists for
its repository is a candidate; candidates are de-duplicated by file
identity (first occurrence kept) and only those that pass
`workspace-bookmark--offerable-canonical-p' are returned.  Each is an
absolute directory name with a trailing slash.  Never signals.

Runs as one discovery call: on a canonical main clone the whole test
costs three subprocesses, and further checkouts of a repository already
seen cost one each."
  (workspace-bookmark--with-discovery-memo
    (seq-filter
     #'workspace-bookmark--offerable-canonical-p
     (seq-uniq (delq nil (mapcar #'workspace-bookmark--main-worktree-of
                                 checkouts))
               #'workspace--same-file-p))))
#+end_src

** The safety rule, and ambiguity

=workspace-bookmark--canonical-checkouts-for-identity= finds every
in-view checkout of the identity and returns every DISTINCT canonical
checkout of their repositories.  If none survives, the answer is nil,
which the resolver maps to =no-clone= — never "the closest thing in
view".

*Two separate main clones of one identity are AMBIGUOUS* (user decision,
2026-09-25).  An old standalone clone next to a newer one, or
=~/.emacs.d= as its own clone next to =~/emacs=, are each a legitimate
main worktree that no workspace owns, and they can be on different
branches.  The first implementation returned the first one found, so
the answer depended on which workspace was current and then on registry
order, and the consumer could not tell a choice had been made.
=workspace-bookmark--canonical-checkouts-for-identity= therefore
returns them ALL and names none of them as THE checkout — the same
shape as =--workspace-checkouts=: a list, whose length tells "none"
from "one" from "several".  How ambiguity maps onto the resolver's
outcomes is the resolver's decision, not this section's.  Two worktrees
of ONE repository in view are not ambiguous: they share one main
worktree, which is counted once.

It asks every in-view checkout for its identity, because uniqueness
needs them all; there is no early stop at the first match.  Each costs
one subprocess (its position, =--shared-position=); the identity itself
is =--memoised-identity='s, a hit on a warm memo.  The matching
checkouts then go to =--canonical-checkouts-among= inside the SAME
discovery call, so their positions are not asked again.

#+begin_src emacs-lisp
(defun workspace-bookmark--canonical-checkouts-for-identity (identity)
  "Return every distinct canonical checkout of IDENTITY, or nil.

Searches the checkouts in view (`workspace-bookmark--checkouts-in-view')
for those whose identity is IDENTITY, and returns the canonical
checkouts of their repositories that pass
`workspace-bookmark--offerable-canonical-p', de-duplicated by file
identity, in order of first appearance.  A workspace-owned or `other'
checkout is never returned.  Nil when IDENTITY is nil, when no checkout
of it is in view, or when none passes.  Never signals.

One subprocess per checkout in view (its position); identities come
from `workspace-bookmark--memoised-identity', and the positions are
shared with the canonical test that follows."
  (when identity
    (workspace-bookmark--with-discovery-memo
      (workspace-bookmark--canonical-checkouts-among
       (seq-filter (lambda (checkout)
                     (let ((position (workspace-bookmark--shared-position checkout)))
                       (and position
                            (equal identity
                                   (workspace-bookmark--memoised-identity
                                    (nth 0 position) (nth 1 position))))))
                   (workspace-bookmark--checkouts-in-view))))))
#+end_src

** Cross-module interface: the canonical checkouts in view

=workspace-bookmark-canonical-checkouts-in-view= is this module's ONE
public discovery function, and a CROSS-MODULE INTERFACE: the
git-worktrees repository picker (=config/workspaces/git-worktrees.org=,
=jf/workspace--worktree-git-derived-candidates= and
=jf/workspace--worktree-canonical-only=) calls it.  Beside it stands
one public SCOPE, =workspace-bookmark-call-with-discovery-memo=, which
the picker wraps around its whole candidate build (below).  The picker
calls nothing else in this module.  Everything with a =--= in its name
stays private and may change freely.

STABILITY PROMISE.  The name, the calling convention and the meaning
below are a contract.  Changing any of them means changing
=git-worktrees.org= in the same commit.  The consumer guards the call
with =fboundp= at CALL time and never =require=s this module (a
magit-dependent module must not depend on a bookmark module), so a
rename would not fail loudly: the picker would silently lose its
git-derived source.  The tripwire is =config/workspaces/test/git-worktrees-spec.el=
§ "git-derived repo candidates", which loads this module for real.

- =(workspace-bookmark-canonical-checkouts-in-view)= — the canonical
  checkouts of the repositories of the checkouts in view
  (=--checkouts-in-view=), in view order.
- =(workspace-bookmark-canonical-checkouts-in-view CHECKOUTS)= — the
  same for the list CHECKOUTS instead of the checkouts in view.
  =CHECKOUTS= given as nil means NONE, not "the default": the result is
  nil.  (git-worktrees passes magit's repository list here, so that
  magit's candidates are admitted by the same predicate.)
- Every element passed =workspace-bookmark--offerable-canonical-p=: a
  repository's main worktree, owned by no workspace, and holding its
  work tree.  Never a workspace's checkout, a linked worktree, a husk,
  or a =core.worktree= directory.
- Absolute directory names with a trailing slash, as git spells them;
  no two name the same directory.
- Never signals in normal operation: every step returns nil on failure.
  The consumer still wraps the call in an error barrier, because a bug
  here must not break worktree creation.

#+begin_src emacs-lisp
(cl-defun workspace-bookmark-canonical-checkouts-in-view
    (&optional (checkouts nil checkouts-given))
  "Return the canonical checkouts of the repositories in view.

With no argument, the repositories in view are those of the checkouts
in view (`workspace-bookmark--checkouts-in-view'): the current
workspace's, then every other registered workspace's, then
`jf/emacs-dir'.  With CHECKOUTS, a list of directories, they are the
repositories of CHECKOUTS instead; CHECKOUTS nil yields nil.

Each element is its repository's main worktree and passed
`workspace-bookmark--offerable-canonical-p': never a workspace-owned
checkout, a linked worktree, or a directory that is not a main
worktree.  The value is in order of first appearance, de-duplicated by
file identity, each an absolute directory name with a trailing slash.

This is a CROSS-MODULE INTERFACE, called from git-worktrees.el behind a
call-time `fboundp' guard; its name, calling convention and meaning are
stable.  Never signals in normal operation."
  (workspace-bookmark--canonical-checkouts-among
   (if checkouts-given
       checkouts
     (workspace-bookmark--checkouts-in-view))))
#+end_src

*One scope for several calls.*  The picker has two sources — the
checkouts in view, and magit's repository list — and asks the function
above once for each, so that each keeps its own error barrier and its
own fallback when this module is absent.  Each call is its own
discovery call, so a repository reached from both (a main clone under
=~/src= whose linked worktree sits in a workspace home: the everyday
shape) would pay its canonical test twice.
=workspace-bookmark-call-with-discovery-memo= makes the two calls ONE
discovery call without merging them: it calls a function inside one
discovery memo and returns its value, and every call of the entry point
made inside shares that memo.  The entry point's name, calling
convention and meaning are unchanged, and a caller that does not use the
scope gets exactly the answers it got before.

The scope's promise of equal answers has a PRECONDITION, stated in its
docstring: nothing may change the repositories while it is open.  A
nested discovery shares the outer memo rather than starting its own
(=workspace-bookmark--with-discovery-memo=), so inside the scope EVERY
discovery joins it — the resolver's, a workspace's checkouts — not
only the entry point; a checkout added inside the scope and then asked
about would be answered from the listing taken before the add.  So the
function run in the scope must not create, move or remove a checkout or
change a repository's configuration, and must not wait for user input.
The git-worktrees picker wraps only its pure candidate build, never the
prompt that follows.  The one place this module adds a checkout and then
asks again, =workspace-bookmark--add-worktree-and-replan=, does not
rely on its caller: it re-resolves in a fresh memo.

It is a FUNCTION taking a function, not a macro, because the consumer
reaches it across a soft edge: git-worktrees loads before this module
and guards the call with =fboundp= at call time, and a macro the
consumer's code was read without would have been expanded as a plain
function call.  Same stability promise as the entry point; the
tripwire is the same spec, which now permits exactly these two public
names.

#+begin_src emacs-lisp
(defun workspace-bookmark-call-with-discovery-memo (function)
  "Call FUNCTION with no arguments as ONE discovery call; return its value.

Every call of `workspace-bookmark-canonical-checkouts-in-view' made
while FUNCTION runs shares one discovery memo, so a repository those
calls reach more than once is asked each git question once.  So does
every other discovery made while FUNCTION runs, not only that entry
point.  The memo is dropped when FUNCTION returns or exits non-locally;
nothing survives the call.

Precondition: answers are exactly those the calls give on their own
only while nothing changes the repositories inside the scope.
FUNCTION must not create, move or remove a checkout or change a
repository's configuration, and must not wait for user input (while
it waits, anything may change); a question asked again after such a
change is answered from the memo, as before it.

This is a CROSS-MODULE INTERFACE, called from git-worktrees.el behind a
call-time `fboundp' guard; its name, calling convention and meaning are
stable."
  (workspace-bookmark--with-discovery-memo
    (funcall function)))
#+end_src

* Resolution

Given a bookmark record and a workspace name, which location — if any —
does the record mean in that workspace?  =workspace-bookmark--resolve=
answers with exactly one outcome from a closed set and never acts on
it.  It is a DECISION FUNCTION: it reads the stamp and asks the
discovery functions above, which run git, but it opens no buffer, asks
the user nothing and reports nothing
(=register/vocabulary/bookmark-resolution-outcome=, producer
discipline).  What to do with each outcome — open, report, prompt — is
the jump seam's and the prompts' business.  Keeping the resolver free of
interaction is what makes the awkward outcomes testable: forcing
=no-clone= or a failing git against real repositories is fiddly, and
against a mocked discovery function it is one =cl-letf=.

The whole capability exists so that no path silently opens a file the
user did not ask for (=register/invariant/no-silent-wrong-file-open=).
Here that means one rule above all: *the stored absolute =filename= is
used by exactly one outcome, =non-portable=*, for which it is today's
answer.  Every other outcome is computed from the stamped coordinates
and the checkouts discovery finds, and a stale or foreign absolute path
cannot leak into it.

** The closed set of outcomes

Six outcomes.  The set is closed so that a new one is a deliberate
two-place change (this constant and the resolver), never a stray symbol
that a caller might treat as "just open the stored path".  It mirrors
=workspace--valid-reincarnation-steps= in =layouts.el=.

| outcome         | =:path=                                   | meaning                                                            |
|-----------------+-------------------------------------------+--------------------------------------------------------------------|
| =resolved=      | the location in the workspace's checkout  | the only outcome that may be opened without asking                 |
| =not-on-branch= | nil                                       | the checkout exists, the relpath does not: report, NEVER visit     |
| =missing-repo=  | the candidate under the canonical checkout, or nil | the workspace holds no checkout; the caller may OFFER a read-only view |
| =no-clone=      | nil                                       | no checkout of the repository is in view                           |
| =non-portable=  | the record's stored =filename=            | no usable stamp: stock behaviour                                   |
| =ambiguous=     | nil                                       | more than one candidate checkout; =:candidates= lists them, nothing is chosen |

=ambiguous= is the sixth (user decision, 2026-09-26).  Discovery
reports ambiguity rather than hiding it — two sibling worktrees of one
repository in a home, or two separate main clones in view — and a
resolver that took the first would be choosing a branch by directory
order.  Like =not-on-branch=, it must be reported and nothing opened.

The value is always the same six-key plist, whatever the outcome:

#+begin_example
(:outcome OUTCOME :path PATH-OR-NIL :identity ID-OR-NIL
 :relpath REL-OR-NIL :candidates CHECKOUTS-OR-NIL
 :checkout CHECKOUT-OR-NIL)
#+end_example

=:identity= and =:relpath= are the stamped coordinates, nil for
=non-portable= (the record has none a caller may trust).  =:candidates=
is nil except for =ambiguous=.  =:checkout= names the checkout the
relpath was anchored under — the workspace's for =resolved= and
=not-on-branch=, the canonical checkout for =missing-repo= — and is nil
for the rest.  It is there so that a caller offering =add-worktree= for
a =missing-repo= knows which repository to add without running
discovery a second time, which is a full in-view scan that could answer
differently.  =:candidates= is not overloaded for this: being nil
outside =ambiguous= is what makes it an unambiguous marker.  The plist
is built in one place,
=workspace-bookmark--outcome=, which refuses a symbol outside the set.
Inside the resolver that refusal is caught like any other error and
becomes a degraded outcome, so a typo in a future branch cannot escape
as an unknown symbol.

#+begin_src emacs-lisp
(defconst workspace-bookmark--valid-outcomes
  '(resolved not-on-branch missing-repo no-clone non-portable ambiguous)
  "Closed set of bookmark-resolution outcomes.
`workspace-bookmark--resolve' returns exactly one of these.  Adding a
member is a deliberate change here AND in the resolver, and in every
caller that dispatches on the outcome.")

(defun workspace-bookmark--valid-outcome-p (outcome)
  "Return non-nil when OUTCOME is a member of `workspace-bookmark--valid-outcomes'."
  (and (symbolp outcome)
       (memq outcome workspace-bookmark--valid-outcomes)
       t))

(cl-defun workspace-bookmark--outcome
    (outcome &key path identity relpath candidates checkout)
  "Return the resolution plist for OUTCOME.

The plist always carries the six keys :outcome, :path, :identity,
:relpath, :candidates and :checkout, in that order.  Signals an error
when OUTCOME is not in `workspace-bookmark--valid-outcomes'."
  (unless (workspace-bookmark--valid-outcome-p outcome)
    (error "Not a bookmark-resolution outcome: %S" outcome))
  (list :outcome outcome :path path :identity identity
        :relpath relpath :candidates candidates :checkout checkout))
#+end_src

** Reading the stamp

A record's stamp is usable only when ALL THREE properties are present
and meaningful (=register/shape/portable-bookmark-coordinates=):

- the identity is a non-empty string;
- the format version is one this module knows — only version 1 exists,
  and a record stamped under a later meaning must not be misread as
  this one;
- the relpath is a non-empty string whose spelling stays inside the
  checkout it is anchored under.

Anything else — no stamp, two of three, an unknown version, a
non-string — is =non-portable=, decided before any git runs.  So is a
value that is not a record at all: a resolver handed a string would
otherwise look the name up in the live bookmark list, which is not a
decision over the record it was given.

*A relpath may not escape.*  Stamping only ever writes what git
reports, and git never reports =..= or an absolute path; a record
carrying one has been hand-edited or synced from somewhere else.  Such
a relpath re-anchored under a checkout would name a file outside it —
another checkout, or anywhere at all — so it is refused outright:

- an absolute relpath (=/etc/hosts=, =~/x=, =~user/x=: everything
  =file-name-absolute-p= accepts, which is exactly what
  =expand-file-name= would take as a new root);
- any component that is exactly =..= (a name such as = ..= with a
  space is an ordinary name);
- a NUL byte, which no file name can hold.

A leading =~= that =file-name-absolute-p= rejects (=~foo= when there is
no user =foo=) is an ordinary name: =expand-file-name= anchors it under
the checkout, exactly as the stamp's own verification did.

*Confinement is lexical, and only lexical* (user decision DD-16,
2026-09-26).  A relpath whose spelling stays inside the checkout
resolves to =<checkout>/<relpath>= whatever the links on that branch
point at.  A tracked =link-rel -> ../shared/x.txt=, or =sub/f.txt= on a
branch where =sub= is a link out of the checkout, is what the checkout's
own branch says it is: visiting that spelling by hand opens exactly the
same thing, and the resolver may not know better.  Following links to
decide "really inside" was tried and rejected — the record that failed
the test was a VALID stamp, and degrading it to =non-portable= handed
back the stored =filename=, another workspace's copy: the very defect
this module exists to remove.  So the three refusals above are the whole
confinement test, and a valid stamp never resolves =non-portable=.

*Relpath forms.*  The relpath is used VERBATIM — never trimmed, never
re-spelled — because that is how the stamp stored it:

| stored       | means                                   | anchored under =CO/=  |
|--------------+-----------------------------------------+-----------------------|
| =./=         | the repository root (=workspace-bookmark--root-relpath=) | =CO/=                 |
| =lisp/=      | a directory (git's =--show-prefix=, trailing slash) | =CO/lisp/=            |
| =lisp/foo.el= | a file                                  | =CO/lisp/foo.el=      |
| = lead.txt=, =trail.txt = | a file whose name has leading or trailing whitespace | =CO/ lead.txt=, =CO/trail.txt = |

The trailing slash is also the record's KIND: a relpath ending in =/=
names a directory, any other a file.  A location whose kind on this
branch differs (a directory where a file was bookmarked, or the
reverse) is not the thing that was bookmarked, and resolves as
=not-on-branch=.

#+begin_src emacs-lisp
(defconst workspace-bookmark--known-format-versions
  (list workspace-bookmark-format-version)
  "The stamp-format versions `workspace-bookmark--resolve' can read.
A record stamped under any other version resolves `non-portable'.")

(defun workspace-bookmark--confined-relpath-p (relpath)
  "Return non-nil when RELPATH is a relpath that stays inside its checkout.

RELPATH must be a non-empty string that is not absolute (in the sense
of `file-name-absolute-p'), has no component that is exactly \"..\",
and holds no NUL byte.  This test of spelling is the WHOLE confinement
test (DD-16): `workspace-bookmark--anchor' decides the LOCATION by that
spelling, and asks the filesystem — which follows links — only whether
something of RELPATH's kind is present there."
  (and (stringp relpath)
       (not (string-empty-p relpath))
       (not (string-search "\0" relpath))
       (not (file-name-absolute-p relpath))
       (not (member ".." (split-string relpath "/")))))

(defun workspace-bookmark--stamped-coordinates (record)
  "Return the (IDENTITY . RELPATH) stamped on RECORD, or nil.

Non-nil only when RECORD is a bookmark record (a cons) carrying all
three stamped properties: a non-empty string identity, a format version
in `workspace-bookmark--known-format-versions', and a relpath that
satisfies `workspace-bookmark--confined-relpath-p'.  Runs no
subprocess.  Never signals."
  (and (consp record)
       (condition-case nil
           (let ((identity (bookmark-prop-get
                            record workspace-bookmark-repo-property))
                 (relpath (bookmark-prop-get
                           record workspace-bookmark-relpath-property))
                 (version (bookmark-prop-get
                           record workspace-bookmark-format-property)))
             (and (stringp identity)
                  (not (string-empty-p identity))
                  (memql version workspace-bookmark--known-format-versions)
                  (workspace-bookmark--confined-relpath-p relpath)
                  (cons identity relpath)))
         (error nil))))

(defun workspace-bookmark--stored-filename (record)
  "Return RECORD's stored `filename' when it is a string, else nil.
Never signals."
  (and (consp record)
       (condition-case nil
           (let ((filename (bookmark-prop-get record 'filename)))
             (and (stringp filename) filename))
         (error nil))))
#+end_src

** Re-anchoring a relpath

A confined relpath is anchored under a checkout with =expand-file-name=
— the same call the stamp used to verify it, so everything the stamp
accepted anchors identically — and then checked against the DISK for
two things only:

1. The anchored path must exist.  If it does not, the relpath is not on
   this branch: =absent=.
2. Its kind must match the relpath's (see "Relpath forms"): otherwise
   =absent=.

Whether the path is "really" inside the checkout is NOT asked.  The
spelling is inside — =workspace-bookmark--confined-relpath-p= saw to
that — and by DD-16 the spelling is the answer.  A link that leaves the
checkout resolves to its in-checkout spelling, a link that stays inside
resolves the same way, and a dangling link is =absent=: nothing exists
there, and =not-on-branch= opens nothing.

The anchoring itself is checked once: the expanded path must start with
the checkout, or be the checkout (which a hand-edited =.= anchors to).
A confined relpath cannot fail this, so a failure is a programming
error and SIGNALS.  The resolver's barrier turns the signal into
=no-clone=, an outcome that opens nothing; it never becomes a location.

#+begin_src emacs-lisp
(defun workspace-bookmark--anchor (relpath checkout)
  "Anchor RELPATH under CHECKOUT and check it against the disk.

RELPATH must already satisfy `workspace-bookmark--confined-relpath-p'.
Returns one of:

  (present . PATH)  PATH exists and is a directory exactly when RELPATH
                    ends in \"/\";
  (absent)          nothing of RELPATH's kind exists at PATH.

PATH is RELPATH expanded against CHECKOUT's directory name, and is the
answer by its spelling; whether something of RELPATH's kind exists
there is asked of the filesystem, which follows links, so a link that
points out of CHECKOUT still answers PATH and a dangling link is absent
\(DD-16).  Signals when PATH does not start with CHECKOUT, which a
confined RELPATH cannot produce."
  (let* ((root (file-name-as-directory checkout))
         (path (expand-file-name relpath root)))
    (unless (or (string-prefix-p root path)
                (string-equal path (directory-file-name root)))
      (error "Relpath %S anchors outside %s: %s" relpath root path))
    (cond
     ((not (file-exists-p path)) (list 'absent))
     ((not (eq (and (string-suffix-p "/" relpath) t)
               (and (file-directory-p path) t)))
      (list 'absent))
     (t (cons 'present path)))))
#+end_src

** The decision

First match wins.  The order is part of the contract, because the
predicates overlap: a workspace can hold a checkout AND a canonical
checkout can be in view, and only the order keeps the answer
deterministic.

| # | condition                                                         | outcome          |
|---+-------------------------------------------------------------------+------------------|
| 1 | not a record, or no usable stamp (see "Reading the stamp")         | =non-portable=   |
| 2 | the workspace holds exactly ONE checkout of the identity           | =resolved= / =not-on-branch= |
| 3 | the workspace holds TWO OR MORE                                    | =ambiguous=      |
| 4 | the workspace holds none, exactly ONE canonical checkout in view   | =missing-repo=   |
| 5 | the workspace holds none, TWO OR MORE canonical checkouts in view  | =ambiguous=      |
| 6 | nothing in view                                                    | =no-clone=       |

The discovery functions asked —
=workspace-bookmark--workspace-checkouts= and
=workspace-bookmark--canonical-checkouts-for-identity= — return
lists, and uniqueness is read off the list HERE: a helper that answered
nil for both "none" and "several" would turn ambiguity into
=missing-repo= or =no-clone=, which is why no such helper exists.

Rows 2 and 4 re-anchor the relpath by its spelling (see "Re-anchoring
a relpath") and name the checkout they anchored under in =:checkout=.
A valid stamp NEVER resolves =non-portable=: only row 1 does, and only
for a stamp that is absent, partial, of an unknown version, or
lexically escaping.  In row 4 a relpath that is absent under the canonical checkout
still answers =missing-repo= — the repository really is missing from
the workspace — but with =:path= nil: there is nothing to offer as a
read-only view, and the caller must not visit a path that does not
exist.

WORKSPACE-NAME nil (no current workspace) holds no checkout, so the
answer comes from rows 4–6.

*Errors never propagate.*  This code runs inside a bookmark jump, a
core Emacs interaction, on behalf of a peripheral feature.  The
discovery functions already return nil rather than signal; the resolver
catches anyway, and maps by what is known at the point of failure:

- the identity is known (the stamp was read) → =no-clone=, with
  =:identity= and =:relpath= filled in and =:path= nil;
- it is not → =non-portable=.

The barrier also catches the resolver's own programming errors — an
anchoring answer it does not recognise, a relpath that anchored outside
its checkout — and those, too, come out as =no-clone=.  The arms that
dispatch on an anchoring answer have no catch-all that returns a
location: an answer nobody wrote code for signals, and so opens nothing.

#+begin_src emacs-lisp
(defun workspace-bookmark--resolve-anchored (outcome relpath checkout identity)
  "Anchor RELPATH under CHECKOUT and return the outcome for it.

OUTCOME is `resolved' (CHECKOUT is the workspace's) or `missing-repo'
\(CHECKOUT is the canonical checkout).  A present location gives OUTCOME
with its :path.  An absent one gives `not-on-branch' for `resolved',
and `missing-repo' with a nil :path for `missing-repo'.  Either way
:checkout is CHECKOUT.  Any other anchoring answer is a programming
error and signals: nothing here returns a location it did not anchor."
  (let ((anchored (workspace-bookmark--anchor relpath checkout)))
    (pcase (car anchored)
      ('present
       (workspace-bookmark--outcome outcome :path (cdr anchored)
                                    :identity identity :relpath relpath
                                    :checkout checkout))
      ('absent
       (workspace-bookmark--outcome (if (eq outcome 'resolved)
                                        'not-on-branch
                                      outcome)
                                    :identity identity :relpath relpath
                                    :checkout checkout))
      (_ (error "Unknown anchoring answer: %S" anchored)))))

(defun workspace-bookmark--non-portable (record)
  "Return the `non-portable' outcome for RECORD, with its stored filename."
  (workspace-bookmark--outcome
   'non-portable :path (workspace-bookmark--stored-filename record)))

(defun workspace-bookmark--resolve-coordinates (identity relpath workspace-name)
  "Decide the outcome for the stamped IDENTITY and RELPATH in WORKSPACE-NAME.
See `workspace-bookmark--resolve'.  May signal; the caller catches.

The whole decision is ONE discovery call
\(`workspace-bookmark--with-discovery-memo'): the current workspace's
checkouts, which both plural discovery functions examine, are
positioned once.  Nothing between the two calls can change the layout,
so the outcome is the same as with two."
  (workspace-bookmark--with-discovery-memo
    (let ((checkouts (workspace-bookmark--workspace-checkouts
                      identity workspace-name)))
      (cond
       ((and checkouts (null (cdr checkouts)))
        (workspace-bookmark--resolve-anchored
         'resolved relpath (car checkouts) identity))
       (checkouts
        (workspace-bookmark--outcome 'ambiguous :identity identity
                                     :relpath relpath :candidates checkouts))
       (t
        (let ((canonical (workspace-bookmark--canonical-checkouts-for-identity
                          identity)))
          (cond
           ((and canonical (null (cdr canonical)))
            (workspace-bookmark--resolve-anchored
             'missing-repo relpath (car canonical) identity))
           (canonical
            (workspace-bookmark--outcome 'ambiguous :identity identity
                                         :relpath relpath :candidates canonical))
           (t
            (workspace-bookmark--outcome 'no-clone :identity identity
                                         :relpath relpath)))))))))

(defun workspace-bookmark--resolve (record workspace-name)
  "Decide where bookmark RECORD points in workspace WORKSPACE-NAME.

RECORD is a bookmark record (NAME . ALIST); WORKSPACE-NAME a registered
workspace's name, or nil for none.  Returns the plist

  (:outcome OUTCOME :path PATH :identity ID :relpath REL
   :candidates CHECKOUTS :checkout CHECKOUT)

where OUTCOME is one of `workspace-bookmark--valid-outcomes', decided
first-match-wins:

  `non-portable'   RECORD carries no usable stamp; :path is its
                   stored `filename' (the ONLY outcome that uses it).
  `resolved'       WORKSPACE-NAME holds exactly one checkout of the
                   identity and the relpath exists there; :path is it,
                   :checkout that checkout.
  `not-on-branch'  that one checkout lacks the relpath; :path nil,
                   :checkout that checkout.
  `ambiguous'      WORKSPACE-NAME holds several checkouts, or holds
                   none and several canonical checkouts are in view;
                   :candidates lists them, :path nil.
  `missing-repo'   WORKSPACE-NAME holds none and exactly one canonical
                   checkout is in view; :checkout is it, and :path is
                   the relpath under it when it exists there, else
                   nil.  A candidate to offer, never a location to act
                   on.
  `no-clone'       nothing in view; :path nil.

:checkout is nil for every outcome not listed with one.  A relpath
that would leave its checkout by its spelling (`..', an absolute name)
resolves `non-portable'; one that leaves it only through a symbolic
link resolves by its spelling, as visiting it by hand would (DD-16).
The stamp is not checked against the stored `filename' (see the Org
prose on stale stamps).

This is a decision function: it runs git through the discovery
functions but never visits a file, displays a buffer, reads input or
writes to the echo area.  It never signals: an error once the identity
is known gives `no-clone', before that `non-portable'."
  (condition-case nil
      (let ((coordinates (workspace-bookmark--stamped-coordinates record)))
        (if (not coordinates)
            (workspace-bookmark--non-portable record)
          (condition-case nil
              (workspace-bookmark--resolve-coordinates
               (car coordinates) (cdr coordinates) workspace-name)
            (error (workspace-bookmark--outcome
                    'no-clone :identity (car coordinates)
                    :relpath (cdr coordinates))))))
    (error (workspace-bookmark--non-portable record))))
#+end_src

** Known limitation: stale stamps

The stamp is TRUSTED; it is not checked against the record's stored
=filename= (user decision, 2026-09-24, ask 5 of cycle-1789935943).
=bookmark-relocate= — and any hand edit, or a bookmark file synced from
elsewhere — rewrites =filename= but leaves the three stamped properties
pointing at the OLD location.  From another checkout such a record
resolves to its pre-relocation file.  That is a known limitation of
this slice, stated here because it is accepted, not fixed.  The planned
answer is to detect broken stamps ON READ (for example: honour a stamp
only when =filename= ends with the stamped relpath) — see
=.tasks/portable-bookmarks-stale-stamp-detection.md=.  No consistency
check is made here until that task is taken up.

* Advice installation

Installation AND matching removal are both defined so the module can be
reloaded during development without stacking advice.  =advice-add= does
not duplicate an advice that names the same function symbol, so
=workspace-bookmark-install-advice= is idempotent; the explicit removal
exists for =M-x workspace-bookmark-remove-advice= during development and
for tests that need stock bookmark behaviour.

#+begin_src emacs-lisp
(defun workspace-bookmark-install-advice ()
  "Install the two portable-bookmark advice seams.  Idempotent."
  (interactive)
  (advice-add 'bookmark-make-record :filter-return
              #'workspace-bookmark--stamp-record)
  (advice-add 'bookmark-handle-bookmark :around
              #'workspace-bookmark--handle-bookmark-advice))

(defun workspace-bookmark-remove-advice ()
  "Remove the two portable-bookmark advice seams, restoring stock behaviour."
  (interactive)
  (advice-remove 'bookmark-make-record
                 #'workspace-bookmark--stamp-record)
  (advice-remove 'bookmark-handle-bookmark
                 #'workspace-bookmark--handle-bookmark-advice))

(workspace-bookmark-install-advice)
#+end_src

* Module Initialization

The feature symbol is =workspace-portable-bookmarks= while the file is
=portable-bookmarks.el=.  That is the package's established convention,
not an accident: every sibling in =config/workspaces/= provides a
=workspace-=-prefixed feature whose name differs from its basename
(=data-model.el= → =workspace-data-model=, =tabs.el= → =workspace-tabs=,
=git-worktrees.el= → =workspace-git-worktrees=).  The prefix keeps the
feature namespace collision-free; the basename stays short because the
directory already says "workspaces".

(provide 'workspace-portable-bookmarks)

#+end_src
