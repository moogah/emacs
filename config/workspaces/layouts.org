User-facing layout commands plus auto-save on context switch
(design.md §D7).  Layouts are window configurations scoped to a
workspace, named, and restorable.  In MVP every layout-group holds
exactly one layout; the schema's =:layouts= list is reserved for the
deferred history feature (design.md §D5).

* Window-state serialization

We serialize per-tab window configuration with =window-state-get= /
=window-state-put=.  This is the same primitive tab-bar uses
internally for per-tab window state (=tab-bar.el='s =tab-bar--tab=),
and is the right granularity for our case: one tab's window tree,
no frame-level side effects.

The =workspace--capture-frameset= / =workspace--restore-frameset=
names are kept for historical compatibility within the package; the
underlying data is a window-state form, not a frameset struct.

** Extended persistent parameters

Emacs's default =window-persistent-parameters= is conservative: side
windows (=window-side=, =window-slot=), preserved-size constraints,
=no-other-window= / =no-delete-other-windows= flags, and explicit
mode-line/header-line/tab-line overrides are NOT persisted by
=window-state-get= unless the parameter list is extended.

Users with treemacs, vterm, compilation, or other side-window-driven
layouts otherwise lose those properties on workspace restore — the
windows come back, but as ordinary windows rather than dedicated side
windows.

We extend the persistent-parameters list for the duration of capture
and restore.  This matches the pattern activities.el uses (see
=activities-window-persistent-parameters=, =activities.el:244-257=).

The =writable= value tells =window-state-get= to serialize the
parameter via =prin1= rather than store the raw value, so the result
round-trips through =read=.

#+begin_src emacs-lisp
(defcustom workspace-window-persistent-parameters
  '((header-line-format . writable)
    (mode-line-format . writable)
    (tab-line-format . writable)
    (no-other-window . writable)
    (no-delete-other-windows . writable)
    (window-preserved-size . writable)
    (window-side . writable)
    (window-slot . writable))
  "Window parameters preserved across workspace capture/restore.
Extends `window-persistent-parameters' for the duration of
`workspace--capture-frameset' and `workspace--restore-frameset'.

Each entry is `(PARAMETER . writable)' where `writable' tells
`window-state-get' to serialize the value via `prin1' so it survives
the round trip through the on-disk eld form."
  :type '(alist :key-type symbol :value-type symbol)
  :group 'workspaces)
#+end_src

** Readable-by-construction serialization

=window-state-get … 'writable= emits writable-parameter VALUES
verbatim — it does *not* sanitize a live Emacs object embedded inside a
parameter value.  Two parameters in our persistent set can carry such
objects:

- =window-preserved-size= holds a =(BUFFER DIR SIZE)= triple whose first
  element is a live buffer object.  Once that buffer is killed the slot
  still references the dead buffer, and =prin1= of a buffer object emits
  the unreadable =#<buffer …>= syntax.  A single such object in the
  on-disk =.eld= makes the whole state file unreadable — a stale
  preserved-size constraint corrupts an otherwise good save.
- a buffer's =bookmark-make-record= result can embed a marker, buffer, or
  natively-compiled subr (the =help-mode= =bug#56643= class), which is
  likewise unreadable.

The canonical fix (=activities.el='s =activities-window-parameters-
translators=, =burly.el='s =burly-window-parameters-translators=) is a
per-parameter serialize/deserialize translator pass over the leaf tree,
plus a belt-and-suspenders scrub of bookmark-record props.  We already
own the leaf walker, so the translator table slots in cleanly.  This
makes the serialized form readable *by construction*; the write-time
=prin1=→=read= assert (persistence.el, a separate task) is the backstop
that should never fire once the translators are in place.

The predicate below is the single shared notion of "unreadable" — it
is reused by the bookmark scrub here and by the write-time assert in
persistence.el (which already requires =workspace-layouts=).  Keeping
one definition avoids divergent notions of readability.

#+begin_src emacs-lisp
(defun workspace--unreadable-object-p (obj)
  "Return non-nil if OBJ cannot be reconstructed by `read'.
Covers the live-object classes that `prin1' renders as the
unreadable =#<…>= syntax: buffers, markers, overlays, frames,
windows, processes, and non-symbol functions (subrs and closures).
Symbols that happen to be `functionp' (named functions) are
readable and return nil.  Total over any input."
  (or (bufferp obj)
      (markerp obj)
      (overlayp obj)
      (framep obj)
      (windowp obj)
      (processp obj)
      (and (not (symbolp obj)) (functionp obj))))
#+end_src

The translator table is keyed by window-parameter symbol; each entry
carries a =serialize= and a =deserialize= function over that
parameter's value.  =window-preserved-size= is the only buffer-bearing
parameter in the current persistent set, so it is the only seed.  The
table is the one place to extend when a future buffer/marker-bearing
parameter is added.

The serializer replaces the live buffer with its name string (or nil if
the buffer is already dead); the deserializer resolves the name back to
a live buffer via =get-buffer= (or nil if the buffer is gone from the
session), preserving the =(VALUE DIR SIZE)= triple shape across the
round trip.  For a live buffer the value round-trips to the same buffer
by name.

#+begin_src emacs-lisp
(defvar workspace-window-parameter-translators
  `((window-preserved-size
     (serialize . ,(pcase-lambda (`(,buffer ,dir ,size))
                     (list (and (bufferp buffer) (buffer-name buffer))
                           dir size)))
     (deserialize . ,(pcase-lambda (`(,name ,dir ,size))
                       (list (and name (get-buffer name)) dir size)))))
  "Per-window-parameter serialize/deserialize translators.
An alist `(PARAM . ((serialize . FN) (deserialize . FN)))'.  FN
receives a single argument — the parameter's value as stored in a
window-state leaf's `parameters' map — and returns a replacement
value.  Modelled on `activities-window-parameters-translators' and
`burly-window-parameters-translators'.

`window-preserved-size' carries a `(BUFFER DIR SIZE)' triple; the
serializer replaces BUFFER with its name (readable), the deserializer
resolves the name back to a live buffer.  Add an entry here for any
future window parameter whose value embeds a live, unreadable object.")
#+end_src

** Window-state leaf walker

The =window-state= form is a recursively nested tree of
=(leaf . ATTRS)= nodes interleaved with split-direction keywords and
window-tree branches.  To translate every leaf (e.g. to embed a
=workspace-buffer= struct in its =parameters= map, or to reincarnate
the buffer on restore) we walk the tree with =pcase= and apply a
caller-provided leaf-translation function in place.

Two variants:

- =workspace--window-state-walk-leaves= — pure recursive walker that
  takes a leaf-translation function and returns a fresh tree with
  each =(leaf . attrs)= node replaced by =(funcall func leaf)=.
- =workspace--window-state-serialize= /
  =workspace--window-state-deserialize= — apply the walker with leaf
  translators that add (resp. consume) the =workspace-buffer= entry
  on each leaf's =parameters= map.

*** Edge case: one-window frame

A frame with a single window does not wrap its leaf in a multi-window
tree; the top-level form *is* a =(leaf . attrs)= node (or rather, the
elements following the =leaf= keyword are the window-attrs).  We
detect this with =cl-position 'leaf state=: if non-nil, we treat the
form as a one-window frame and translate the leaf in place,
preserving any prefix elements (e.g. the =leaf= keyword's
surrounding bookkeeping) before it.

Modelled on =activities--mapcar-window-state-leafs= and
=activities--window-serialized= (=activities.el:527-711=).

#+begin_src emacs-lisp
(defun workspace--window-state-walk-leaves (state func)
  "Return a fresh window-state like STATE with FUNC applied to each leaf.
FUNC is called with a `(leaf . attrs)' form and must return a
replacement form (typically a fresh leaf with translated attrs).

Handles three cases per node:
- `(leaf . _attrs)' — apply FUNC.
- atom — return as-is.
- `(_key . atom)' — return as-is (split-direction keywords etc).
- proper list — recurse on its members.

The one-window-frame edge case (top-level form is itself a leaf,
not wrapped in a tree) is detected by `cl-position 'leaf' on the
form; if non-nil, the leaf-bearing sublist is translated and the
prefix before it preserved."
  (cl-labels
      ((walk (node)
         (pcase node
           (`(leaf . ,_attrs) (funcall func node))
           ((pred atom) node)
           (`(,_key . ,(pred atom)) node)
           ((pred proper-list-p)
            (if-let ((leaf-pos (cl-position 'leaf node)))
                ;; One-window-frame: prefix elements + translated leaf.
                (append (cl-subseq node 0 leaf-pos)
                        (funcall func (cl-subseq node leaf-pos)))
              (mapcar #'walk node)))
           (_ node))))
    (walk state)))
#+end_src

** Buffer reincarnation: workspace-buffer serialize / deserialize

A reincarnation record (the =workspace-buffer= struct from
data-model.el) is built by =workspace--serialize-buffer= at save time
and consumed by =workspace--deserialize-buffer= at restore.  The
deserializer implements a four-step fallback chain (design.md §D2):

1. Bookmark restore via the buffer's registered bookmark handler.
2. Filename fallback via =find-file-noselect=.
3. Name fallback via =get-buffer= for live buffers still in the
   session.
4. Error buffer — visible, named, harmless.  The window slot is
   never left empty.

Each fallback step is guarded with =condition-case= so one
unrecoverable record (e.g. the =help-mode= =bug#56643=
natively-compiled-subr issue) does not abort the whole restore.

*A decline is not a failure.*  Step 1 tells two things apart that
both leave the probe buffer unchanged.  A bookmark handler that
FAILS — a read-back error, a missing handler, a =file-error= — has
said nothing about the buffer, and the chain falls through to the
filename.  A handler that DECLINES has made a decision the user is
meant to see: it signalled =workspace-restore-declined=, the one
condition core owns for that decision (data-model.org, "The decline
condition").  For a declined leaf the
chain skips steps 2 AND 3 and goes straight to the error buffer,
which carries the handler's reason.  The saved filename is the
absolute path the buffer had when the layout was captured, and a
handler that refused to open its bookmark's location has, in
general, refused to open THAT path (a bookmark resolved against
another checkout says "not on this branch", and the stored filename
is the other checkout's copy of the file); a live buffer of the same
NAME is, in the same situations, the same wrong file already open.
Falling back to either would turn "report and open nothing" into
"open the stored path quietly", which is the shape
=register/invariant/no-silent-wrong-file-open= exists to remove.

How step 1 tells the three answers apart, and nothing else:

- a buffer other than the probe's — the jump landed: step 1 wins;
- =workspace-restore-declined= out of the jump — DECLINED: the gate
  above, with the reason taken from the condition's datum;
- any other =error= (a plain =user-error= included), or no signal and
  no buffer change — FAILED: fall through to step 2.  =quit= is
  neither; C-g aborts the restore.

The dispatch has one arm per answer and SIGNALS for any other value,
so a result nobody wrote an arm for can never reach the filename step
(=register/invariant/no-silent-wrong-file-open=: a catch-all arm
errors or does nothing, it never opens).  The decline is keyed on the
owned condition alone, not on =user-error=, its parent: stock handlers
signal =user-error= for reasons of their own (=Info-find-file='s "Info
file ... does not exist; consider installing it"), and such a leaf must
keep restoring through its stored filename or the live buffer of its
name, as it did before the gate existed.  A third-party handler that
wants a decline's treatment signals =workspace-restore-declined= and
gets the same reason buffer.

*Asking is not declining.*  Step 1 does NOT suppress interaction.  A
stock handler that asks while visiting a leaf — =find-file-noselect='s
large-file question, which goes through =read-multiple-choice=; the
unsafe local variables query; =vc-follow-symlinks= — asks exactly as it
would on any other visit, and the leaf is restored with the answer.
Binding =inhibit-interaction= here would be wrong on two counts: it
would silently change what every handler does, and in Emacs 30.2
=read-multiple-choice= swallows the =inhibited-interaction= signal and
re-issues its prompt forever, so any leaf over
=large-file-warning-threshold= would spin the restore.

What step 1 does instead is SAY that a layout leaf is being restored,
through one neutral variable core owns: =workspace--restoring-layout-leaf=
is bound non-nil around the leaf's jump.  A consumer whose handler
would otherwise put a question of its own for every leaf of a layout
reads it and declines (=workspace-restore-declined=) instead of
asking, and that decline takes the gate.  A restore paints several leaves in one
gesture; it must never turn into a series of per-leaf questions of a
consumer's making.  Core names no consumer: the variable is core's, and
a consumer reads it guarded by =boundp=.

Declines are collected while the leaves are walked and reported ONCE
per restore by =workspace--restore-frameset=, so a layout with three
declined leaves produces one message naming all three.  This is a gate
in front of the four-step chain, not a fifth step: the step vocabulary
below is unchanged.

The four step symbols are pinned in a closed, ordered set
(=workspace--valid-reincarnation-steps=) with a membership
predicate, mirroring the =workspace--valid-state-slots= /
=workspace--state-slot-p= pair below.  The order is load-bearing:
it matches =workspace--deserialize-buffer=, whose dispatch on step 1's
answer runs steps 2 → 3 → 4 in this order when step 1 FAILED, and
jumps straight to step 4 when step 1 DECLINED.
Adding a fifth step is a register-level change (see
=register/vocabulary/buffer-reincarnation-fallback-chain= in
=interfaces.org=), not a code-level addition.

#+begin_src emacs-lisp
(defconst workspace--valid-reincarnation-steps
  '(bookmark filename name error-buffer)
  "Closed, ordered set of reincarnation-chain step symbols.
The order is load-bearing in production via `workspace--deserialize-buffer':
a buffer from step 1 wins; when step 1 FAILED, steps 2, 3 and 4 are
tried in this order; when step 1 DECLINED (the gate), steps 2 and 3
are skipped and step 4 carries the reason.  Adding a fifth member is a
register-level change (see register/vocabulary/buffer-
reincarnation-fallback-chain in =interfaces.org=), not a
code-level addition.")

(defun workspace--reincarnation-step-p (step)
  "Return non-nil if STEP names a valid reincarnation-chain step."
  (memq step workspace--valid-reincarnation-steps))

(defun workspace--scrub-bookmark-record (record)
  "Return RECORD with any unreadable prop value nulled.
A bookmark record is `(NAME . PROPS)' where PROPS is an alist of
`(KEY . VALUE)'.  This nulls — keeps the KEY, sets VALUE to nil — any
VALUE satisfying `workspace--unreadable-object-p' (a marker, buffer,
overlay, frame, window, process, or non-symbol function a mode may have
embedded; the `help-mode' bug#56643 class).  The record's KEYS are
preserved so it remains a valid `bookmark-make-record'-shaped alist;
only offending values are dropped.  RECORD is mutated in place and
returned; nil passes through unchanged."
  (when record
    (dolist (prop (bookmark-get-bookmark-record record))
      (when (and (consp prop)
                 (workspace--unreadable-object-p (cdr prop)))
        (setcdr prop nil))))
  record)

(defun workspace--serialize-buffer (buffer)
  "Return a `workspace-buffer' struct capturing BUFFER's state, or nil if dead.
The struct carries enough to reincarnate the buffer across restart:
a `bookmark-make-record' result (the standard Emacs primitive for
major-mode-specific restorable state), the filename if file-backed,
the buffer name, and the narrowed/indirect flags.

The bookmark record is scrubbed of unreadable objects via
`workspace--scrub-bookmark-record' before being stored: a mode may
embed a marker or natively-compiled subr in its record (bug#56643),
which would make the whole on-disk state unreadable.  Nulling those
values keeps the record's keys intact, so the bookmark step of the
reincarnation chain still fires for the common case; a record whose
load-bearing value was nulled simply falls through to the file/name
fallback."
  (when (buffer-live-p buffer)
    (with-current-buffer buffer
      (make-workspace-buffer
       :bookmark (condition-case _err
                     (workspace--scrub-bookmark-record
                      (bookmark-make-record))
                   ;; Non-bookmarkable buffers (e.g. minibuffers, fresh
                   ;; *scratch* without a file) raise; fall through.
                   (error nil))
       :filename (buffer-file-name buffer)
       :name (buffer-name buffer)
       :narrowed-p (buffer-narrowed-p)
       :indirect-p (and (buffer-base-buffer buffer) t)))))

(defun workspace--error-buffer (ws-buffer &optional declined)
  "Return a live, named buffer explaining that WS-BUFFER could not be reincarnated.
Modelled on `activities--error-buffer' (activities.el:855-862).

DECLINED, when non-nil, is the message with which the buffer's
bookmark handler declined to restore it; the text then says so and
says that the saved filename was deliberately NOT opened, instead of
listing the four steps as having failed.

A WS-BUFFER whose `etc' alist carries `missing-file' is a recipe pane
whose file did not exist when the layout was applied (see
`workspace--recipe->window-state'); it has no name, and the buffer is
named after, and explains, the missing path."
  (let* ((missing (alist-get 'missing-file (workspace-buffer-etc ws-buffer)))
         (orig-name (or (workspace-buffer-name ws-buffer) "<unknown>"))
         (name (format "*workspace-restore: %s*"
                       (if missing (format "%s (missing)" missing) orig-name)))
         (buf (get-buffer-create name)))
    (with-current-buffer buf
      (let ((inhibit-read-only t))
        (erase-buffer)
        (if missing
            (insert
             "Workspaces could not open a file this layout names.\n\n"
             (format "Missing file : %s\n\n" missing)
             "The layout's recipe names this file, but it does not exist\n"
             "(it may have been moved, renamed or deleted).  The layout's\n"
             "other panes were built as usual, and nothing was created at\n"
             "this path.\n")
          (insert
           "Workspaces could not reincarnate this buffer.\n\n"
           (format "Original buffer name : %s\n" orig-name)
           (format "Original filename    : %s\n"
                   (or (workspace-buffer-filename ws-buffer) "<none>"))
           (format "Bookmark record      : %s\n\n"
                   (cond (declined "present (declined to restore)")
                         ((workspace-buffer-bookmark ws-buffer)
                          "present (failed to restore)")
                         (t "absent"))))
          (if declined
              (insert
               "The buffer's bookmark handler declined to restore it:\n\n"
               (format "  %s\n\n" declined)
               "The saved filename was NOT opened in its place: it is the\n"
               "path this buffer had when the layout was captured, and the\n"
               "handler has just said that path is not the right one here.\n"
               "Open the file you want by hand, then save the layout again.\n")
            (insert
             "All four fallback steps failed:\n"
             "  1. bookmark restore\n"
             "  2. find-file-noselect on filename\n"
             "  3. get-buffer by name\n"
             "  4. (this buffer is step 4)\n\n"
             "It is likely that the buffer's major mode does not support\n"
             "the bookmark system, or the underlying resource (file, repo,\n"
             "process) is no longer available.\n")))
        (goto-char (point-min)))
      (visual-line-mode 1))
    buf))

(defvar workspace--restoring-layout-leaf nil
  "Non-nil while a layout leaf is being restored; consumers must not prompt.
Bound by `workspace--bookmark-buffer' around the leaf's bookmark jump,
and nil everywhere else.  It suppresses nothing by itself: stock
handlers still ask whatever they ask on any visit.  A consumer whose
handler would put a question of its own for every leaf of a layout
reads it (guarded by `boundp') and signals `workspace-restore-declined'
instead, which the reincarnation chain treats as a decline (see
`workspace--deserialize-buffer').")

(defun workspace--bookmark-buffer (ws-buffer)
  "Return the buffer produced by jumping to WS-BUFFER's bookmark record.
Returns the buffer on success, nil when the jump FAILED, or
\(declined . MESSAGE) when the bookmark handler DECLINED to restore
the buffer by signalling `workspace-restore-declined'; MESSAGE is the
condition's datum.  Any other error, a plain `user-error' included,
and a jump that returns without moving off the probe buffer, is a
failure.  `quit' propagates.

The jump runs with `workspace--restoring-layout-leaf' bound non-nil,
so a consumer can tell a layout leaf from an interactive jump; nothing
else about the handler's environment is changed, and a handler that
asks the user is asked as on any other visit.

Uses a temp-buffer probe to detect whether `bookmark-jump' actually
moved off the temp buffer — `bookmark-handle-bookmark' swallows the
\"file no longer exists\" error and returns nil, so the only reliable
signal that the jump succeeded is observing a buffer change.

NOTE: Be aware of the following note from burly.el:
NOTE: Due to changes in help-mode.el which serialize natively
compiled subrs in the bookmark props, which cannot be read
back (which actually break the entire bookmark system when
such a props is saved in the bookmarks file), we have to
workaround a failure to read here.  See bug#56643."
  (let ((bookmark (workspace-buffer-bookmark ws-buffer)))
    (when bookmark
      (with-temp-buffer
        (let* ((temp-buffer (current-buffer))
               (declined nil)
               (jumped-to-buffer
                (save-window-excursion
                  (let ((workspace--restoring-layout-leaf t))
                    (condition-case err
                        (bookmark-jump bookmark)
                      ;; The handler declined: a decision for the
                      ;; user to see, not a failure to fall through.
                      (workspace-restore-declined
                       (setq declined
                             (let ((message (cadr err)))
                               (if (stringp message)
                                   message
                                 (error-message-string err)))))
                      ;; bug#56643 et al.: read-back failures, missing
                      ;; handlers, anything else.  Fall through.
                      (error nil)))
                  (current-buffer))))
          (cond
           (declined (cons 'declined declined))
           ((not (eq temp-buffer jumped-to-buffer))
            jumped-to-buffer)))))))

(defvar workspace--reincarnation-declines nil
  "Collector for the bookmark declines of one layout restore, or nil.
When non-nil it is a one-element list whose car accumulates
\(NAME . MESSAGE) pairs, newest first, one per leaf whose bookmark
handler declined.  `workspace--restore-frameset' binds it around the
leaf walk and reports the collected declines once; when it is nil
nothing is collecting and declines are not recorded.")

(defun workspace--note-reincarnation-decline (ws-buffer message)
  "Record that WS-BUFFER's bookmark declined with MESSAGE, if collecting."
  (when workspace--reincarnation-declines
    (push (cons (or (workspace-buffer-name ws-buffer) "<unknown>") message)
          (car workspace--reincarnation-declines))))

(defun workspace--report-reincarnation-declines (declines)
  "Report DECLINES, a list of (NAME . MESSAGE) pairs, in ONE message.
A no-op when DECLINES is nil.  One restore, one message: the user
sees every leaf that was left on its error buffer and why, without a
prompt or a message per leaf."
  (when declines
    (message "Workspaces: %d buffer%s not restored — the bookmark declined: %s"
             (length declines)
             (if (cdr declines) "s" "")
             (mapconcat (lambda (decline)
                          (format "%s (%s)" (car decline) (cdr decline)))
                        (reverse declines)
                        "; "))))

(defun workspace--deserialize-buffer (ws-buffer)
  "Reincarnate the buffer represented by WS-BUFFER.
Returns a live buffer.  Walks the four-step fallback chain:
bookmark → filename → name → error buffer.  Never returns nil; the
error buffer is the floor.

A bookmark handler that DECLINES by signalling
`workspace-restore-declined' (see `workspace--bookmark-buffer') gates
the chain: steps 2 and 3 are skipped and the leaf lands on the
error buffer carrying the handler's reason, and the decline is noted
for the restore's single report.  The stored filename is the path the
buffer had when the layout was captured; a handler that has just
refused to open its bookmark's location must not be second-guessed
by opening that path anyway.

Step 1 has exactly three answers — a buffer, nil (FAILED) or
\(declined . MESSAGE) — and the dispatch has an arm for each; any
other value signals rather than reaching the filename step."
  (let ((jumped (and (workspace-buffer-bookmark ws-buffer)
                     (condition-case-unless-debug _err
                         (workspace--bookmark-buffer ws-buffer)
                       (error nil)))))
    (cond
     ;; 1. Bookmark restore.
     ((bufferp jumped) jumped)
     ;; The gate: declined.  Not a fifth step — the floor, with a reason.
     ((eq (car-safe jumped) 'declined)
      (workspace--note-reincarnation-decline ws-buffer (cdr jumped))
      (workspace--error-buffer ws-buffer (cdr jumped)))
     ;; Step 1 FAILED: the rest of the chain, in order.
     ((null jumped)
      (or
       ;; 2. Filename fallback.
       (and (workspace-buffer-filename ws-buffer)
            (ignore-errors
              (find-file-noselect (workspace-buffer-filename ws-buffer))))
       ;; 3. Name fallback.
       (and (workspace-buffer-name ws-buffer)
            (get-buffer (workspace-buffer-name ws-buffer)))
       ;; 4. Error buffer.  Always live.
       (workspace--error-buffer ws-buffer)))
     ;; Nothing else is an answer step 1 gives; never guess the filename.
     (t (error "Not a reincarnation step-1 result: %S" jumped)))))
#+end_src

** Window-state serialize / deserialize

These wrap =workspace--window-state-walk-leaves= with leaf-translation
functions that *embed* (on serialize) or *consume* (on deserialize) a
=workspace-buffer= struct in each leaf's =parameters= map.

The deserialize translator also rewrites the leaf's =buffer= slot:
=window-state-get= writes it as =(BUFFER-NAME . BUFFER-ATTRS)=, and
=window-state-put= will resolve =BUFFER-NAME= against the live buffer
list (silently falling back to =*scratch*= if missing).  By replacing
=BUFFER-NAME= with our reincarnated buffer, we ensure the leaf points
at the right buffer regardless of name collisions.

#+begin_src emacs-lisp
(defun workspace--window-state-serialize (state)
  "Return a fresh window-state like STATE with `workspace-buffer' embedded.
Walks STATE; on each leaf, looks up the saved buffer-or-buffer-name,
builds a `workspace-buffer' struct, and stores it in the leaf's
`parameters' map under key `workspace-buffer'."
  (workspace--window-state-walk-leaves
   state
   (lambda (leaf)
     (pcase-let* ((`(leaf . ,attrs) leaf)
                  ((map parameters
                        ('buffer
                         `(,buffer-or-buffer-name . ,_buffer-attrs)))
                   attrs))
       (setf (map-elt parameters 'workspace-buffer)
             (workspace--serialize-buffer
              (get-buffer buffer-or-buffer-name)))
       (pcase-dolist (`(,param . ,translators)
                      workspace-window-parameter-translators)
         (when (map-contains-key parameters param)
           (setf (map-elt parameters param)
                 (funcall (alist-get 'serialize translators)
                          (map-elt parameters param)))))
       (setf (map-elt attrs 'parameters) parameters)
       (cons 'leaf attrs)))))

(defun workspace--window-state-deserialize (state)
  "Return a fresh window-state like STATE with each leaf's buffer reincarnated.
Walks STATE; on each leaf, reads the `workspace-buffer' struct from
its `parameters' map (if present), reincarnates the buffer via the
four-step fallback chain, and rewrites the leaf's `buffer' slot to
point at the live buffer."
  (workspace--window-state-walk-leaves
   state
   (lambda (leaf)
     (pcase-let* ((`(leaf . ,attrs) leaf)
                  ((map parameters
                        ('buffer
                         `(,_buffer-name . ,buffer-attrs)))
                   attrs)
                  ((map workspace-buffer) parameters))
       (when workspace-buffer
         (let ((live (workspace--deserialize-buffer workspace-buffer)))
           (setf (map-elt attrs 'buffer) (cons live buffer-attrs))))
       (pcase-dolist (`(,param . ,translators)
                      workspace-window-parameter-translators)
         (when (map-contains-key parameters param)
           (condition-case-unless-debug _err
               (setf (map-elt parameters param)
                     (funcall (alist-get 'deserialize translators)
                              (map-elt parameters param)))
             (error
              (setq parameters (map-delete parameters param))))))
       (setf (map-elt attrs 'parameters) parameters)
       (cons 'leaf attrs)))))

** Recipe expansion

A layout's =:saved-state= may be a *recipe* (data-model.org, "Recipe
shape") instead of a captured window-state.  A recipe becomes windows
at one place only, the restore choke point =workspace--restore-frameset=
below, which every apply path reaches (=workspace-switch-layout=, and
=workspace--apply-saved-layout= from =workspace-restore= and
=workspace-revert=).  There the recipe is first expanded into the
window-state a capture would have produced, and the unchanged path
runs on that: deserialize (the reincarnation chain) → decline report
→ deferred =window-state-put= behind the generation guard.  Expansion
creates no window and visits no file, and the stored recipe is never
modified, so a revert rebuilds from it against the files as they are
then.

What the expansion produces, read off =window-state-get='s output and
what =window-state-put= consumes:

- *A header of minimum sizes*, the car of the state.  =window-state-put=
  compares it with the target window to refuse a frame too small for
  the layout.  Each pane needs =window-min-height= × =window-min-width=,
  or =window-safe-min-height= × =window-safe-min-width= when sizes may
  be ignored (the restore passes =ignore= =safe=; the expansion uses
  the safe minimums for both relaxed levels); a split adds its
  children's sizes along its direction and takes their largest across
  it.
- *One =hc= (=columns=) or =vc= (=rows=) combination per split*, its
  children sharing it evenly: each child's =normal-width= (in an =hc=)
  or =normal-height= (in a =vc=) is 1/N, its other normal size 1.0, and
  the last child is marked =(last . t)=.  The root's =total-width= and
  =total-height= are 0, which never equals a live window's size, so
  =window-state-put= sizes every child from its normal (fractional)
  size: the expansion is frame-independent.  A split with one pane is
  that pane.
- *One leaf per file pane*, whose =parameters= carry a =workspace-buffer=
  record and whose =buffer= entry carries the neutral display state a
  fresh window has (no hscroll or vscroll, frame-default fringes and
  scroll bars).  The first pane's window is selected.

Each pane's file is looked at here, at apply time:

- *The file exists.*  The record has =:filename= and nothing else: no
  name, so step 3 of the chain can never pick up an unrelated buffer
  that happens to share the file's base name, and no bookmark, so the
  portable-bookmarks seam is never consulted.  Step 2 visits the file;
  nothing visits it earlier.
- *The file does not exist.*  The record has no =:filename= (step 2
  would otherwise return a new, empty buffer /visiting/ that path) and
  no name, and its =etc= alist carries =(missing-file . PATH)=.  The
  chain falls to its floor, =workspace--error-buffer=, which names and
  explains the missing path.  The pane's window shows that, and the
  other panes are built as usual.
- *Where point goes.*  A pane's line is recorded as =(line . N)= in
  the record's =etc= alist; it cannot become a buffer position until
  the file is visited.  So =workspace--window-state-place-points= runs
  after the reincarnation walk and gives each leaf that has no window
  position (only a recipe leaf lacks one; a captured leaf always has
  =point= and =start=) the position it is shown at: the beginning of
  line N of the buffer the chain returned for a pane with a line (a
  line past the end lands on the last line), the buffer's own point
  for one without, as visiting the file would.  =start= is the
  beginning of that line, so it is at the top of the window.  The
  position is not optional: =window-state-put= skips a leaf's
  positions when =start= is absent, and the window is then left with a
  window start that points nowhere, which fails the next time the
  window is selected.

#+begin_src emacs-lisp
(defconst workspace--recipe-leaf-buffer-state
  '((hscroll . 0) (fringes nil nil nil nil) (margins nil)
    (scroll-bars nil nil t nil nil t nil) (vscroll . 0) (dedicated))
  "Display state of a recipe leaf's window, in `window-state-get' form.
What a fresh window has: no scroll, frame-default fringes, margins and
scroll bars.  `window-state-put' applies each entry unguarded, so every
one must be present.")

(defun workspace--recipe-pane-workspace-buffer (pane)
  "Return the `workspace-buffer' record for file PANE, decided now.
An existing file gets a record with only `:filename'.  A missing one
gets no filename (the reincarnation chain would visit, so create, it)
and `(missing-file . PATH)' in `etc', which lands the leaf on
`workspace--error-buffer'.  A pane's line is carried as `(line . N)'
in `etc' for `workspace--window-state-place-points'."
  (let ((path (plist-get pane :file))
        (line (plist-get pane :line)))
    (if (file-exists-p path)
        (make-workspace-buffer :filename path
                               :etc (and line (list (cons 'line line))))
      (make-workspace-buffer :etc (list (cons 'missing-file path))))))

(defun workspace--recipe-node (pane normal-height normal-width first last)
  "Expand recipe PANE into a window-state node and its minimum sizes.
NORMAL-HEIGHT and NORMAL-WIDTH are the node's share of its parent.
FIRST non-nil marks the first pane of the whole recipe, whose window
is selected; LAST non-nil marks the last child of its parent.

Return (NODE . SIZES), SIZES an alist of the node's minimum sizes
keyed `min-height', `min-width', `min-height-safe' and
`min-width-safe'."
  (let ((head (append (and last '((last . t)))
                      `((normal-height . ,normal-height)
                        (normal-width . ,normal-width)))))
    (pcase pane
      (`(:split ,_dir :panes (,only))
       (workspace--recipe-node only normal-height normal-width first last))
      (`(:split ,dir :panes ,panes)
       (let* ((columns (eq dir 'columns))
              (share (/ 1.0 (length panes)))
              (children
               (cl-loop for child in panes
                        for index from 0
                        collect (workspace--recipe-node
                                 child
                                 (if columns 1.0 share)
                                 (if columns share 1.0)
                                 (and first (= index 0))
                                 (null (nthcdr (1+ index) panes)))))
              (combine
               ;; Children's minimum KEY sizes, summed along the split
               ;; (ALONG non-nil) or the largest across it.
               (lambda (key along)
                 (cons key (apply (if along #'+ #'max)
                                  (mapcar (lambda (child)
                                            (alist-get key (cdr child)))
                                          children))))))
         (cons (append (list (if columns 'hc 'vc))
                       head
                       '((combination-limit))
                       (mapcar #'car children))
               (list (funcall combine 'min-height (not columns))
                     (funcall combine 'min-width columns)
                     (funcall combine 'min-height-safe (not columns))
                     (funcall combine 'min-width-safe columns)))))
      (_
       (cons `(leaf ,@head
                    (parameters
                     (workspace-buffer
                      . ,(workspace--recipe-pane-workspace-buffer pane)))
                    (buffer ,(plist-get pane :file)
                            ,@(and first '((selected . t)))
                            ,@(copy-tree workspace--recipe-leaf-buffer-state)))
             `((min-height . ,window-min-height)
               (min-width . ,window-min-width)
               (min-height-safe . ,window-safe-min-height)
               (min-width-safe . ,window-safe-min-width)))))))

(defun workspace--recipe->window-state (recipe)
  "Return the window-state RECIPE describes, ready for the restore path.
RECIPE satisfies `workspace--recipe-p'.  The result has the shape of
`workspace--capture-frameset''s: a header of minimum sizes, then an
`hc' (`columns') or `vc' (`rows') combination per split with even
normal sizes, and one leaf per file pane carrying a `workspace-buffer'
record (see `workspace--recipe-pane-workspace-buffer').  A one-pane
recipe is a one-window state.  Checks whether each pane's file exists;
visits none and creates no window."
  (pcase-let* ((`(,node . ,sizes)
                (workspace--recipe-node (cdr recipe) 1.0 1.0 t nil))
               (header (list (cons 'min-height (alist-get 'min-height sizes))
                             (cons 'min-width (alist-get 'min-width sizes))
                             (cons 'min-height-ignore
                                   (alist-get 'min-height-safe sizes))
                             (cons 'min-width-ignore
                                   (alist-get 'min-width-safe sizes))
                             (cons 'min-height-safe
                                   (alist-get 'min-height-safe sizes))
                             (cons 'min-width-safe
                                   (alist-get 'min-width-safe sizes))))
               (`(,type . ,attrs) node))
    (append (list header type '(total-width . 0) '(total-height . 0))
            attrs)))

(defun workspace--window-state-place-points (state)
  "Return STATE with a window position in each leaf that has none.
STATE is a deserialized window-state: each leaf's `buffer' entry holds
a live buffer.  A leaf whose `workspace-buffer' record carries
`(line . N)' in its `etc', or whose `buffer' entry has no `start',
gets `point' and `start' from that buffer: point at the beginning of
line N (counted from the start of the buffer), or the buffer's own
point when there is no line, and start at the beginning of point's
line.  Other leaves, every captured one among them, are returned
unchanged."
  (workspace--window-state-walk-leaves
   state
   (lambda (leaf)
     (pcase-let* ((`(leaf . ,attrs) leaf)
                  ((map parameters ('buffer `(,buffer . ,buffer-attrs))) attrs)
                  ((map workspace-buffer) parameters)
                  (line (and (workspace-buffer-p workspace-buffer)
                             (alist-get 'line
                                        (workspace-buffer-etc workspace-buffer)))))
       (when (and (buffer-live-p buffer)
                  (or line (not (assq 'start buffer-attrs))))
         (pcase-let ((`(,point . ,start)
                      (with-current-buffer buffer
                        (save-restriction
                          (widen)
                          (save-excursion
                            (when line
                              (goto-char (point-min))
                              (forward-line (1- line)))
                            (cons (point) (line-beginning-position)))))))
           (setf (alist-get 'point buffer-attrs) point
                 (alist-get 'start buffer-attrs) start
                 (map-elt attrs 'buffer) (cons buffer buffer-attrs))))
       (cons 'leaf attrs)))))
#+end_src

** Capture and restore primitives

Both =workspace--capture-frameset= and =workspace--restore-frameset=
=let=-bind =window-persistent-parameters= so the extension is scoped
to our serialization calls and does not pollute global state for
other packages.

The capture path walks the freshly-taken window-state and embeds a
=workspace-buffer= struct in each leaf — so the saved form carries
everything the restore path needs without a second pass over live
buffers.

The restore path =copy-tree='s the saved state so its
buffer-replacement mutation does not leak into the in-memory
registry, then defers =window-state-put= via =run-at-time= to avoid
racing against =bookmark--jump-via='s buffer-display call
(design.md §D2, Gotcha 2).

#+begin_src emacs-lisp
(defun workspace--capture-frameset ()
  "Return a window-state capturing the selected frame's root window.
Extends `window-persistent-parameters' with
`workspace-window-persistent-parameters' so side windows, preserved
sizes, and explicit modeline overrides survive the round trip.

Each leaf in the returned form carries a `workspace-buffer' struct
in its `parameters' map, encoding enough to reincarnate the buffer
across restart via the four-step fallback chain."
  (let* ((window-persistent-parameters
          (append workspace-window-persistent-parameters
                  window-persistent-parameters))
         (state (window-state-get (frame-root-window) 'writable)))
    (workspace--window-state-serialize state)))

(defun workspace--restore-frameset (state)
  "Apply window-state STATE to the selected frame's root window.
STATE is expected to carry a `workspace-buffer' struct in each
leaf's `parameters' map (see `workspace--capture-frameset').

STATE may instead be a layout recipe (`workspace--recipe-p'); it is
first expanded with `workspace--recipe->window-state', and the rest
of the path is the same.  This is the only place a recipe becomes
windows.  After the leaves are reincarnated, each recipe leaf gets
its window position, a pane's line becoming its window's point
(`workspace--window-state-place-points').

The state is `copy-tree'-ed before mutation so the in-memory
registry is not affected by buffer-replacement side effects.  The
`window-state-put' call is deferred via `run-at-time' nil nil to
avoid racing against `bookmark--jump-via''s buffer-display call,
which fires synchronously from within bookmark handlers.

A generation counter (`workspace--restore-generation') gates the
deferred closure: if a newer restore is queued while this one is
pending, the older closure no-ops.  The counter is incremented
HERE — at the single restore choke point — so every entry path
(`workspace--apply-saved-layout', `workspace-switch-layout', and
any future caller of `workspace--restore-frameset') participates
in the race guard.

Leaves whose bookmark handler declined (see
`workspace--deserialize-buffer') are collected during the walk and
reported in ONE message here, after the walk and before the deferred
paint — one restore, one report, no per-leaf prompt."
  ;; Note: only the INNER let binding of `window-persistent-parameters'
  ;; (inside the deferred lambda) is load-bearing — that is the binding
  ;; in scope when `window-state-put' runs.  An earlier draft also
  ;; bound it around `workspace--window-state-deserialize', but that
  ;; deserializer reads the per-leaf `workspace-buffer' struct from the
  ;; saved parameters map; it does not consult the dynamic variable.
  (let* ((state (if (workspace--recipe-p state)
                    (workspace--recipe->window-state state)
                  state))
         (workspace--reincarnation-declines (list nil))
         (bufferized (workspace--window-state-place-points
                      (workspace--window-state-deserialize
                       (copy-tree state))))
         (gen (cl-incf workspace--restore-generation))
         (frame (selected-frame)))
    (workspace--report-reincarnation-declines
     (car workspace--reincarnation-declines))
    (run-at-time nil nil
                 (lambda ()
                   (when (= gen workspace--restore-generation)
                     (let ((window-persistent-parameters
                            (append workspace-window-persistent-parameters
                                    window-persistent-parameters)))
                       (window-state-put bufferized
                                         (frame-root-window frame)
                                         'safe)))))))
#+end_src

* Layout capture helper

The capture helper snapshots the current frame into one of the active
layout-group's two state slots, dispatched by the SLOT argument:

- =:saved-state= — explicit user gesture path (=workspace-save= and its
  variants).  Writes the captured state into the recent layout's
  =:saved-state= slot.  This is the user's authoritative \"make this
  the baseline\" affordance.
- =:working-state= — autosave path (tab-switch advice, idle timer,
  =kill-emacs-hook=).  Writes to =:working-state=, leaving
  =:saved-state= untouched.  This is register/invariant/autosave-
  never-writes-saved-state's structural enforcement: the autosave
  code path has no syntactic ability to address =:saved-state= because
  the slot is passed in by the caller.

SLOT has no default: every caller MUST pass an explicit
=:saved-state= or =:working-state=.  An omitted or off-vocabulary
slot raises an error rather than silently writing to the wrong
slot — the structural fix for v1 MVP gap D8 (=fix-restoration-
roundtrip= bug 4).

The function is a no-op when not on a workspace-tagged tab or when
the workspace has no recent layout-group yet — safe to install
globally during side-by-side development (design.md §D8).

In v1 the helper additionally drove a tab-switch advice that
clobbered explicit saves; that advice is re-introduced in
=persistence.org= with the structural fix (writes =:working-state=
only).

#+begin_src emacs-lisp
(defconst workspace--valid-state-slots '(:saved-state :working-state)
  "Closed vocabulary of layout state slots.
See =register/vocabulary/workspace-state-slot= in =interfaces.org=.
The two members map to: =:saved-state= (explicit-save writes;
authoritative across restarts) and =:working-state= (autosave
writes; cleared by explicit save).  Adding a third member is a
register-level change, not a code-level addition.")

(defun workspace--state-slot-p (slot)
  "Return non-nil if SLOT is a valid workspace state-slot keyword."
  (memq slot workspace--valid-state-slots))

(defun workspace--autosave-current-layout (slot)
  "Snapshot the current frame into the current workspace's recent layout SLOT.
SLOT MUST be one of `:saved-state' (explicit save) or
`:working-state' (autosave path).  Routing is by direct caller
specification (no trigger → slot indirection at this site).

There is no default for SLOT: the load-bearing invariant
`autosave-never-writes-saved-state' (see =register/invariant/= in
=interfaces.org=) is enforced structurally — a caller that forgets
to pass a slot triggers `cl-assert' rather than silently defaulting
to the explicit-save slot.  This is the structural fix for v1 MVP
gap D8.

Every explicit save — `workspace-save', `workspace-save-layout' and
`workspace--capture-home-layout' — passes through here with
`:saved-state', so this is the one place an explicit save takes
ownership: re-saving a layout whose origin is `agent' makes it the
user's, keeping its other metadata (`workspace--layout-with-metadata').
A layout created here keeps :etc nil, which already reads as the
user's.  The `:working-state' path leaves :saved-state and :etc as
they were.

Captures only the window-state; does NOT update `:buffer-files'.
That sync is intentionally limited to explicit user save paths
(`workspace-save'); doing it here would wipe the file list whenever
a user switched away from a tab whose buffers had been killed since
the last explicit save.  No-op when not on a workspace tab or when
the workspace has no recent layout-group yet."
  (unless (workspace--state-slot-p slot)
    (error "workspace--autosave-current-layout: invalid SLOT %S \
(must be one of %S)" slot workspace--valid-state-slots))
  (let ((ws-name (workspace--current-name)))
    (when ws-name
      (let* ((ws (gethash ws-name workspace--registry))
             (group-name (and ws (workspace--recent-group ws))))
        (when (and ws group-name)
          (let* ((captured (workspace--capture-frameset))
                 (group (workspace--find-group ws group-name))
                 (existing (and group (workspace--group-recent-layout group)))
                 (layout (cond
                          ((and existing (eq slot :working-state))
                           ;; Preserve :saved-state; update timestamp +
                           ;; :working-state in place.
                           (let ((copy (copy-sequence existing)))
                             (plist-put copy :timestamp
                                        (time-convert nil 'integer))
                             (plist-put copy :working-state captured)))
                          ((and existing (eq slot :saved-state))
                           ;; Replace :saved-state; preserve :etc and
                           ;; any prior :working-state (the caller —
                           ;; typically `workspace-save' — decides
                           ;; whether to clear it as a separate step).
                           ;; An agent layout becomes the user's (R4).
                           (let ((copy (copy-sequence existing)))
                             (plist-put copy :timestamp
                                        (time-convert nil 'integer))
                             (plist-put copy :saved-state captured)
                             (if (eq (workspace--layout-origin existing) 'agent)
                                 (workspace--layout-with-metadata
                                  copy :origin 'user)
                               copy)))
                          (t
                           ;; No existing layout — construct a fresh one.
                           ;; A :working-state-only first write would
                           ;; leave :saved-state nil, which is
                           ;; structurally valid (effective-state falls
                           ;; through correctly) and matches the v2
                           ;; semantics: explicit save defines the
                           ;; baseline, autosaves layer on top.
                           (if (eq slot :working-state)
                               (let ((l (workspace--layout-make nil)))
                                 (plist-put l :working-state captured))
                             (workspace--layout-make captured)))))
                 (updated (workspace--upsert-group ws group-name layout)))
            (puthash ws-name updated workspace--registry)))))))

(defun workspace-save-layout (name)

Re-saving an existing layout (including the reserved `home' layout)
overwrites the layout's :saved-state while preserving :etc and any
prior :working-state is then cleared (explicit-save-clears-working-

Funnels through `workspace--autosave-current-layout :saved-state' so
all three explicit-save variants (`workspace-save', this command, and

                     (workspace--current-group-names)
                     nil nil nil 'workspace--save-layout-history)))

    (unless ws-name
      (user-error "Not on a workspaces-managed tab"))

    ;; so the helper writes into the target group.  For an existing
    ;; group, the helper's :saved-state cond arm copies and preserves
    ;; :etc; for a new group, it falls through to the fresh-construction

           (with-recent (workspace--set-recent-group ws name)))
      (puthash ws-name with-recent workspace--registry))
    (workspace--autosave-current-layout :saved-state)
    ;; Clear any prior :working-state drift on the re-saved layout to
    ;; honour register/invariant/explicit-save-clears-working-state.
    ;; For a brand-new group the working-state is already nil (helper

#+end_src

* Switch layout

Public command.  Snapshots the outgoing layout, restores the chosen
layout's frameset, and updates the recent pointer.

#+begin_src emacs-lisp
(defun workspace-switch-layout (name)
  "Switch to layout NAME within the current workspace.
The outgoing layout's `:working-state' is updated with a fresh snapshot
of the current frame and flushed to disk synchronously (a layout switch
is a discrete user action; no debounce).  The destination layout's
effective state (`:working-state' if non-nil else `:saved-state') is
restored."
  (interactive
   (list
    (completing-read "Switch to layout: "
                     (workspace--current-group-names)
                     nil t)))
  (let ((ws-name (workspace--current-name)))
    (unless ws-name
      (user-error "Not on a workspaces-managed tab"))
    (let* ((ws (gethash ws-name workspace--registry))
           (group (workspace--find-group ws name)))
      (unless group
        (user-error "No layout named %s in workspace %s" name ws-name))
      ;; Snapshot the outgoing layout into its :working-state slot
      ;; before restoring.  Writing :working-state (not :saved-state)
      ;; preserves the outgoing layout's last explicit save unaltered
      ;; (register/invariant/autosave-never-writes-saved-state).
      (workspace--autosave-current-layout :working-state)
      ;; Deliberate command — flush the outgoing layout's snapshot
      ;; synchronously (no debounce) before restoring the destination.
      (workspace--flush-state)
      (let ((layout (workspace--group-recent-layout group)))
        (when layout
          (when-let ((state (workspace--layout-effective-state layout)))
            (workspace--restore-frameset state))))
      (workspace--update-recent-group ws-name name)
      name)))

(defun workspace-switch-to-recent-layout ()
  "Switch to the current workspace's most recently activated layout."
  (interactive)
  (let* ((ws-name (workspace--current-name))
         (ws (and ws-name (gethash ws-name workspace--registry)))
         (recent (and ws (workspace--recent-group ws))))
    (unless recent
      (user-error "No recent layout for this workspace"))
    (workspace-switch-layout recent)))
#+end_src

* Delete layout

Public command.  Refuses to delete reserved layout names.

When a layout goes, the workspace's recent pointer may have to move.
=workspace--reassign-recent-group= holds the one rule, shared with the
programmatic =workspace-remove-layout= below: a pointer that names
another layout is kept; otherwise (it named the removed layout, or it
was nil) it moves to the first remaining group, or to =home= when none
remains.

The interactive command updates the registry without flushing; the
next save trigger writes it.

#+begin_src emacs-lisp
(defun workspace--reassign-recent-group (ws removed-name)
  "Return WS with its recent pointer reassigned after REMOVED-NAME went.
WS is the workspace with REMOVED-NAME's group already removed; its
recent pointer is still the one it had before the removal.  A pointer
naming another layout is kept.  A pointer that named REMOVED-NAME, or
was nil, moves to the first remaining group, else to `home'.
Non-destructive."
  (let ((recent (workspace--recent-group ws))
        (remaining (workspace--layout-groups ws)))
    (if (and recent (not (equal recent removed-name)))
        ws
      (workspace--set-recent-group
       ws (if remaining
              (workspace--group-name (car remaining))
            "home")))))

(defun workspace-delete-layout (name)
  "Delete layout NAME from the current workspace.

The reserved layout `home' cannot be deleted.  If the deleted layout
was the workspace's recent pointer, it is reassigned to the first
remaining group (or `home' if none)."
  (interactive
   (list
    (completing-read "Delete layout: "
                     (workspace--current-group-names)
                     nil t)))
  (when (workspace--group-name-reserved-p name)
    (user-error "Cannot delete reserved layout: %s" name))
  (let ((ws-name (workspace--current-name)))
    (unless ws-name
      (user-error "Not on a workspaces-managed tab"))
    (let* ((ws (gethash ws-name workspace--registry))
           (existed (workspace--find-group ws name)))
      (unless existed
        (user-error "No layout named %s" name))
      (puthash ws-name
               (workspace--reassign-recent-group
                (workspace--remove-group ws name) name)
               workspace--registry)
      name)))
#+end_src

* Programmatic layout writes

=workspace-add-layout= and =workspace-remove-layout= are how a program
— an agent tool, an integration — gives a workspace a layout or takes
one away.  They are the only programmatic writers of a workspace's
layout groups.

They address the workspace by name, not by the selected tab, and work
on any registered workspace, whether or not it has a tab.  They change
only the workspace's registry entry, through the pure data layer
(=workspace--layout-make=, =workspace--layout-with-metadata=,
=workspace--upsert-group=, =workspace--remove-group=), and then flush
the registry once with =workspace--flush-state=.  They never touch a
frame, tab, window or buffer.

They do not go through =workspace--autosave-current-layout=.  That
funnel captures the /selected frame/ into the /current/ workspace's
recent layout: the wrong workspace, the wrong layout, and a capture the
program never asked for.  For the same reason adding a layout never
moves the recent pointer: the user's next =workspace-restore= or
=workspace-switch-to-recent-layout= lands where it did before.

The rules that keep a program's writes from fighting the user's:

- *R1.*  An added layout holds its window-state as =:saved-state=, with
  =:working-state= nil and origin =agent= unless the caller says
  otherwise.  Whatever the user changes while viewing it autosaves into
  =:working-state=, so =workspace-revert= brings back the version the
  program added.
- *R2.*  A program never replaces or removes a layout whose origin is
  =user=.  A layout with no recorded origin — every layout made before
  layout metadata existed — is the user's.
- *R3.*  A program may replace or remove an =agent= layout, discarding
  any working-state drift on it, unless the layout is on screen
  (=workspace-layout-on-screen-p=: the workspace's recent layout, with
  a tab open in some frame).  Tab-bar restores an open tab's own window
  configuration, and the next autosave would bury a replacement under
  =:working-state=: the change would be silently invisible.  Removal is
  refused on screen for the same reason.
- The reserved =home= layout is never written by a program.

One guard, =workspace--programmatic-write-refusal=, decides all three
refusals and their messages, before anything changes; both writers
signal its message as a =user-error=.  The messages are written for an
agent to read: agent tools pass them on unchanged.

Two cases outside the guard: an unregistered workspace name is a
=user-error= naming it, and removing a layout the workspace does not
have is a =user-error= naming the layout, as =workspace-delete-layout=
does.

=workspace-layout-on-screen-p= lives in =workspaces.el=, which loads
after this module; it is called only at run time.

#+begin_src emacs-lisp
(declare-function workspace-layout-on-screen-p "workspaces" (name layout))

(defun workspace--programmatic-write-refusal (ws layout-name)
  "Return why a program may not write LAYOUT-NAME of workspace WS, or nil.
The message, for the reserved name, a layout that belongs to the user
\(R2) or an agent layout that is on screen (R3), is written to be shown
to an agent unchanged.  Changes nothing."
  (let* ((ws-name (workspace--name ws))
         (group (workspace--find-group ws layout-name))
         (layout (and group (workspace--group-recent-layout group))))
    (cond
     ((workspace--group-name-reserved-p layout-name)
      (format "Layout \"%s\" is reserved for the workspace's home layout; \
a program cannot add, replace or remove it" layout-name))
     ((and group (eq (workspace--layout-origin layout) 'user))
      (format "Layout \"%s\" in workspace \"%s\" belongs to the user; \
a program cannot replace or remove it (to add a layout, use another name)"
              layout-name ws-name))
     ((and group (workspace-layout-on-screen-p ws-name layout-name))
      (format "Layout \"%s\" in workspace \"%s\" is on screen; \
it cannot be replaced or removed while the user is looking at it"
              layout-name ws-name)))))

(defun workspace--programmatic-write-target (ws-name layout-name)
  "Return the registered workspace WS-NAME, if a program may write LAYOUT-NAME.
Signal a `user-error' when WS-NAME is not registered or
`workspace--programmatic-write-refusal' refuses."
  (let ((ws (gethash ws-name workspace--registry)))
    (unless ws
      (user-error "No workspace named \"%s\"" ws-name))
    (when-let* ((refusal (workspace--programmatic-write-refusal ws layout-name)))
      (user-error "%s" refusal))
    ws))

(defun workspace-add-layout (ws-name layout-name state &rest metadata)
  "Add layout LAYOUT-NAME holding window-state STATE to workspace WS-NAME.
STATE is stored as the layout's `:saved-state', with `:working-state'
nil.  METADATA is keyword arguments for `workspace--layout-with-metadata'
\(:origin, :description, :source); :origin defaults to `agent'.

An existing agent layout of that name that is not on screen is
replaced, its working state discarded.  The reserved name, a layout
that belongs to the user and an agent layout on screen are refused
with a `user-error', changing nothing.

Works on any registered workspace, with or without a tab.  Touches no
frame, tab, window or buffer, leaves the recent pointer as it was, and
flushes the registry once.  Return LAYOUT-NAME."
  (let* ((ws (workspace--programmatic-write-target ws-name layout-name))
         (layout (apply #'workspace--layout-with-metadata
                        (workspace--layout-make state)
                        (if (plist-member metadata :origin)
                            metadata
                          (append metadata '(:origin agent))))))
    (puthash ws-name
             (workspace--upsert-group ws layout-name layout)
             workspace--registry)
    (workspace--flush-state)
    layout-name))

(defun workspace-remove-layout (ws-name layout-name)
  "Remove layout LAYOUT-NAME from workspace WS-NAME.
The reserved name, a layout that belongs to the user, an agent layout
on screen and a layout WS-NAME does not have are refused with a
`user-error', changing nothing.

The recent pointer moves only when it named LAYOUT-NAME or was nil, as
`workspace-delete-layout' moves it (`workspace--reassign-recent-group').
Works on any registered workspace, with or without a tab.  Touches no
frame, tab, window or buffer, and flushes the registry once.  Return
LAYOUT-NAME."
  (let ((ws (workspace--programmatic-write-target ws-name layout-name)))
    (unless (workspace--find-group ws layout-name)
      (user-error "No layout named \"%s\" in workspace \"%s\""
                  layout-name ws-name))
    (puthash ws-name
             (workspace--reassign-recent-group
              (workspace--remove-group ws layout-name) layout-name)
             workspace--registry)
    (workspace--flush-state)
    layout-name))
#+end_src

* Home layout capture for new workspaces

=workspace-new= calls the home builder; we now persist the resulting
window configuration as the workspace's =home= layout-group.  This
establishes the invariant that *every workspace has at least one
saved layout* before any switch happens.

#+begin_src emacs-lisp
(defun workspace--capture-home-layout ()
  "Stamp the current frame's window config as the current workspace's `home'.

Funnels through `workspace--autosave-current-layout :saved-state' (the
canonical layout-construction path), keeping shape parity with
`workspace-save' and `workspace-save-layout'.  Resolves
register/shape/layout-v2-plist producer fragmentation.

Called as an `:after' advice on `workspace-new', which has just put a
freshly-made workspace into the registry with `:recent-layout-group'
nil and no layout-groups.  Pointing recent to \"home\" before the
helper runs causes the helper's no-existing-layout branch to construct
a fresh layout via `workspace--layout-make' — same shape as the
explicit-save variants on first save."
  (let ((ws-name (workspace--current-name)))
    (when ws-name
      ;; Set the recent pointer to "home" before invoking the helper so
      ;; the helper writes into the home group (creating it via its
      ;; no-existing-layout branch).
      (let* ((ws (gethash ws-name workspace--registry))
             (with-recent (workspace--set-recent-group ws "home")))
        (puthash ws-name with-recent workspace--registry))
      (workspace--autosave-current-layout :saved-state)
      ;; `workspace-new' is a deliberate action — flush the home stamp
      ;; synchronously (no debounce).
      (workspace--flush-state))))

(advice-add 'workspace-new :after
            (lambda (&rest _)
              (workspace--capture-home-layout)))
#+end_src
