#+title: Workspaces — Data Model
#+author: Jeff Farr
#+property: header-args:emacs-lisp :tangle data-model.el
#+auto_tangle: y

Side-effect-free data layer for the =workspaces= module.  It never
writes, holds no state beyond the registry shapes it defines, and
reads the filesystem only in the identity and containment predicates
(=workspace--same-file-p= and =workspace--path-within-p=, see
[[*File identity][File identity]]), which stat paths and never read
file contents.  Reading a file's contents (=home.org=) is
=home-org.el='s business, not this layer's.

The in-memory representation mirrors the persistent shape (design.md
§D5) so that serialization is a direct walk of the registry, no
struct-to-plist conversion at the disk boundary:

- =Workspace=    : =(:name STR :home STR :recent-layout-group STR :buffer-files (FILE ...) :layout-groups (LAYOUT-GROUP ...))=
- =Layout-group= : =(:name STR :layouts (LAYOUT ...))=
- =Layout=       : =(:timestamp INT :saved-state BLOB :working-state BLOB-or-nil :etc nil)=

The =:home= slot is the workspace's filesystem anchor (an absolute
path string).  It is required by the constructor — floating workspaces
without a home directory are structurally unrepresentable.  By
convention, =basename(:home)= equals =:name=, and the registry key
under which a workspace is stored equals =:name=; the data layer does
not enforce this equality (the constructor takes both NAME and HOME
independently), but every caller is expected to honour the contract.

The optional =:broken= runtime tag is set when the persistence loader
discovers that =:home= no longer exists on disk; it is never
serialized.  See =workspace--broken-p= and =workspace--mark-broken=
below.  Validation of =:home= (does the directory exist?) lives at
the persistence boundary (=persistence.org=) and in =scaffold.el=,
not here.

The =:saved-state= slot holds the window-state written by explicit
saves (=workspace-save= and its variants).  The =:working-state= slot
holds the window-state written by autosaves (tab-switch advice, idle
timer, kill-emacs-hook); nil when no drift has accumulated since the
last explicit save.

Restore precedence: =workspace--layout-effective-state= prefers
=:working-state= when non-nil, else =:saved-state=.

The =:etc= slot is an alist forward-compat hook; replaces the v1
=:git-state= placeholder.

Public-facing commands live in sibling modules (=tabs.el=,
=layouts.el=, =buffer-membership.el=, =persistence.el=) and call into
=workspace--= helpers defined here. No symbol in this file is intended
as a public API surface.

* Layout primitives

** workspace-buffer struct

The =workspace-buffer= struct is the per-window-leaf payload that the
restore path needs to *reincarnate* a buffer — bring it back to life
across an Emacs restart, complete with point position, narrowing,
indirect-buffer status, and (most importantly) its major-mode-specific
restorable state for non-file buffers like =magit-status=, =eshell=,
=*Messages*=.

The bookmark slot carries the result of =bookmark-make-record= — the
standard Emacs primitive that asks each buffer's major-mode for a
serializable representation of "what I am right now."  Because we
write this record into our persistence file (not
=bookmark-default-file=) it does not collide with the user's existing
bookmarks (design.md §D2).

The =local-variables= slot is reserved (always nil in v2; the
catalog-pattern hook for the deferred =workspace-buffer-local-variables=
defcustom).  The =etc= slot is the forward-compat alist.

#+begin_src emacs-lisp
(cl-defstruct workspace-buffer
  "Per-window-leaf reincarnation record.
Stored under the leaf's `parameters' map by `workspace--capture-frameset',
consumed by `workspace--deserialize-buffer' on restore.

Slots:
- `bookmark'        :: result of `bookmark-make-record', or nil for
                       non-bookmarkable buffers.
- `filename'        :: file path for file-backed buffers, else nil.
- `name'            :: `buffer-name' at save time.
- `narrowed-p'      :: t if the buffer was narrowed at save time.
- `indirect-p'      :: t if the buffer was an indirect buffer.
- `local-variables' :: reserved (always nil in v2); forward-compat hook.
- `etc'             :: alist; forward-compat slot."
  (bookmark nil)
  (filename nil)
  (name nil)
  (narrowed-p nil)
  (indirect-p nil)
  (local-variables nil)
  (etc nil))
#+end_src

** The decline condition: =workspace-restore-declined=

Reincarnating a =workspace-buffer= starts by jumping to its bookmark
record (layouts.org, "A decline is not a failure"), and that step has
three answers: the jump landed, the jump FAILED, or the handler
DECLINED.  A decline is a decision the user is meant to see — the
handler has refused to open its bookmark's location on the user's
behalf — and the restore must not second-guess it by opening the
leaf's stored filename or a live buffer of the same name.  A failure
says nothing about the buffer, and the chain falls through.

Telling the two apart needs a condition nobody signals by accident.
=user-error= is not one: stock handlers signal it for their own
reasons (=Info-find-file='s "Info file ... does not exist"), and those
leaves must keep falling through to the filename and buffer-name
fallbacks.  So core owns one condition, defined here beside the record
the reincarnation chain consumes, because this is the core module
every configuration that loads a consumer of the chain already has:

- *Who signals it:* a bookmark handler that refuses a location on the
  user's behalf while a layout leaf is being restored — the
  portable-bookmarks jump seam for its =(decline . MESSAGE)= plan, and
  any third-party handler that wants the same treatment.  The datum is
  =(MESSAGE)=, the reason the user reads.
- *Who catches it:* =workspace--bookmark-buffer= (layouts.org), whose
  decline arm catches this condition alone and answers
  =(declined . MESSAGE)= with the message taken from the datum.  Every
  other error, a plain =user-error= included, FAILS the step.

Its parent is =user-error=, so a declining jump that reaches an
interactive caller is still a =user-error= (and =bookmark-insert='s
abort on a declined record is unchanged).  Emacs prints a child of
=user-error= prefixed and with its datum quoted (=Bookmark handler
declined to restore: "..."=); only =user-error= itself echoes bare.  A
signaller that can be reached interactively therefore signals the
condition only during a leaf restore and a plain =user-error=
otherwise, and the catcher reads the message from the datum, never
from =error-message-string=.

#+begin_src emacs-lisp
(define-error 'workspace-restore-declined
  "Bookmark handler declined to restore"
  'user-error)
#+end_src

* Layout helpers

A layout is the leaf node: two window-state slots
(=:saved-state= for explicit saves, =:working-state= for autosaves),
a timestamp, and a forward-compat =:etc= alist slot.

The two-state shape (schema v2) makes the v1 MVP "tab-switch advice
clobbers explicit save" failure mode structurally impossible: every
autosave path writes =:working-state= only, leaving =:saved-state=
untouched.  Restore precedence — =workspace--layout-effective-state= —
prefers =:working-state= when non-nil, else =:saved-state= (design.md
§D3, §D4).

#+begin_src emacs-lisp
(defun workspace--layout-make (saved-state &optional timestamp)
  "Build a layout plist wrapping SAVED-STATE.
TIMESTAMP defaults to current time as an integer.  The freshly-built
layout has =:working-state= nil (no autosave drift yet) and =:etc= nil
(forward-compat alist)."
  (list :timestamp (or timestamp (time-convert nil 'integer))
        :saved-state saved-state
        :working-state nil
        :etc nil))

(defun workspace--layout-saved-state (layout)
  "Return the :saved-state window-state stored in LAYOUT.
This is the explicit-save slot; written only by =workspace-save= and
its variants.  Never written by autosave paths."
  (plist-get layout :saved-state))

(defun workspace--layout-working-state (layout)
  "Return the :working-state window-state stored in LAYOUT.
This is the autosave slot; may be nil.  Written by tab-switch advice,
the idle-save timer, and =workspace--kill-emacs-flush=.  Cleared to nil
by every explicit =workspace-save=."
  (plist-get layout :working-state))

(defun workspace--layout-effective-state (layout)
  "Return the window-state to apply on restore for LAYOUT.
Precedence: =:working-state= when non-nil, else =:saved-state=.
Returns nil when both slots are nil (no state ever captured).

This is the single dispatch point for the working-over-saved
precedence rule (register/invariant/restore-precedence-working-over-
saved); direct reads of either slot from the restore path are a
regression risk."
  (or (workspace--layout-working-state layout)
      (workspace--layout-saved-state layout)))

(defun workspace--layout-timestamp (layout)
  "Return the integer timestamp stored in LAYOUT."
  (plist-get layout :timestamp))
#+end_src

* Layout-group helpers

A layout-group is a named collection of layouts.  In MVP every group
holds exactly one layout (the current one); the schema is shaped as a
list so the deferred history feature can append timestamped revisions
without a migration (design.md §D5).

The name =home= is reserved (design.md §D6).  The reservation
predicate lives here so it is testable in isolation and so the
command layer cannot drift from the data layer on policy.

#+begin_src emacs-lisp
(defconst workspace--reserved-group-names '("home")
  "Layout-group names that cannot be deleted by user commands.")

(defun workspace--group-name-reserved-p (name)
  "Return non-nil if NAME is a reserved layout-group name."
  (and (stringp name)
       (member name workspace--reserved-group-names)
       t))

(defun workspace--group-make (name layout)
  "Build a layout-group plist named NAME containing LAYOUT as its sole entry."
  (list :name name
        :layouts (list layout)))

(defun workspace--group-name (group)
  "Return the name of GROUP."
  (plist-get group :name))

(defun workspace--group-layouts (group)
  "Return the list of layouts in GROUP."
  (plist-get group :layouts))

(defun workspace--group-recent-layout (group)
  "Return the most recent layout in GROUP.
MVP keeps a single layout per group; this returns the head of the
:layouts list, which is also the most recently saved one."
  (car (workspace--group-layouts group)))

(defun workspace--group-add-layout (group layout)
  "Return a new group like GROUP with LAYOUT prepended to its :layouts.
Non-destructive: GROUP is not modified.  In MVP this replaces rather
than appends; the deferred history feature can change this without
disturbing callers."
  (list :name (workspace--group-name group)
        :layouts (list layout)))
#+end_src

* Workspace helpers

A workspace is the user-facing entity that pairs 1:1 with a tab.

The =:home= slot is required (positional) and is the workspace's
filesystem anchor — every workspace points at exactly one directory.
=workspace--make= canonicalises HOME on entry to the form pinned by
=register/shape/workspace-plist-v3= so that every constructed workspace
carries an =:home= in the same shape regardless of how the caller
shaped the input:

- absolute path (=expand-file-name= applied — tilde and relative
  prefixes resolved against =default-directory=),
- trailing slash present (=file-name-as-directory= applied — so
  =equal= comparison across producers always agrees), and
- symlinks NOT resolved (we preserve the user's resolution choice).

Three known producers (cycle-3 =workspace--new-default-path=,
cycle-4 =workspace--new-anchor-existing=, cycle-3
=workspace-re-anchor= via =workspace--set-home=) all reach the
constructor via this entry point; canonicalising here means none of
them can drift out of the pinned shape (cycle-4 architect finding
=arch-cycle-20260526-191802-02=).

The persistence-loader path bypasses =workspace--make= deliberately:
=:home= is preserved verbatim on read so that a corrupted or
hand-edited file shows the offending path in =*Messages*= rather than
silently re-canonicalising it. The =:home=-shape validator on the
shape register pins the canonical form structurally so that any new
producer that tries to bypass the constructor surfaces the drift.

See register/invariant/home-required-no-floating-workspaces,
register/invariant/registry-name-equals-basename, and
register/shape/workspace-plist-v3.

#+begin_src emacs-lisp
(defun workspace--make (name home)
  "Build an empty workspace plist named NAME anchored at HOME.

NAME is the workspace name (and the registry key under which it is
stored).  HOME is the workspace's filesystem anchor — an absolute
path string.  By convention, =basename(HOME)= equals NAME; the data
layer does not enforce this here, but callers in the command layer
do (the canonical construction site derives NAME from HOME).

HOME is canonicalised on entry to the form pinned by
=register/shape/workspace-plist-v3=: absolute (=expand-file-name=
applied) and trailing-slash-present (=file-name-as-directory=
applied).  Symlinks are NOT resolved.  Callers that already pass a
canonical HOME observe a no-op; callers that pass the un-slashed or
tilde-prefixed form get normalised silently.  This makes the
constructor the single canonicalisation choke-point so that
downstream =equal= comparison on =:home= across all three producers
(=workspace--new-default-path=, =workspace--new-anchor-existing=,
=workspace-re-anchor=) agrees.

Both arguments are required: floating workspaces (without a home
directory) are structurally unrepresentable.  HOME is type-checked
so that a programmatic caller passing nil (the only way to land a
no-=:home= entry, since the deserialiser skips such entries) fails
loudly at the constructor rather than producing a workspace that
violates =register/invariant/home-required-no-floating-workspaces=."
  (cl-check-type home string)
  (list :name name
        :home (file-name-as-directory (expand-file-name home))
        :recent-layout-group nil
        :buffer-files nil
        :layout-groups nil))

(defun workspace--name (ws)
  "Return the name of workspace WS."
  (plist-get ws :name))

(defun workspace--home (ws)
  "Return the absolute home directory path of workspace WS.

Returns nil if WS has no =:home= slot (defensive: handles
hand-constructed or stale plists from a corrupted persistence file)."
  (plist-get ws :home))

(defun workspace--set-home (ws home)
  "Return a new workspace like WS with its =:home= slot set to HOME.
Non-destructive: WS is not modified.

HOME is canonicalised identically to =workspace--make=: absolute
(=expand-file-name= applied) and trailing-slash-present
(=file-name-as-directory= applied).  This keeps the invariant pinned
by =register/shape/workspace-plist-v3= holding across the post-
construction re-anchor path (=workspace-re-anchor= is the third known
producer of =:home= values, alongside =workspace--new-default-path=
and =workspace--new-anchor-existing= — see
=arch-cycle-20260526-191802-02=)."
  (let ((copy (copy-sequence ws)))
    (plist-put copy :home (file-name-as-directory (expand-file-name home)))))

(defun workspace--set-name (ws name)
  "Return a new workspace like WS with its =:name= slot set to NAME.
Non-destructive: WS is not modified.  Used by =workspace-re-anchor=
to keep =:name= in lockstep with =:home= when the new home's basename
differs from the workspace's current name (per
=register/invariant/registry-name-equals-basename=)."
  (let ((copy (copy-sequence ws)))
    (plist-put copy :name name)))

(defun workspace--layout-groups (ws)
  "Return the layout-groups of workspace WS."
  (plist-get ws :layout-groups))

(defun workspace--recent-group (ws)
  "Return the name of WS's most recently activated layout-group, or nil."
  (plist-get ws :recent-layout-group))

(defun workspace--set-recent-group (ws name)
  "Return a new workspace like WS with its recent-layout-group set to NAME.
Non-destructive: WS is not modified."
  (let ((copy (copy-sequence ws)))
    (plist-put copy :recent-layout-group name)))

(defun workspace--find-group (ws name)
  "Return the layout-group named NAME in WS, or nil if none."
  (seq-find (lambda (g) (equal (workspace--group-name g) name))
            (workspace--layout-groups ws)))

(defun workspace--upsert-group (ws name layout)
  "Return a new workspace like WS with a group named NAME holding LAYOUT.
If a group with NAME already exists, it is replaced; otherwise the new
group is appended.  Non-destructive."
  (let* ((existing (workspace--layout-groups ws))
         (filtered (seq-remove (lambda (g) (equal (workspace--group-name g) name))
                               existing))
         (replaced? (not (equal (length filtered) (length existing))))
         (new-group (workspace--group-make name layout))
         (next (if replaced?
                   ;; Preserve original position: walk existing, swap matching slot.
                   (mapcar (lambda (g)
                             (if (equal (workspace--group-name g) name)
                                 new-group
                               g))
                           existing)
                 (append existing (list new-group))))
         (copy (copy-sequence ws)))
    (plist-put copy :layout-groups next)))

(defun workspace--remove-group (ws name)
  "Return a new workspace like WS with the layout-group named NAME removed.
Non-destructive.  Reserved names are not specially handled here; callers
in the command layer must consult `workspace--group-name-reserved-p'
before invoking this on a user-supplied name."
  (let* ((next (seq-remove (lambda (g) (equal (workspace--group-name g) name))
                           (workspace--layout-groups ws)))
         (copy (copy-sequence ws)))
    (plist-put copy :layout-groups next)))

(defun workspace--buffer-files (ws)
  "Return the buffer-file membership list of WS."
  (plist-get ws :buffer-files))

(defun workspace--add-buffer-file (ws path)
  "Return a new workspace like WS with PATH added to its buffer-files.
Dedupes: adding the same PATH twice yields one entry.  Non-destructive."
  (let* ((files (workspace--buffer-files ws))
         (next (if (member path files) files (append files (list path))))
         (copy (copy-sequence ws)))
    (plist-put copy :buffer-files next)))

(defun workspace--remove-buffer-file (ws path)
  "Return a new workspace like WS with PATH removed from its buffer-files.
Non-destructive."
  (let* ((next (remove path (workspace--buffer-files ws)))
         (copy (copy-sequence ws)))
    (plist-put copy :buffer-files next)))
#+end_src

* Broken-state runtime tag

The =:broken= tag is a *runtime-only* flag set by the persistence
loader when a workspace's =:home= directory does not exist on disk at
load time (design.md §D5).  It is never serialized — on next save the
workspace is written out with its =:home= intact and the broken tag
implicitly dropped, since the missing-directory check is fresh on
every load.

Command-layer callers consult =workspace--broken-p= as an entry-point
guard.  Per
register/vocabulary/workspace-broken-disposition, =workspace-switch=
and =workspace-restore= refuse to operate on broken workspaces;
=workspace-re-anchor=, =workspace-purge=, and =workspace-delete=
permit it.  The runtime guards are inline at each command's entry
point (design.md §D6); this module owns only the predicate and the
mark/clear helpers.

#+begin_src emacs-lisp
(defun workspace--broken-p (ws)
  "Return non-nil if WS is in a broken state.

A workspace is broken when its =:home= directory was missing at
persistence-load time.  The flag is runtime-only (never serialized);
on next save it is implicitly dropped."
  (plist-get ws :broken))

(defun workspace--mark-broken (ws)
  "Return a new workspace like WS marked broken.
Non-destructive: WS is not modified.  Sets =:broken t= on the copy."
  (let ((copy (copy-sequence ws)))
    (plist-put copy :broken t)))

(defun workspace--clear-broken (ws)
  "Return a new workspace like WS with the broken tag cleared.
Non-destructive: WS is not modified.  Sets =:broken nil= on the copy."
  (let ((copy (copy-sequence ws)))
    (plist-put copy :broken nil)))
#+end_src

* Workspace health

The broken tag records what persistence saw at load; it cannot record a
home deleted since.  A surface that is about to operate on a
workspace's home — the menu's operational and Integrations groups (and
through them the directory-creating =jf/workspace--add-worktree=), the
portable-bookmarks add-worktree offer and off-workspace picker — needs
the live answer: not tagged broken, *and* its =:home= is an existing
local directory.  =workspace--unhealthy-reason= is that one health
notion; every such gate reads it, so the gates cannot disagree.

Remote homes are unsupported (they load broken).  =file-remote-p= is
asked before =file-directory-p= and without its CONNECTED argument, so
it answers from the name alone and a remote home is never stat'ed —
reading a remote workspace's health never opens a TRAMP connection.  A
local home costs one stat per call.

#+begin_src emacs-lisp
(defun workspace--unhealthy-reason (ws)
  "Return why workspace WS is not healthy, or nil when it is.

WS is healthy when it is not tagged broken (`workspace--broken-p') and
its `:home' is an existing local directory.  Otherwise the reason, a
symbol, the first that applies: `broken' (the tag persistence sets at
load when the home was missing or remote), `no-home' (no `:home' on the
plist, or WS is nil), `home-remote' (remote homes are unsupported),
`home-missing' (the home is not a directory on disk, however it went —
the broken tag is load-time only and cannot record a deletion since).
`file-remote-p' is asked before `file-directory-p', so a remote home is
never stat'ed and no connection is opened."
  (let ((home (workspace--home ws)))
    (cond
     ((workspace--broken-p ws) 'broken)
     ((not (stringp home)) 'no-home)
     ((file-remote-p home) 'home-remote)
     ((not (file-directory-p home)) 'home-missing))))

(defun workspace--healthy-p (ws)
  "Return non-nil when workspace WS is healthy.
That is, WS is non-nil and `workspace--unhealthy-reason' finds nothing
wrong with it: not tagged broken, and its `:home' an existing local
directory.  Never contacts a remote host."
  (and ws (not (workspace--unhealthy-reason ws))))
#+end_src

* File identity

Every "are these two paths the same file or directory?" question in
=config/workspaces/= — core and consumers alike — goes through ONE
predicate, =workspace--same-file-p=, and it compares FILE IDENTITY: the
device and inode numbers of the two paths' truenames.  Spelling does
not matter (trailing slash, =~=, symlinks, letter case on a
case-insensitive disk), and neither does anything that can change while
the file stays the same file.  Path strings are hash keys and
de-duplication pre-filters, never the verdict.

=file-equal-p= is REJECTED for identity.  In Emacs 30 it truenames and
stats each path and then compares the WHOLE attribute lists with
=equal=.  Those lists include the access, modification and status-change
times, so a directory that is modified, or merely read, between the two
stats compares unequal to itself.  On this machine's APFS volume the
first read of a directory after it changes also updates its access time,
so any concurrent reader (Spotlight, a sync client, git in another
process) is enough.  The portable-bookmarks review measured 4,817 wrong
answers in 20,000 ownership checks while a shell loop created and
removed one file in a workspace home.

Nil when either path is not a local string or does not exist.  Remote
(TRAMP) names are rejected before any filesystem call, so the predicate
never opens a connection.  It never signals.

This predicate and the containment predicate below are the only
functions in this file that read the filesystem.  They stat paths, never
read file contents, write nothing and hold no state, so the data layer
stays free of side effects.  They live here because =data-model.el= is
the first module the package loads, and every module that compares paths
(=tabs.el=, =git-worktrees.el=, =workspaces.el=,
=portable-bookmarks.el=) loads after it.

#+begin_src emacs-lisp
(defun workspace--same-file-p (a b)
  "Return non-nil when A and B name the same existing local file.

Compares the device and inode numbers of the two paths' truenames, so
spelling, symlinks and timestamps do not matter.  `file-equal-p' is
deliberately not used: it compares whole attribute lists, timestamps
included, and so reports a directory modified between its two stats as
unequal to itself.  Nil when either is not a string, is remote, or does
not exist.  Never signals."
  (and (stringp a) (stringp b)
       (not (file-remote-p a))
       (not (file-remote-p b))
       (condition-case nil
           (let ((attrs-a (file-attributes (file-truename (expand-file-name a))))
                 (attrs-b (file-attributes (file-truename (expand-file-name b)))))
             (and attrs-a attrs-b
                  (file-attribute-inode-number attrs-a)
                  (file-attribute-device-number attrs-a)
                  (equal (file-attribute-inode-number attrs-a)
                         (file-attribute-inode-number attrs-b))
                  (equal (file-attribute-device-number attrs-a)
                         (file-attribute-device-number attrs-b))))
         (error nil))))
#+end_src

** Containment

"Does this path lie inside that directory?" is the identity question
asked of each ancestor, so it has ONE predicate too,
=workspace--path-within-p=, built on =workspace--same-file-p=.  The
path is truenamed, then it and each of its parent directories in turn is
compared to the directory by file identity, up to the filesystem root.
Spelling does not matter (trailing slash, =~=, a symlinked prefix such
as macOS's =/var= → =/private/var=, letter case on a case-insensitive
disk), whole directories are compared (=/a/ws-old= is not inside
=/a/ws=), and the directory being written to during the walk does not
change the answer.  A path is within itself.

=file-in-directory-p= is REJECTED for containment.  It truenames both
paths, compares their components with a case-sensitive =string-equal=,
and ends with =file-equal-p=, so it carries both defects: a
differently-cased spelling of a directory on this machine's disk is not
inside it, and a directory written to between two reads is not inside
itself.

Both paths must be local and exist, and the directory must be a
directory: a path that does not exist cannot be proven inside anything,
so it is not.  Remote (TRAMP) names are rejected before any filesystem
call.  It never signals.

The equality test in the loop compares two spellings of the SAME walk to
detect the root (the parent of the root is the root); it is a
termination guard, never the verdict.

#+begin_src emacs-lisp
(defun workspace--path-within-p (path dir)
  "Return non-nil when PATH is DIR or lies inside it.

Both must be local and exist (a missing PATH is inside nothing); DIR
must be a directory.  Containment is by file identity: PATH is
truenamed, then it and each of its ancestors is compared to DIR with
`workspace--same-file-p', so differences of spelling (trailing slash,
`~', symlinked prefixes, letter case on a case-insensitive filesystem)
do not matter, and neither do DIR's timestamps changing during the
walk.  `file-in-directory-p' is deliberately not used: it compares
spellings case-sensitively and ends in `file-equal-p'.  Never signals."
  (and (stringp path) (stringp dir)
       (not (file-remote-p path))
       (not (file-remote-p dir))
       (condition-case nil
           (let ((current (directory-file-name
                           (file-truename (expand-file-name path))))
                 (previous nil)
                 (found nil))
             (when (and (file-exists-p (expand-file-name path))
                        (file-directory-p (expand-file-name dir)))
               (while (and (not found) (not (equal current previous)))
                 (if (workspace--same-file-p current dir)
                     (setq found t)
                   (setq previous current
                         current (directory-file-name
                                  (file-name-directory current))))))
             found)
         (error nil))))
#+end_src

* Recipe shape

A layout's =:saved-state= holds either a window-state captured from
real windows or a declarative *recipe*: a tree of file panes that is
turned into windows only when the layout is applied (layouts.org,
"Recipe expansion").  The form is

#+begin_example
(:recipe :split columns            ; or rows
         :panes ((:file "/abs/ask.org")
                 (:split rows      ; a pane may itself be a split
                  :panes ((:file "/abs/scaffold.org" :line 157)
                          (:file "/abs/design.md")))))
#+end_example

- =:split= is =columns= (panes side by side) or =rows= (panes stacked).
- =:panes= is a non-empty list.  Each pane is exactly =(:file PATH)=,
  =(:file PATH :line N)= or a nested =(:split DIR :panes PANES)=, to any
  depth.  The panes of one split share its space evenly.
- PATH is an absolute file name string.  A name starting with =~= is
  rejected even though =file-name-absolute-p= accepts it: what it names
  depends on =$HOME= (and, for =~user=, on the password database) when
  it is read, not when it was stored.  The builder that turns tool
  arguments into a recipe expands every path, so it never produces one.
- N is a positive integer, the line point lands on when the layout is
  applied.

=workspace--recipe-p= is the one predicate that tells a recipe from a
captured window-state; a captured state's car is a cons (its size
header), never =:recipe=.  It is pure shape: it never touches the
filesystem (whether a pane's file exists is decided when the layout is
applied) and it is total, answering nil rather than signalling for any
malformed tree, dotted pair or improper list.  The keys are matched in
the order shown and no others are accepted, so a form that is almost a
recipe is not one.

#+begin_src emacs-lisp
(defun workspace--recipe-split-p (dir)
  "Return non-nil if DIR is a recipe split direction, `columns' or `rows'."
  (memq dir '(columns rows)))

(defun workspace--recipe-path-p (path)
  "Return non-nil if PATH is an absolute file name a recipe pane may name.
Pure string test: a name starting with `~' is refused because its
meaning depends on the environment when it is read."
  (and (stringp path)
       (file-name-absolute-p path)
       (not (string-prefix-p "~" path))))

(defun workspace--recipe-pane-p (pane)
  "Return non-nil if PANE is a well-formed recipe pane.
A pane is `(:file PATH)', `(:file PATH :line N)' with N a positive
integer, or a nested `(:split DIR :panes PANES)'."
  (pcase pane
    (`(:file ,path) (workspace--recipe-path-p path))
    (`(:file ,path :line ,line)
     (and (workspace--recipe-path-p path)
          (natnump line)
          (> line 0)))
    (`(:split ,dir :panes ,panes)
     (and (workspace--recipe-split-p dir)
          (workspace--recipe-panes-p panes)))))

(defun workspace--recipe-panes-p (panes)
  "Return non-nil if PANES is a non-empty proper list of recipe panes."
  (and (consp panes)
       (proper-list-p panes)
       (cl-every #'workspace--recipe-pane-p panes)))

(defun workspace--recipe-p (state)
  "Return non-nil if STATE is a layout recipe, not a captured window-state.
A recipe is `(:recipe :split DIR :panes PANES)': DIR is `columns' or
`rows'; PANES is a non-empty list of `(:file PATH)', `(:file PATH
:line N)' or nested `(:split DIR :panes PANES)' panes, PATH an
absolute file name and N a positive integer.  Total over any input
and touches no file."
  (pcase state
    (`(:recipe :split ,dir :panes ,panes)
     (and (workspace--recipe-split-p dir)
          (workspace--recipe-panes-p panes)
          t))))
#+end_src
